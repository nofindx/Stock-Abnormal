# 2.0.5 候选记录

版本 `2.0.5` · 发布标识 `20261125.1` · 计算 `v76`。用户确认2.0.4未提审，本版包含其全部修正，统一交付用户真机验证。最近核验云端为2.0.4、微信公众版为2.0.3；本地候选不能等同线上已发布。

## 本轮改动

- 单股、预测context可选 `include_s1=1`，同一响应返回已授权S1；前端先显示S1再请求S2，正常首开/手动从3次串行请求减到2次。旧服务缺少S1时兼容授权GET，旧包继续使用原接口。
- 保持CODE-007：每次手动操作使用新entry取得最新名单、公告及计算基线；同entry重试固定原S1，旧token不扩池；S1失败不发旧S2，S2失败保留最新S1，模拟输入按基线是否改变决定保留或重置。
- 监控每次查MySQL活动指针，复用同发布ID的不可变快照解析结果；单股先按证券裁剪再复制，调用方修改不影响缓存。缓存不跨指针复用，不改变公告质量。
- entry锁从所有用户共用改为按entry哈希隔离；Tushare慢网络读取不占缓存元数据锁，相同key合并，其他key和缓存命中独立。
- 后端固定阶段汇总和客户端最多30条内存路径模板计时，无证券、token、输入、响应或持久化。用于实际部署/真机后定位剩余等待。
- 前后端三份版本文件和文档统一2.0.5；默认广告版本白名单包含2.0.5，广告继续关闭。计算阈值、IPO、公告解析版本、v76、Redis的3秒报价和60秒配对不变，无数据库迁移。

2.0.4处理范围及证据见[前版记录](../2.0.4/README.md)。原性能检查见[性能基线](../2.0.4/verification/performance-20261125.json)，其开发者工具样本不代表用户2.0.3真机耗时。
