# vNext 专项门禁验收方式

> **20261109 归档说明**：用户已要求移除暂缓及不必要的专项工作。本文仅保留历史验收设计，以下“待验”“暂缓”及执行顺序均不再作为当前待办或本次发布门禁。当前范围以[正式上线清单](正式上线清单.md)为准；未执行专项不记作通过，也不自动恢复执行。

> 版本：`GATE-PLAN-20261109.2`
> 状态：本文件只定义怎样验，不代表门禁已通过，也不授权对生产环境做故障注入、压力测试或回滚。20261109用户最新决定停止T2，状态为暂缓、未验证，不继续回档或创建资源；证据见[T2执行单](T2数据库恢复执行单_20261109.md)。其余暂缓项目不变。

## 1. 执行原则

- 先在本地或隔离环境执行自动化/集成测试；涉及云服务的项目用独立测试服务、独立 MySQL schema 和测试 Redis，不写生产数据、不压测公开行情源。
- 每次结果记录：用例 ID、提交 SHA、规则/配置/数据集版本、环境、执行时间、测试输入 manifest 哈希、结果、日志/报告路径和缺陷号。
- 通过只表示表中明确的范围通过。样本缺失、环境不可用、只看了代码或只跑了单测，都记为“未验”，不得记通过。
- 已由用户确认完成的 T3/T8 可复用原验收回执，不重复做破坏性验证；复用时补齐证据索引即可。

## 4. 建议评审与执行顺序

1. 先评审本方案的环境边界和既有阈值；用户确认后，先完成本地可重复的 T1 夹具审阅（是否执行仍遵循用户对 T1 的暂缓决定）。
2. 若未来同意恢复真实演练，先准备隔离资源，顺序执行 T2、T4、T6；通过后再验 T5、T7。T3/T8 复用已确认记录，只有证据缺失才补档。
3. 任一失败先登记缺陷、修复并重跑受影响用例；不能以其他门禁通过抵消，也不能用文档评审代替运行证据。

本方案不改变 `1.0.18` 审核状态，不要求现在部署、上传、清库、重建或启动真实演练。详细规则仍以 [vNext 测试用例与门禁](next-major/testing/测试用例与门禁-vNext.md) 为权威，本文件把 T1–T8 转成可执行步骤和证据标准。
