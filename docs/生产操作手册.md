# 生产操作手册

> 当前运维基线：代码已接入Redis、v2 S1/S2和共享publication，20261108线上运行/落盘预测v73核验通过。详见[发布验收](发布验收_20261108.md)；完整实例列表及新华传媒行情完整性仍待核查。日常验收以[正式上线清单](正式上线清单.md)为入口；本手册不授权清库、删表或删除Redis。

适用服务：微信云托管 `flask-9a5y`。生产发布只使用微信云托管控制台；本手册不使用 CloudBase CLI。

## 1. 盘中链路与发布验收

1. 盘中行情和预测刷新结果不写入正式数据集；实时协调使用 Redis 共享报价缓存、短期视图和刷新租约，MySQL 仍是公告事实、重置、正式计算结果和已发布数据集的结构化真相源。
2. Redis 是当前生产链路的一部分：不得移除环境变量、解绑私有网络或删除实例。发布前检查 `/health` 的 `realtimeCoordination.redisEnabled=true`、`redisPing=true` 和来源策略门禁为 `pass`。
3. 保存并重新发布服务。发布后执行：

   ```bash
   curl -fsS https://flask-9a5y-319926-10-1496305218.sh.run.tcloudbase.com/health
   curl -fsS https://flask-9a5y-319926-10-1496305218.sh.run.tcloudbase.com/health/ui >/tmp/stock-abnormal-health.html
   python3 server/tools/api_contract_check.py \
     --base-url https://flask-9a5y-319926-10-1496305218.sh.run.tcloudbase.com \
     --require-data
   ```

   `/health` 应返回实时源来源级聚合统计、股票基础资料覆盖、预测数据集状态和任务错误；不再检查 `intradayState`。浏览器打开 `/health/ui` 查看人类可读摘要。
4. 盘中刷新接口返回 `dataStage=realtime` 和完整 `items`；随后 GET 仍返回稳定数据集；`POST /api/quotes/realtime` 返回 `persisted=false`。Redis 故障时不得回退到各实例直连上游或进程本地行情副本，应返回 queued/unavailable 并保留原有稳定画面。

## 2. 基础数据与数据库变更

当前生产股票基础资料由服务启动同步，并在 `/health.data.marketCalc.stockBasicCoverage` 报告完整性。人工 SQL 回填、改 schema 或重抓历史行情不属于日常发布步骤；只有发现明确数据缺口并完成备份、影响评估和单独批准后，才按专项修复方案处理。

生产 MySQL 当前同时承载行情计算基础、公告事实、发布记录和预测数据集。不要按旧流程重建或清空数据库，不要手工删 `prediction_cache` 或其他表，不要在生产执行本文历史迁移脚本。检查具体迁移状态时，以当前 `server/migrations`、`schema_migration` 和健康接口为准；迁移/恢复演练必须使用隔离目标并保留对账证据。

## 3. 预测重建与数据修复

规则版本变更后，服务根据已保存的基础行情和公告事实重算派生指标、today/next_day 数据集。本流程不要求默认重抓全市场基础行情，不清库，也不需要手工修改 `FORCE_MARKET_HISTORY_REBUILD` 或 `PREDICTION_CACHE_COMPAT_READ`。

发现线上数据错误时，先核对 `/health` 的运行规则版本、数据集版本/日期/质量和 job 状态。仅在根因确认需要时，使用已实现并授权的重建入口；不能把盘后 `POST /api/predictions/refresh` 当作重建命令，它只读取已发布结果。重建后同时验收 today、next_day 目标日、数据源阶段、规则版本、任务错误和重点回归个股。不要通过环境变量反复重启以触发全市场任务。

任何清库、删表、替换历史数据、修改生产基础表或改变 Redis/VPC 连接，都必须形成单独执行方案、备份与恢复路径，并取得用户明确批准；常规版本发布授权不包含上述操作。
