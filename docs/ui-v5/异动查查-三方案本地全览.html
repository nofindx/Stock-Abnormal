异动查查 · 三方案本地全览

三套方案共享同一套页面结构、数据契约、T+N 表格框架（时间为行、指标为列，默认 2 日 / 可选 5 日 / 10 日）与异常状态规则，差异只在列表容器。方案 A 清单流＝白底 + 1px 分割线单列行；方案 B 卡片流＝浅灰底 + 白卡单列；方案 C 双列网格＝浅灰底 + 白卡双列、卡内字段纵向。股票卡片一律只有四要素：名称+代码 / 类型 / 当日或次日 / 关键数值，列宽固定、上下严格对齐。

方案 A · 清单流（评审 4.59 · 推荐采用）

白底 + 1px 分割线，行高 88rpx。五列固定列宽 72 / 60 / 86 / 40 / 64 px，数值右对齐。

方案 B · 卡片流（评审 4.53 · 压线达标 · 备选）

浅灰底 #F2F3F5 + 白卡单列，卡高 96rpx、卡间距 12rpx、页面左右留白 10px。列宽与 A 一致，对齐红利全保留；误触率三套最低，代价是一屏少 2–3 条。

方案 C · 双列网格（评审 3.89 · 不达标 · 已否决）

浅灰底 + 白卡双列（174×78px），卡内字段纵向排布，数值放大到 32rpx、整卡触控 78px。否决原因：左列与右列存在两条垂直轴，跨列字段无法上下对齐，违反硬性要求 2。

评分来自三位独立 UI 设计师评审（交互可用性 / 视觉与设计系统 / 小程序工程化），非设计者自评：
方案 A 4.59 ✅ 达标（推荐） · 方案 B 4.53 ✅ 压线达标（备选） · 方案 C 3.89 ❌ 不达标（否决）。 详见 docs/异动查查-三方案评审结论.md。本页所有尺寸单位为 px，实际开发按 1px = 2rpx 换算。
