## 1. 盘中链路与发布验收

1. 盘中行情和预测刷新结果不写入正式数据集；Redis 提供共享报价缓存和取价租约；MySQL 保存 S1/S2 短期授权视图、共享任务、公告事实、重置、计算基线及已发布数据集。默认 TTL 和任务归属见架构设计 §3.14、§6.1。
2. Redis 是当前生产链路的一部分：不得移除环境变量、解绑私有网络或删除实例。发布前检查 `/health` 的 `realtimeCoordination.redisEnabled=true`、`redisPing=true` 和来源策略门禁为 `pass`。
3. 保存并重新发布服务。发布后执行：

   ```bash
   curl -fsS https://flask-9a5y-319926-10-1496305218.sh.run.tcloudbase.com/health
   curl -fsS https://flask-9a5y-319926-10-1496305218.sh.run.tcloudbase.com/health/ui >/tmp/stock-abnormal-health.html
   python3 server/tools/api_contract_check.py \
     --base-url https://flask-9a5y-319926-10-1496305218.sh.run.tcloudbase.com \
     --require-data
   ```

   `/health` 应返回实时源来源级聚合统计、股票基础资料覆盖、预测数据集状态和任务错误；不再检查 `intradayState`。浏览器打开 `/health/ui` 查看人类可读摘要。
4. 首开先读S1再执行一次S2；用户手动刷新先重取最新S1再执行S2，所有时段可获取来源最新可用报价；核对 `refreshStatus`、`refresh_state`、`result_state`、`dataQuality.quoteAvailable` 和真实 `quoteUpdatedAt`，不能单凭`dataStage`判断价格是否更新。盘中沿用上一日next候选池时可保留`formal`阶段，次日角色只更新显示价格、不重算未来条件；随后无实时视图token的GET仍返回稳定数据集。`POST /api/quotes/realtime`不落盘正式行情。Redis故障时不得回退到各实例直连上游或进程本地行情副本，应明确失败/排队并保留原有稳定画面。

### 1.1 本地联调与来源配置

本地启动示例见根 README；实际配置以 `server/.env.example` 为字段清单。单纯启动 HTTP 服务不代表 S1/S2 已就绪：需可用的 MySQL、已有共享发布表与基础数据、至少 32 字节的 `VNEXT_CONTEXT_SECRET`，S2 另需可用 Redis 和哈希一致的 `SOURCE_POLICY_JSON/HASH`；PDF 跨实例阅读使用 `MONITOR_PDF_TOKEN_SECRET`。密钥仅由环境注入，不能把生产凭据放进示例、日志或小程序。

2.0.4 保持现有来源 JSON 和哈希兼容，历史时间键已退休，不用手动改为 60 再重算生产哈希。运行时唯一时间差为 60 秒，`/health.data.realtimeCoordination.sourcePolicyGate.quotePairing` 可查实际口径；报价本身的自然年龄不设 5 秒失效线。来源身份/版本/哈希门禁仍执行，字段说明见架构设计 §6.1。

## 2. 基础数据与数据库变更

当前生产股票基础资料由服务启动同步，并在 `/health.data.marketCalc.stockBasicCoverage` 报告完整性。人工 SQL 回填、改 schema 或重抓历史行情不属于日常发布步骤；只有发现明确数据缺口并完成备份、影响评估和单独批准后，才按专项修复方案处理。

生产 MySQL 当前同时承载行情计算基础、公告事实、发布记录和预测数据集。不要按旧流程重建或清空数据库，不要手工删 `prediction_cache` 或其他表，不要因本文整理而重新执行迁移或改表。检查具体迁移状态时，以当前 `server/migrations`、`schema_migration` 和健康接口为准；迁移/恢复演练必须使用隔离目标并保留对账证据。

## 3. 预测重建与数据修复

规则版本变更后，服务根据已保存的基础行情和公告事实重算 today/next_day 派生数据集；事实发布路径按现有逻辑更新受影响的派生指标。本流程不要求默认重抓全市场基础行情，不清库，也不需要手工修改 `FORCE_MARKET_HISTORY_REBUILD` 或 `PREDICTION_CACHE_COMPAT_READ`。

发现线上数据错误时，先核对 `/health` 的运行规则版本、数据集版本/日期/质量和 job 状态。仅在根因确认需要时，使用已实现并授权的重建入口；不能把 `POST /api/predictions/refresh` 当作全市场重建命令：它在所有时段刷新固定已发布名单的报价，次日角色不改未来触发条件，也不重建正式候选集。重建后同时验收 today、next_day 目标日、数据源阶段、规则版本、任务错误和重点回归个股。不要通过环境变量反复重启以触发全市场任务。

任何清库、删表、替换历史数据、修改生产基础表或改变 Redis/VPC 连接，都必须形成单独执行方案、备份与恢复路径，并取得用户明确批准；常规版本发布授权不包含上述操作。

### 5.1 2.0.4 手动刷新与公告原因复验

- 服务启动后的既有调度识别 `20261124-product-policy-v35`，重采当前公告窗口以补齐认定依据；不要为此清事实表。来源失败时保留已有确认事实，旧缺依据记录先用中性文案。验证同向公告未被写成“价格偏离达到100%”，生效日、监控期限和正式计次未因文案丢失。
- 单股和预测的手动下拉均检查最新context/S1→POST S2顺序，原token未过期也要读最新S1。2.0.5新后台可合并context与S1，旧后台兼容GET S1。新S1后报价失败保留新事实和名单；初次打开只一轮S1→S2，切标签/返回不再自动取价。
- 同日公告重置发布后，手动刷新应更新计算基线和模拟默认态；新基线标识不变时则保留用户输入。重点监控继续读最新列表。以上需部署/真机复验，本地用例通过不代表生产已经完成。


### 5.2 2.0.5 性能核验

先发布兼容旧包的2.0.5后端，再使用2.0.5体验包。核对三份版本文件为 `2.0.5 / 20261125.1`，计算保持v76，广告关闭。确认单股/预测context带 `include_s1=1` 返回同一token的S1；无该参数的2.0.3/2.0.4调用保留旧响应。若仍连2.0.4，兼容回退将保留三次请求，不能据此判定两次请求优化已生效。

读取 `/health.data.readPerformance` 查看固定阶段耗时；开发者工具/真机调试可查 `getApp().globalData.requestPerformance` 最近30条记录，不复制含token的原始网络请求。用新entry核对后台新事实和新名单可见、旧token仍固定旧集；S1失败与S2失败分别验证。完整功能与真机2秒/3秒核验见测试规范 §17。性能未通过时先按context/S1、S2和渲染分段定位，不能直接用扩容或延长缓存隐藏原因。

## 6. 保存图片的隐私配置与提审

在微信公众平台进入 **设置 → 服务内容声明 → 用户隐私保护指引**，按平台当前选项声明 `wx.saveImageToPhotosAlbum` 对应的相册写入用途。联系信息填写真实资料并留在管理后台。声明生效后，用新体验包验证授权、拒绝和实际相册落图。声明缺失、`errno=112` 或接口封禁时核对 AppID、后台用途及生效状态。用户拒绝时由用户自行管理微信授权。

### 6.1 相册用途

#### 相册用途文案

> 仅当用户主动点击“保存图片”时，将页面当前显示的股票状态、四项预警及模拟计算图片（包含当前2/10日和已填写输入）保存至用户设备相册。不读取用户相册中的照片或视频，不上传相册内容。拒绝授权不影响查询、计算及好友分享。

#### 相册用途短版

> 用于用户主动保存结果图片至设备相册，仅写入，不读取或上传相册内容。

#### 权限说明

> 查询、计算及好友分享不申请相册权限。仅在用户主动保存图片时申请必要的相册写入授权；不读取相册，拒绝不影响其他功能。

保存接口使用微信原生授权。平台隐私声明与运行时相册写入授权各自生效。

### 6.2 版本更新说明与审核备注

#### 版本更新说明

> 优化单股结果分享，支持通过微信发送给朋友或群，并在用户主动授权后将结果图片保存至相册。保存仅写入本机生成的图片，不读取或上传用户相册；同步更新隐私说明。

#### 审核备注

> 本小程序基于公开行情、公告及交易监管规则提供股票异动查询和计算，包含单股计算、异动预测、重点监控与公告阅读，不提供交易下单、代客理财、荐股或收益承诺。无需登录。进入单股计算页并选择股票后，页面底部“分享一下”提供“发给朋友”和“保存图片”。前者为微信原生小程序卡片，接收者打开后为该股默认计算态；后者在用户主动操作并授权后，将当前完整页面（状态卡、四项预警、当前2/10日模拟和已填输入）生成图片保存至相册，不读取或上传用户相册。拒绝保存授权不影响其他功能。当前广告关闭，10 日模拟和次日预测可直接使用。

实际启用广告时按 §7 更新审核备注。名称、简称、简介、类目及资质按实际业务和微信后台要求填写。

#### 审核操作路径

> 单股计算 → 搜索并选择股票 → 下滑至“分享一下” → “发给朋友”或“保存图片”。无需账号或测试密码。模拟计算好友接收者为默认2日空白；保存图片保留发送者点击时当前的2/10日输入和结果。保存按钮仅当次显式操作才触发授权，不需要提供相册中已有图片。

## 7. 广告启停

目前线上广告关闭，两项功能免费。取得流量主资格后，从微信后台开通官方广告单元及适用场景。UV 去重、违规历史和申请条件以流量主后台判定为准，使用本小程序自己的真实单元。

1. 在微信后台分别创建四个展示位与两个激励视频单元。位置、场景及完整配置见 [PRD](01-产品需求PRD.md#34-官方广告)和[接口设计](02-架构与开发设计.md#315-广告配置与次日就绪)。
2. 在云托管配置 `CLIENT_ADS_CONFIG_JSON`，将 `allowedVersions` 指向拟开放版本。先验证展示位，再按需为对应视频启用 `rewarded`。暂未开放的视频场景保留 `free`。
3. 核验线上 `GET /api/client-config` 的配置版本、对应版本白名单和开关，真机验证真实广告及两个门槛。按实际开启场景更新隐私披露、审核备注和提审材料。
4. 暂停投放时关闭微信广告单元，并将云端配置的 `ads.enabled` 设为 false、两个 `featureGates.*.mode` 设为 `free` 后发布。客户端在下一次按需取配置时生效，现有成功配置缓存最多 600 秒。
