# 异动查查 · 方案 B「卡片流」

**与方案 A 的关系：** 完全一致的信息架构、页面结构、数据契约与交互流程；差异**只在视觉容器**——由「白底 + 1px 分割线」改为「浅灰底 + 白色卡片」。
共享内容（页面结构 / 交互流程 / 数据字段 / 实现说明 / 异常状态）以**方案 A 文档为准**，本文只写差异。

---

## 1. 设计主张

> 用**明确的边界**换取**更低的误触与更强的分块感**。

方案 A 靠 1px 分割线切分列表，行与行之间只靠一条细线区分；方案 B 给每一行一个白色卡片容器，页面底色退成浅灰，让「一条记录 = 一个块」这件事变成物理可见的。

### 与 A 的差异对照

| 维度 | 方案 A 清单流 | 方案 B 卡片流 |
| --- | --- | --- |
| 页面底 | `#FFFFFF`（与卡片同色） | `#F2F3F5`（灰底，卡片浮起） |
| 容器 | 无边框，仅 1px 分割线 | 白卡 + 1px `#E8ECF2` 边 + 8rpx 圆角 |
| 行高 | 88rpx（44px） | 96rpx（48px） |
| 行间距 | 0（线分割） | 12rpx（6px） |
| 横向内边距 | 14px（贴边） | 10px（卡片左右留白） |
| 分组标题 | 3px 色条 + 文字，贴边 | 同上，但整体随卡片内缩 |
| 卡片四要素 | 名称 / 代码 / 类型 / 当日次日 / 数值 | **完全相同，列宽完全相同** |
| 对齐规则 | CSS Grid 固定列宽 | **完全相同** |

---

## 2. 为什么这样改

| 收益 | 说明 |
| --- | --- |
| 误触更少 | 卡片之间有 6px 空隙，手指点击的边界明确，不会点串行 |
| 分块更清晰 | 灰底衬白卡，一屏 12 条时眼睛更容易锁定单条 |
| 状态区更自然 | 「已出监管」用灰卡 `#FAFBFC` + 灰边，与白卡的「当前监控」形成材质级差异，不只是颜色差异 |
| 后续可扩展 | 若将来要给某条加「展开详情」，卡片容器天然承载折叠动画 |

| 代价 | 说明 |
| --- | --- |
| 一屏少约 2 条 | 行高 +8rpx、间距 +12rpx，812pt 屏从约 14 条降到约 12 条 |
| 视觉重量增加 | 灰底 + 边框比纯白底"重"一丝，极简纯度略降 |
| 多 1 个样式层 | 需维护卡片边框与圆角，WXML 多一层 `view`（对小程序渲染压力可忽略） |

## 3. 卡片规范

### 3.1 四要素（与 A 完全一致）

名称 + 代码 / 异动或预测类型 / 当日或次日 / 关键数值。去除交易所、板块、监控期、剩余交易日、风险原因、进度条、触发价、起止日期、卡片级时间。

### 3.2 列宽（与 A 完全一致，rpx）

```css
/* components/stock-card/stock-card.wxss */
.card{
  background:#FFFFFF;
  border:1rpx solid #E8ECF2;
  border-radius:8rpx;
  height:96rpx;
  margin:0 20rpx 12rpx;      /* 左右留白 + 卡间距 */
  padding:0 24rpx;
}
.stk{
  display:grid;
  grid-template-columns:144rpx 120rpx 172rpx 80rpx 128rpx; /* 72/60/86/40/64 px */
  column-gap:12rpx;
  align-items:center;
  height:100%;
}
.stk > view{ min-width:0; overflow:hidden; white-space:nowrap; text-overflow:ellipsis; }
.stk .val{ text-align:right; font-variant-numeric:tabular-nums; }
```

| 列 | px | rpx |
| --- | --- | --- |
| 名称 | 72 | 144 |
| 代码 | 60 | 120 |
| 类型 | 86 | 172 |
| 当日/次日 | 40 | 80 |
| 关键数值 | 64 | 128（右对齐） |

> 注意：卡片左右各 24rpx padding 后，内容宽 = 375 − 2×20 − 2×24 = 287px，而五列合计 = 72+60+86+40+64 + 4×6 = 346px。**超出**。
> 处理：卡片左右 padding 降为 12rpx（12px），内容宽 = 375 − 20 − 12 = 343px ≈ 346px，取 `column-gap:8rpx` 后合计 338px，可容纳。最终参数见下。

**修正后的确定值：**

| 项 | 值 |
| --- | --- |
| 卡片外边距 | `0 20rpx 12rpx` |
| 卡片内边距 | `0 12rpx` |
| 卡片高度 | `96rpx` |
| 列间隙 | `8rpx` |
| 列宽 | `144 / 120 / 172 / 80 / 128` rpx |
| 内容宽校验 | 144+120+172+80+128 + 4×8 = 676rpx = 338px ≤ 343px ✅ |

### 3.3 监控池两类区分（在 A 的基础上再强化一层）

| 维度 | 当前监控 | 已出监管 |
| --- | --- | --- |
| 卡片底 / 边 | `#FFFFFF` / `#E8ECF2` | `#FAFBFC` / `#EBEDF0` |
| 名称 / 代码 | `#1A1A1A` / `#6B7280` | `#6B7280` / `#9CA3AF` |
| 类型列 | 彩色 | 灰字「已出监管」 |
| 数值列 | 当前偏离值 | 结束日期 |
| 分组标题 | 「当前监控 12」红条 | 「已出监管 25」灰条 |

## 4. 页面清单

与方案 A 完全相同（6 屏 + 规则页）：

```
Tab1 单股：index（搜索+状态+四项预警）· forecast（T+N 2/5/10）· rule（规则与诊断）
Tab2 监控池：index（当前监控 / 已出监管 两组）
Tab3 预测：index（当日预测 / 次日预测两组；当日含已触发和可达未触发候选）
```

T+N 沿用方案 A 表格框架：时间为行、指标为列，`交易日 | 股票% | 指数% | 3日 | 10日 | 30日 | 安全上涨空间`，默认 2 日、可选 5 日 / 10 日，一次取 10 日前端截取。

## 7. 关键实现说明（差异部分）

```xml
<!-- components/stock-card/stock-card.wxml -->
<view class="card {{pool==='exited' ? 'card--muted' : ''}}" bindtap="onTap">
  <view class="stk">
    <view class="name">{{name}}</view>
    <view class="code">{{code}}</view>
    <view class="type {{typeClass}}">{{typeLabel}}</view>
    <view class="day">{{dayLabel}}</view>
    <view class="val {{valClass}}">{{valueText}}</view>
  </view>
</view>
```

- 用 `margin` 而非 `padding` 做卡间距，避免小程序 iOS 上 `padding` 折叠异常。
- 卡片 `box-sizing:border-box`，高度写死 `96rpx`，保证列对齐不受内容影响。
- 边框用 `1rpx`，在 2x/3x 屏上自动变细，不会出现 2px 粗线。
- 不使用阴影（小程序低端机阴影掉帧），靠边框 + 底色差建立层级。

---

## 8. 适用建议

**优先选 B 的场景：** 列表较长（监控池 37 条、历史 25 条）、用户以单条点击为主、希望在低端机上降低误触。
**优先选 A 的场景：** 追求极限密度与极限极简、列表较短、用户以扫读而非点击为主。
