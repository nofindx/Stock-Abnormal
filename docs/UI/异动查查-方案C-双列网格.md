# 异动查查 · 方案 C「双列网格」

**与方案 A 的关系：** 信息架构、页面结构、数据契约、T+N 框架、异常状态规则**完全一致**；差异**只在列表布局**——由「单列一行一条」改为「双列卡片网格，一条一张卡」。
共享内容以**方案 A 文档为准**，本文只写差异。

---

## 1. 设计主张

> 把「一行」升级成「一块」：更大的点击区、更大的数字，靠**双列网格**把密度损失补回来。

方案 A/B 都是「横向一行塞五个字段」，字段只能做小；方案 C 把每条记录变成一张独立卡片，字段改为**纵向三行**，数值字号可以从 26rpx 提到 32rpx，触控区从 44px 高变成 78px 高的整卡。为了不让一屏条数变少，用双列网格铺开。

### 与 A / B 的差异对照

| 维度 | A 清单流 | B 卡片流 | **C 双列网格** |
| --- | --- | --- | --- |
| 页面底 | 白 | 浅灰 `#F2F3F5` | 浅灰 `#F2F3F5` |
| 容器 | 无边框 + 分割线 | 白卡单列 | **白卡双列** |
| 每条高度 | 88rpx（44px） | 96rpx（48px） | **156rpx（78px）** |
| 每行条数 | 1 | 1 | **2** |
| 一屏条数（812pt） | ≈14 | ≈12 | **≈16** |
| 字段排布 | 横向 5 列 | 横向 5 列 | **纵向 3 行** |
| 名称字号 | 28rpx | 28rpx | **30rpx** |
| 数值字号 | 26rpx | 26rpx | **32rpx** |
| 触控区 | 44px 高整行 | 48px 高整卡 | **78px 高整卡** |
| 列对齐 | 全列表统一列位 | 全列表统一列位 | **列内统一（见 §3.2 取舍）** |

## 2. 卡片结构

```
┌──────────────────────┐
│ 比亚迪        当日   │   行1：名称 30rpx 粗 + 日次 20rpx 灰（右）
│ 002594               │   行2：代码 22rpx 灰
│ 30日严重异常         │   行3：类型 20rpx 档位色
│            +203.11   │   行4：数值 32rpx 粗（右对齐）
└──────────────────────┘
```

- 卡片尺寸：**174 × 78px**（348 × 156rpx）
- 布局：`grid-template-columns: repeat(2, 1fr)`，列间隙 12rpx，行间隙 12rpx，页面左右留白 20rpx
- 卡内边距：`16rpx 20rpx`
- 卡内纵向 4 行，`justify-content: space-between`，数值行右对齐

### 尺寸校验

```
卡宽 = (375 − 2×10 − 6) / 2 = 174.5px  ✅
一屏 = floor((812 − 88状态栏 − 88导航 − 84TabBar − 40分组标题) / (78 + 6)) × 2
     ≈ 8 行 × 2 = 16 张
```

## 3. 取舍（这一版最需要评审判断的地方）

### 3.1 收益

| 收益 | 说明 |
| --- | --- |
| 数值最醒目 | 32rpx 粗体、右对齐、独占一行，"关键数值一眼可见"这条硬要求达成度最高 |
| 触控最舒适 | 整卡 174×78px，远大于 44px 底线，误触率最低 |
| 单卡可独立阅读 | 四要素自成一块，不需要跨列比对 |
| 条数不减反增 | 16 条 > A 的 14 条 |

### 3.2 代价（已知问题，请评审重点判断）

| 代价 | 说明 | 严重度 |
| --- | --- | --- |
| **跨列不对齐** | 左列名称起点 x=30，右列 x=210。"名称对齐名称"只在**同一列内**成立，跨列不成立 | **高** |
| **名称易截断** | 卡内可用宽 ≈134px，30rpx 字号下约 4.5 字；5 字以上名称（如"中际旭创"4字尚可，"长城汽车"4字尚可，但"中国石油"4字、"科创50ETF"之类会截断） | **中** |
| 字号被迫加大 | 30rpx 名称比 A 的 28rpx 更占空间，是截断风险的根源 | 中 |
| 竖向滚动变长 | 单条 78px，同样 37 条需要滚 ≈2.3 屏（A 约 1.3 屏） | 中 |
| 分组标题占比上升 | 每组标题占 40px，双列下显得更"空" | 低 |

> **关于对齐的说明：** 方案 C 中所有卡片使用**完全相同的内部网格模板**，`padding` / `gap` / 字号逐项一致，因此**列内严格对齐、两列视觉节奏完全一致**。它牺牲的是"跨列同一行两张卡的名称起点相同"——这在网格布局中不可避免。若评审认为这违反"上下对齐"硬要求，方案 C 应判为不达标。

## 4. 监控池两类区分

在双列网格下，两类差异必须更强才能"一眼分辨"：

| 维度 | 当前监控 | 已出监管 |
| --- | --- | --- |
| 卡底 / 边 | `#FFFFFF` / `#E8ECF2` | `#F2F3F5` / `#E1E7EE`（与页面底接近，呈"沉下去"效果） |
| 名称 | `#1A1A1A` 30rpx | `#9CA3AF` 30rpx |
| 类型 | 档位色 | 灰「已出监管」 |
| 数值 | 当前偏离值（红/绿，32rpx） | 结束日期（灰，28rpx） |
| 分组标题 | 「当前监控 12」红条 | 「已出监管 25」灰条 |

额外强化：已出监管的卡片**去掉日次角标**（该列不适用），并在卡片右上角以 20rpx 灰字直接写「已出」，避免只靠颜色判断。

## 5. 页面清单与 T+N

与方案 A 完全一致：

```
Tab1 单股：index · forecast（T+N 2/5/10）· rule
Tab2 监控池：index（双列网格，当前监控 / 已出监管 两组）
Tab3 预测：index（双列网格，当日预测 / 次日预测两组；当日含已触发和可达未触发候选）
```

T+N 沿用方案 A 表格框架（时间为行、指标为列，`交易日|股票%|指数%|3日|10日|30日|安全空间`，默认 2 日 / 可选 5 日 / 10 日）。**双列网格只作用于监控池与预测的列表，不作用于 T+N 表格**（表格必须横向对齐，不能拆成两列）。

## 6. 异常状态标识（与 A 一致）

离线「离线 · 缓存 14:50」/ 刷新失败「刷新失败 重试」/ 无数据「无标的」/ 数据不足「不可判定 + —」/ 部分失败「· 失败 12」/ 新增命中「+3」。
在双列网格下，空态「无标的」改为整行跨两列居中显示。

## 8. 关键实现说明（差异部分）

```css
/* 双列网格 */
.grid{
  display:grid;
  grid-template-columns:repeat(2,1fr);
  gap:12rpx;
  padding:0 20rpx;
}
.cell{
  background:#FFFFFF;
  border:1rpx solid #E8ECF2;
  border-radius:12rpx;
  height:156rpx;
  padding:16rpx 20rpx;
  display:flex;
  flex-direction:column;
  justify-content:space-between;
}
.cell--muted{ background:#F2F3F5; border-color:#E1E7EE; }
.cell .r1{ display:flex; justify-content:space-between; align-items:center; }
.cell .nm{ font-size:30rpx; font-weight:600; overflow:hidden; white-space:nowrap; text-overflow:ellipsis; }
.cell .day{ font-size:20rpx; color:#9CA3AF; flex:none; }
.cell .cd{ font-size:22rpx; color:#6B7280; }
.cell .tp{ font-size:20rpx; }
.cell .vl{ font-size:32rpx; font-weight:700; text-align:right; font-variant-numeric:tabular-nums; }
```

- 名称 `flex:1` + `overflow:hidden` + `text-overflow:ellipsis`，保证日次角标永不被挤掉。
- 卡片高度写死 `156rpx`，避免内容多少导致行高参差（网格布局下尤其明显）。
- 不用 `wx:for` 嵌套渲染两列（会产生 DOM 翻倍）；用**单层 `wx:for` + CSS Grid 自动换行**，小程序渲染性能最好。
- 空态用 `grid-column: 1 / -1` 跨列居中。

---

## 9. 适用建议

**优先选 C 的场景：** 用户以"看数值、点进去"为主，列表条数中等（≤40），机型触摸屏较大，且能接受名称 4 字截断。
**不建议选 C 的场景：** 名称普遍偏长、要求跨行严格对齐、列表很长（>60 条，竖向滚动会明显变长）。
