## 1. 数据源分工

### 主数据源：Tushare

Tushare 作为生产计算链路的唯一主数据源，优先使用以下接口：

| Tushare 接口 | 用途 |
| --- | --- |
| `stock_basic` | 股票代码、名称、上市市场、上市状态 |
| `trade_cal` | 交易日历和最近交易日判断 |
| `daily` | 只用于生成最近 30 个交易日收盘收益率向量和每日新增价格；不保存原始日线 |
| `index_daily` | 五个板块对应指数的最近 30 个交易日收盘收益率向量 |

生产环境必须把 Tushare Token 放在后端环境变量中，不能放进微信小程序包。

### 辅助数据源

| 数据源 | 作用 | 使用限制 |
| --- | --- | --- |
| 东方财富证券 18.cn | 监管池全部类型的主源，抓取正文和链接并做语义分类 | 仅监管池使用；只保存来源链接和元数据，不保存正文/PDF |
| 巨潮资讯 | 监管池备源，主源成功时仅辅助佐证，主源失败时接替 | 只保存来源链接和分类结果；不与主源重复展示 |
| 上海证券交易所、深圳证券交易所、北京证券交易所官网 | 规则原文核对 | 不接入监管池公告接口 |
| AKShare | 免费历史行情、指数和交易日历交叉校验 | 非官方聚合接口，网络源变化或限流时不能替代 Tushare |
| BaoStock | 免费历史日线和复权数据回补 | 适合历史回补和离线核对，不作为实时数据源 |
| 东方财富公开行情接口 | 临时盘中价格和数据缺口的应急校验 | 非正式开放 API，限流、字段和服务条款存在变化，不进入核心计算链路 |

建议的数据优先级：单股计算使用 MySQL 当前计算数据 + 腾讯/新浪/东方财富盘中报价；监管池使用 18.cn 主源 -> 巨潮备源；规则文案再以交易所原文核对。
当辅助数据和 Tushare 不一致时，保留差异记录并以 Tushare 结果为准，不静默覆盖。

## 2. 计算口径

### 2.0 官方规则版本与来源

本项目按当前有效的交易所规则配置，规则版本和原文链接必须随服务配置记录：

| 交易所 | 官方规则 | 关键条款 | 生效/发布日期 |
| --- | --- | --- | --- |
| 上海证券交易所 | [《上海证券交易所交易规则（2026年修订）》](https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20260424_10816492.shtml) | 第5.4.2、5.4.3；科创板第6.10至6.12 | 2026-07-06生效，2026-04-24发布 |
| 深圳证券交易所 | [《深圳证券交易所交易规则（2026年修订）》](https://www.szse.cn/lawrules/rule/trade/current/t20260424_620190.html)；[规则正文PDF](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf) | 第5.4.3至5.4.5 | 2026-07-06生效，2026-04-24发布 |
| 北京证券交易所 | [《北京证券交易所交易规则》公告（北证公告〔2026〕17号）](https://www.bse.cn/jygl_list/200028217.html) | 第5.4.2至5.4.5 | 2026-07-06生效，2026-04-24发布 |

沪深交易所规则明确：严重异常的方向阈值为上涨 `+100%/+200%`、下跌 `-50%/-70%`。北交所独立使用上涨 `+150%/+300%`、下跌 `-60%/-75%`。三所均规定无价格涨跌幅限制股票不纳入指标计算；交易所公布异常或股票复牌后从次一交易日起重新计算。交易所后续修订时，先更新规则版本配置和测试，再更新页面文案。

### 2.1 区间偏离值

N 个交易日区间使用 N+1 条有效收盘价：

```text
股票区间涨跌幅 = (区间末收盘价 / 区间首收盘价 - 1) × 100
指数区间涨跌幅 = (区间末指数收盘价 / 区间首指数收盘价 - 1) × 100
累计偏离值 = 股票区间涨跌幅 - 指数区间涨跌幅
```

停牌日、无效价格、缺失指数数据不能直接填 0；必须先按交易日历对齐并标记数据质量问题。

### 2.2 普通异动

普通异动窗口为连续 3 个交易日，满足任一条件即触发：

| 板块 | 连续 3 日累计收盘价偏离阈值 |
| --- | --- |
| 主板 | ±20% |
| 创业板 | ±30% |
| 科创板 | ±30% |
| 北交所 | ±40% |

交易所规则文本还包含部分换手率条件；本产品 V1 不采集、不存储换手率，也不将其用于单股四项指标、10 日同向计数或监管池。监管池只按 18.cn/巨潮正文分类和 10 日、30 日严重异动口径。

ST、*ST、退市整理、上市首日等特殊状态不能直接套用普通股票阈值，生产配置应单独维护。

### 2.3 严重异常波动

“连续 10/30 个交易日内”是回看上限，不是必须恰好取固定长度。对齐股票与所属指数的有效共同交易日后，在 3..10 或 3..30 个连续区间中取当前正向偏离最大的区间；因此预测卡片可能显示实际的 9 日、28 日等区间，规则文案仍明确写 10 日或 30 日阈值。缺失交易日、停牌和指数缺口不填 0。

核心模块检查三类条件，任意一类满足即标记为严重异常：

1. 最近 10 个交易日累计偏离达到上涨 `+100%` 或下跌 `-50%`。
2. 最近 30 个交易日回看窗口累计偏离达到上涨 `+200%` 或下跌 `-70%`；该 30 日是认定窗口，不代表触发后的监管期长度。
3. 最近 10 个交易日内出现多次同向普通异动：主板 4 次，创业板和科创板 3 次。上交所科创板为 3 次；普通换手率条件不计入此次数。

北交所使用独立口径：3 个交易日累计偏离 `±40%` 为异常波动；10 个交易日内 3 次同向异常波动，或累计偏离达到上涨 `+150%` / 下跌 `-60%`，以及 30 个交易日累计偏离达到上涨 `+300%` / 下跌 `-75%`，属于严重异常波动。偏离值对应北证 50 成份指数。

严重异常是三类条件的并集，不是把上涨和下跌绝对值对称处理。页面应同时显示方向和实际阈值，例如"10日严重异常：上涨+100% / 下跌-50%"。

实现上的窗口边界：交易所的 10/30 日是回看上限，不允许把任意更短的 3 日窗口冒充严重异常的 10/30 日条件。对齐股票与所属指数后，只在 N-2、N-1、N 三个有效长度中选择当前正向偏离最大的连续区间：10 日规则对应 8/9/10 日，30 日规则对应 28/29/30 日。少于 N-2 个有效共同交易日时不判定该条件；卡片展示实际有效长度，规则文案仍显示交易所的 10 日/30 日窗口。

上涨异动和下跌异动分开计数，不能相互抵消。命中的 3 日滚动窗口消费该 3 日区间，下一次从未消费的交易日开始扫描；10 日窗口滚动后，移出窗口的区间自然重置。这样可避免连续涨停被重叠窗口错误放大为 6 次、7 次。

### 2.4 触发价格

```text
目标股票涨跌幅 = 同期指数涨跌幅 + 目标偏离值
理论触发价格 = 区间起点价格 × (1 + 目标股票涨跌幅 / 100)
```

该价格是规则计算的理论线，不是买卖建议，也没有替代交易所最终认定。

### 2.5 T+1 至 T+10 预测

预测模块不自行假设"明天一定涨跌"，而是接受指数日涨跌幅假设作为输入，逐日复合后计算理论触发价。
页面必须展示"规则辅助预测"和数据更新时间；非交易日不得生成 T+N。

## 3. 项目结构

```text
server/
├── core/                         # 纯规则计算，不访问网络
│   ├── abnormal_rules.py         # 异动、严重异常、触发价格和预测函数
│   ├── models.py                 # 股票、行情、监控池、预测和数据质量结构
│   ├── __init__.py               # 统一导出核心数据结构和函数
│   └── test_abnormal_rules.py    # 规则回归测试
├── data_sources/                 # Tushare、官方公告、免费辅助源适配器
├── services/                     # 股票详情、监控池、预警预测业务编排
└── api/                          # 提供给微信小程序的 HTTP 接口

miniprogram/
├── pages/                        # 首页、已异动、预警、个股详情等页面
├── components/                   # 股票卡片、偏离卡片、预测卡片、底部导航
└── utils/                        # 请求封装、格式化和本地缓存
```

## 4. 上线前必须复核

- 交易所规则更新，特别是北交所、ST、退市整理和上市首日。
- Tushare 账户对 `daily`、`index_daily`、`stock_st` 等接口的权限与频率。
- 复权口径。监管异动展示通常应基于交易所实际收盘价，不能未经确认直接使用前复权价。
- 官方公告与 Tushare 行情日期是否一致。
- 所有页面增加"仅供参考，不构成投资建议"的风险提示。

## 5. 单股最小数据更新方案

- CloudBase MySQL 只保存 `stock_basic`、`stock_calc_base`、`index_calc_base`、`market_calc_job`；不建立原始日线表，不保存成交量、成交额、换手率、历史行情或历史计算快照。
- 上海时间每日 00:00 后后台更新。空库初始化最近 30 个交易日收益率；非空库只拉新增交易日价格并截断向量到 30 个元素；每日强制更新 `stock_basic` 以识别新上市股票。
- 更新失败后，次日 01:00-09:00 每小时重试；成功后当天不重复更新。前端请求不会触发后台任务。
- 选股后读取数据库向量，并行获取股票和所属指数实时行情；两者均成功才修正偏离值，失败则返回最近交易日结果并标记降级。T+N 默认 2 日、可选 10 日，完全在前端本地计算。
