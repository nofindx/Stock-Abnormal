# 异动查查：设计与工程说明

> 版本：V2.0（2026-10-10）
> 定位：当前实现、联调和部署的技术基线。产品范围和验收以《异动查查小程序 PRD》为准。

## 1. 系统边界

```text
微信小程序 -> Python HTTP 服务 -> MySQL / Tushare / 盘中行情 / 公告源
```

前端不调用 Tushare、不保存 Token、不执行全市场循环计算，也不根据展示字符串推断规则。后端负责数据源、规则、数据集和状态。

## 2. 数据源适配

| 接口/来源 | 必要参数 | 用途 | 口径 |
| --- | --- | --- | --- |
| `stock_basic` | `list_status=L` | 全市场股票池 | 交易日后台更新 |
| `trade_cal` | `exchange,start_date,end_date` | 交易日和阶段 | 日期 `YYYYMMDD` |
| `daily` | `trade_date` 或日期范围 | 股票正式收盘 | 不混入盘中数据 |
| `index_daily` | `index_code,start_date,end_date` | 指数正式收盘 | 与股票按交易日对齐 |
| 腾讯/新浪/东方财富 | 股票或指数代码 | 盘中临时行情 | 仅主动刷新 |
| 18.cn/巨潮 | 公告列表和详情 | 重点监控 | 主源/备源四态决策 |

请求前检查 Token、权限、日期范围和交易日。空结果要区分非交易日、无数据、未上市、参数错误、权限不足和网络失败。辅助源只交叉核验，不静默覆盖 Tushare 正式结果。

盘中实时行情请求必须在同一刷新任务中同时取得股票和所属指数，收到两边响应后再计算；缺一边或时间不可解析时沿用稳定数据，不混合不同请求批次。

## 3. 阶段状态机

阶段函数输入当前上海时间、交易日历、基础数据日期和数据集状态，输出：

```json
{
  "phase": "pre_open|dataset_open_pending|intraday|post_close_pending|post_close_confirmed|rest_day",
  "targetTradeDate": "20261012",
  "todaySourceScope": "today|next_day",
  "realtimeRefreshAllowed": false
}
```

固定边界：

```text
09:00:00  next_day 成为 today
09:15:00  允许用户主动实时刷新
15:00:00  进入盘后任务阶段
```

预测接口在下一交易日 `09:00:00` 前返回上一交易日的 today 数据，并允许读取已生成且目标日期匹配的 next_day 数据。到 `09:00:00`，该 next_day 数据集成为 today；`09:00:00` 至盘后新数据集落盘期间，次日接口返回不可用状态，不返回错误日期的数据。盘后初态/正式数据集以 `nextTradeDate` 作为次日目标日。

阶段判断不得使用跨越边界的固定缓存。每次请求必须根据当前上海时间和最近边界重新判定。休息日和下一交易日 09:00 前保留上一交易日 today；收盘已触发卡片不得提前清除。

## 4. 数据库设计

### 4.1 基础计算表

```sql
stock_calc_base(
  ts_code PRIMARY KEY, as_of_trade_date, latest_close,
  stock_return_vector JSON, data_stage, quote_updated_at, updated_at
)

index_calc_base(
  index_code PRIMARY KEY, as_of_trade_date, latest_close,
  index_return_vector JSON, data_stage, quote_updated_at, updated_at
)
```

只保存最近 30 个有效共同交易日所需向量，不保存原始日线、盘中报价或用户输入。

### 4.2 `prediction_dataset`

```sql
prediction_dataset(
  dataset_role, target_trade_date, base_trade_date,
  data_stage, data_quality, rule_version,
  dataset_quote_updated_at, dataset_quote_as_of,
  dataset_quote_source, dataset_quote_complete,
  item_count, exclusion_stats JSON,
  status, items JSON, updated_at, last_error,
  PRIMARY KEY(dataset_role, target_trade_date)
)
```

卡片字段至少为：

```json
{
  "predictionKey": "600825.SH-severe_10d-20261012",
  "ts_code": "600825.SH",
  "ruleKey": "severe_10d",
  "predictionWindow": 10,
  "actualWindow": 9,
  "deviationLabel": "9日 +77.75%",
  "deviationPercent": 77.75,
  "triggerCondition": "10日偏离达到 +100.00%",
  "triggerValue": "+100.00%",
  "triggered": false,
  "cardTone": "",
  "change": "+2.35%",
  "quoteUpdatedAt": "2026-10-12 10:15:00"
}
```

预测数据集不包含 `same_direction_10d`。同向次数只由单股计算接口返回。

### 4.3 任务表

任务锁、失败状态和重试状态使用以下任务表：

```sql
prediction_job(
  job_name PRIMARY KEY, target_trade_date, data_stage,
  status, lease_until, started_at, finished_at,
  attempt, input_watermark, output_dataset_key, last_error
)
```

`prediction_dataset` 只保存业务结果；任务锁、失败和重试只使用 `prediction_job`。现有 `prediction_cache` 只读兼容，迁移完成后停止使用。

## 5. 后台任务流程

### 5.1 15:00 初态

交易日 15:00 后读取全市场股票池、股票行情和所属指数，写入基础向量并标记 `initial/provisional`，随后生成 `today` 和 `next_day`。股票和指数不完整时不得发布 `status=ready` 空数据集。

### 5.2 正式收盘

正式 Tushare 数据成功后覆盖基础向量，重算两个数据集并标记 `formal/confirmed`。失败时保留上一份可用数据集，不发布空成功结果。

### 5.3 次日计算

次日必须遍历完整 `stock_basic(list_status=L)`，不是复制当日候选。按 `ts_code + ruleKey` 排除当日同规则已触发、重点监控同规则、数据不足、停牌尾部和不可达候选。`exclusion_stats` 记录排除原因。

## 6. API 设计

### 6.1 统一响应

```json
{"code":0,"data":{},"message":"ok"}
```

错误响应使用固定 HTTP 状态和 `code/data/message` 外壳：

| 业务码 | HTTP | 含义 |
| ---: | ---: | --- |
| 40001 | 400 | 参数错误 |
| 40401 | 404 | 资源不存在 |
| 40901 | 409 | 当前阶段不允许刷新 |
| 50301 | 503 | 数据源不可用 |
| 50302 | 503 | 数据集未准备 |
| 50001 | 500 | 内部错误 |

预测数据不可用时，读取接口仍返回 HTTP 200 和 `code=0`，`dataUnavailable=true`、`datasetStatus=failed|missing` 和 `error` 供前端在更新时间位置显示“当日数据不可用”。任务失败但上一份数据集存在时，接口保留上一份 `items`，同时将 `datasetStatus` 置为 `failed`，不伪造空成功结果。

### 6.2 搜索和单股

`GET /api/stocks/search?q=`：`q` 至少一个字符，最多返回 5 条 `ts_code/symbol/name/market/board/isSt`。
`GET /api/stocks/detail?ts_code=`：返回状态、四项预警、交易日历、计算输入和 `dataQuality`；股票和指数实时行情必须同时成功才修正详情。

### 6.3 重点监控

`GET /api/monitor?status=current&type=all|risk|severe`，默认 `status=current,type=all`。GET 只读当前快照，不启动采集或行情请求。返回 `items/updatedAt/dataQuality/stale`。严重异动 PDF 在监控期内由短路径代理，结束后 404。

### 6.4 预测读取

`GET /api/predictions?scope=today|next_day`，默认 `today`。返回：

```json
{
  "scope":"today",
  "targetTradeDate":"20261012",
  "baseTradeDate":"20261009",
  "phase":"intraday",
  "todaySourceScope":"next_day",
  "realtimeRefreshAllowed":true,
  "datasetQuoteUpdatedAt":"2026-10-12 10:15:00",
  "quoteUpdatedAt":"2026-10-12 10:15:00",
  "dataStage":"formal",
  "dataQuality":{"quality":"confirmed","complete":true},
  "dataUnavailable":false,
  "nextDayAvailable":true,
  "items":[]
}
```

前端使用 `quoteUpdatedAt`，其值来自数据集行情水位；不能使用前端请求时间或技术字段 `updatedAt`。响应同时返回 `datasetQuoteUpdatedAt`、`datasetQuoteComplete` 和 `exclusionStats`。

### 6.5 预测刷新

`POST /api/predictions/refresh`，请求体 `{"scope":"today"}`。只有 `scope=today` 且阶段为 `intraday` 时获取实时行情；其他时段只读数据集。只处理已有 `predictionKey`，返回完整列表并保持顺序。返回 `refreshStatus=applied|not_allowed|fallback`。

### 6.6 健康检查

`GET /health` 必须报告数据源统计、基础数据日期、当前阶段、两个数据集的目标日期、数据阶段、行情水位、完整性、卡片数量、排除数量、规则版本、最近成功/失败和错误信息；同时报告 `intradayState.backend/shared/ttlSeconds/maxPayloadBytes`、`marketCalc.stockBasicCoverage` 和 `marketCalc.predictionMigration`。`updatedAt` 仅兼容。

## 7. 前端适配

`miniprogram/utils/api.js` 只负责路径、参数和响应解包。预测页面直接使用：

```text
predictionKey, ts_code, name, symbol, change,
deviationLabel, triggerCondition, triggerValue,
triggered, cardTone, quoteUpdatedAt
```

前端禁止自行解析规则、替换业务时间、在 Tab 切换时刷新、按触发状态删除卡片、显示实时延迟提示或股票价格。

### 7.1 页面展示契约

- 重点监控与异动预测共用页面顶部内边距 `24rpx`。
- 筛选行/切换栏高度 `80rpx`、顶部间距 `12rpx`；内部按钮高 `60rpx` 并垂直居中。
- 快照信息行高 `48rpx`、顶部间距 `12rpx`；卡片列表顶部间距 `24rpx`。
- 两类股票卡片共用外尺寸：内边距 `18rpx`、边框 `1rpx`、圆角 `14rpx`。股票名称/代码字号 `30/20rpx`，间距 `12rpx`。
- 卡片分割线 `1rpx`，线上留白和线后内边距均 `12rpx`。
- 预测卡第一行显示名称、代码、当前涨幅和数值；第二行左侧显示偏离胶囊，触发时显示“已触发”胶囊，右侧显示固定触发条件和值。不显示股票价格。
- 当前涨幅和触发值字号 `24rpx`，右对齐并上下对齐；标签字号 `20rpx`。
- 预测偏离和已触发胶囊字号 `20rpx`、行高 `30rpx`、上下内边距 `2rpx`、左右内边距 `10rpx`、边框 `2rpx`、圆角 `8rpx`。
- 行情颜色遵循涨红跌绿；触发卡使用浅红背景，不覆盖涨跌颜色。
- 重点监控类型标签字号 `20rpx`、行高/最小高 `30rpx`、水平内边距 `10rpx`、圆角 `8rpx`；公告文字/图标字号 `20rpx`，图文间距 `4rpx`，与类型标签间距 `16rpx`。
- 重点监控剩余天数区宽 `184rpx`；数字列宽 `48rpx`，数字字号/行高 `34rpx`。

### 7.2 云托管发布配置

GitHub 仓库为 `nofindx/Stock-Abnormal`，发布分支为 `Stock-Abnormal`。微信云托管控制台使用仓库根目录作为构建目录：目标目录留空，Dockerfile 选择“有”，Dockerfile 名称填写 `Dockerfile`，容器端口填写 `80`。根目录 Dockerfile 安装 `server/requirements.txt`，复制 `server/` 并启动 `python -m server.app`。生产发布只使用微信云托管控制台，不使用 CloudBase CLI。

生产环境变量必须配置 `REDIS_URL`。服务重启后 `/health` 的 `intradayState.backend` 必须为 `redis`、`shared=true`、`ttlSeconds=120`、`maxPayloadBytes=2097152`；未配置 Redis 时只能用于本地测试，不能作为生产完成状态。

`PREDICTION_CACHE_COMPAT_READ` 默认为 `1`，迁移窗口内允许在新表无记录时回退读取旧表。迁移核验使用：

```bash
python3 server/tools/prediction_migration_check.py
python3 server/tools/prediction_migration_check.py --require-zero-legacy-reads --require-complete-stock-basic
```

核验脚本只读数据库。连续 7 个交易日 `legacyReadFree=true` 且旧表完成备份后，才允许关闭兼容读取并删除旧表。

## 8. 稳定性和性能

- 全市场计算只在后台任务执行。
- 盘中按股票和指数去重批量请求，同一刷新请求合并。
- 正式数据失败保留旧数据集；真实无候选和计算失败必须区分。
- 不允许静默截断 `items`；如需分页必须新增明确契约。
- 盘中临时状态使用 Redis，键按 `scope + targetTradeDate` 隔离，TTL 为 120 秒，单键上限 2MB；超限记录错误并返回上一次稳定数据。
- Redis 由实例共享，实例重启不影响正式数据集；Redis 不可用时只允许本地开发回退，不作为生产运行模式。生产实例容量至少 256MB，使用 `allkeys-lru`，内存使用率达到 70%/85%/90% 分别触发提醒/告警/紧急告警，命中率低于 95% 触发告警。
- 当前接口返回完整 `items` 列表，不做静默截断；未来分页必须新增 `page/pageSize/hasMore` 契约并同步前端。
