## 1. 本版要解决的问题

方案 A 功能覆盖完整、效率高，但**页面与信息都偏多**：12 屏、每屏 4～6 个信息块、四项预警各占一张卡、监控池两套筛选与两套排序。对一个由个人开发者维护、只有三类动作（选股 / 看结果 / 刷新）的工具来说，这个复杂度不划算。

方案 D 因此**只做减法**，不引入新功能、不换视觉语言：

| 原则 | 做法 |
| --- | --- |
| 一屏只承担一个任务 | 合并同类屏、删掉可推断的信息，任何「顺便展示」的内容一律砍掉 |
| 默认给最常用的那一档 | T+N 默认 5 行、监控池不预加载历史、规则页公式折叠 |
| 缺的信息点一下就有 | 触发价、公式出处、诊断信息全部改为按需展开，不常驻 |

## 2. 减法清单（方案 A → 方案 D）

| 维度 | 方案 A | 方案 D | 减掉的成本 |
| --- | --- | --- | --- |
| **页面数量** | 12 屏 | **8 屏** | 状态页 4 屏 → 2 屏；预测当日/次日 2 屏 → 1 屏；T+N 提升为独立页 |
| **监控池筛选** | 当前/历史 分段器 + 两套排序 + 5 个 chips | **单一列表**（历史灰显 + 「已结束」标签）+ 4 个 chips | 删掉 1 个分段器、1 套排序、1 个 chip |
| **四项预警** | 4 张独立卡（各含进度条 + 触发价 + 起止日） | **1 张 4 行紧凑表**（指标 / 当前 / 阈值 / 状态） | 高度从 ~300px 降到 ~140px；触发价与起止日改为点行展开 |
| **T+N 表** | 10 行全展开、7 列 | **默认 T+1~T+5**、5 列，可展开全部 10 日 | 首屏输入框 20 个 → 10 个；无需横向滚动 |
| **搜索下拉** | 名称+代码+交易所+板块+ST 五段 | **名称+代码+板块**，ST 并入板块文案 | 每行少 2 个字段 |
| **状态档位** | 6 档（含独立「同向严重异常」） | **5 档**，同向条件并入 10 日严重异常 | 见 §4.1 |
| **单股状态原因** | 独立浅底区块 + 规则版本行 | 压在状态条内一行 + 规则版本移到规则页 | 少一个信息块 |
| **规则说明** | 4 段长文 | **阈值表 + 折叠诊断**；换手率与公式收进折叠区 | 首屏从 4 段降到 2 段 |
| **免责声明** | 每屏底部两行 | 同上，但**追加隐私政策 / 用户协议 / 数据源说明三入口** | 补齐 P0（§4.3） |
| **未选股引导** | 居中提示卡 | 两行灰字 | 去掉一张卡 |

> 结论：页面数 −33%，单屏信息块 −30%～40%，T+N 与四项预警的首屏高度约减半。**功能覆盖没有减少**，只是把「常驻展示」改成了「按需展开」。

## 4. 对评审结论的落地

### 4.1 PRD 澄清一：同向严重异常并入 10 日严重异常
- **状态档位由 6 档改为 5 档**：`30日严重异常 > 10日严重异常 > 普通风险提示 > 安全 > 数据不可判定`。
- 同向次数条件触发时，**状态仍显示「10日严重异常」**，原因行补一句「同期同向普通异动 3 次（创业板要求 3 次）」。
- **监控池筛选不再单列「同向严重异常」**，chips 保持 4 个；`monitor_type` 维持 `ordinary / severe_10d / severe_30d` 三类不变。
- 收益：前端少一个状态分支、少一个筛选选项、少一套徽章配色。

### 4.2 PRD 澄清二：特殊股票计入候选数
- 预测扫描信息行显示的总数**包含**停牌 / 退市整理 / 上市首日 / 无涨跌幅限制股票。
- 这些股票在候选列表中状态固定为「暂无法判定」并灰显，**不参与「已触发 / 临界」排序**。
- 按反馈「不重要」，不做额外 UI 区分，仅保留灰显与缺失项说明。

### 4.3 PRD 澄清三：目录扩展
```text
miniprogram/
├── pages/
│   ├── stock/          # index（搜索+状态）· forecast（T+N）· rule（规则与诊断）
│   ├── monitor/        # index（当前+历史合并列表）
│   └── prediction/     # index（当日/次日）
├── components/
│   ├── stock-search/   # 搜索下拉（5 条上限）
│   ├── status-card/    # 状态条（色条 + 文字双通道）
│   ├── alert-table/    # 四项预警紧凑表（本版新增）
│   ├── monitor-item/   # 监控池列表项（含「已结束」态）
│   ├── prediction-item/# 预测列表项
│   ├── diag-panel/     # 诊断折叠区（本版新增，P0-2）
│   └── empty-state/    # 骨架 / 空态 / 失败 三态复用（本版新增）
└── utils/ request.js · cache.js · format.js
```

### 4.4 三个 P0 缺口的落点

| 缺口 | 落点 | 表现 |
| --- | --- | --- |
| **P0-1 部分失败可见性** | D5 扫描信息第二行 | `扫描完成 14:50:12 · 失败 12 只（限流）`，琥珀色；诊断区 `data_quality = partial` |
| **P0-2 request_id 无处可见** | D6「本次请求诊断」折叠区 | `request_id / updated_at / data_quality / rule_version` + 「复制诊断信息」 |

## 5. 股票信息列对齐规范

**问题：** 用 `flex + gap` 排列时，名称字数不同（比亚迪 3 字 / 宁德时代 4 字）会把后面的代码、板块、状态依次推走，各行字段起点不一致。

**规则：** 所有股票信息行改用**固定列宽网格**，字段起点由列宽决定，与内容长度无关。

| 列 | 宽度 | 对齐 | 内容 |
| --- | --- | --- | --- |
| 1 · 名称 | 72px | 左对齐，超出省略号 | 比亚迪 |
| 2 · 代码 | 60px | 左对齐，等宽数字 | 002594 |
| 3 · 类型/状态 | 86px | 左对齐 | 30日严重异常 |
| 4 · 弹性列 | 1fr | — | 「已结束」等补充标签 |
| 5 · 涨跌幅 | **64px** | **右对齐**，`tabular-nums` | +9.98% |

```css
.stk{display:grid;grid-template-columns:72px 60px 86px 1fr;column-gap:6px;align-items:center}
.stk>span{min-width:0;white-space:nowrap;overflow:hidden;text-overflow:ellipsis}
.chg{display:inline-block;width:64px;text-align:right;font-variant-numeric:tabular-nums}
.sstk{display:grid;grid-template-columns:72px 60px 1fr;column-gap:6px}  /* 搜索下拉 3 列 */
```

配套约定：
1. **历史行**（已结束）把「涨跌幅」替换为「结束日期」，占据同一右侧列位，右边缘对齐。
2. **次要行**用 `.stk2`：第一列固定 96px、中间弹性、右侧右对齐。
3. **ST 标签**不插在名称与代码之间（会挤掉代码列），统一放到该行最后一列；搜索下拉只有 3 列，ST 并入板块文案写作「创业板 · *ST」。
4. **非股票行**（含图标或输入框的行）不得套用 `.stk`。

## 7. 组件与交互

| 组件 | 形态 | 关键行为 |
| --- | --- | --- |
| `stock-search` | 38px 输入框 + 白浮层（≤5 条） | 250ms 防抖、旧请求丢弃、三种空结果文案 |
| `status-card` | 左 4px 色条 + 状态标签 + 一行原因 | 5 档取最高；色 + 文字双通道 |
| `alert-table` | 4 行紧凑表（本版核心减法产物） | 点行展开触发价 / 起止日 / 进度条 |
| `forecast-table` | 5 列 × 默认 5 行 | 失焦或回车本地重算；只重算该行及后续；展开 10 日 |
| `monitor-item` | 整宽行 + 网格 | 历史行灰显 + 「已结束」标签 |
| `prediction-item` | 整宽行 + 网格 | 已触发 / 临界 / 暂无法判定 |
| `diag-panel` | 折叠区 | `request_id` 等四项 + 复制 |
| `empty-state` | 一句话结论 + 一个动作 | 骨架 / 空态 / 失败三态复用同一模板 |

**核心流程（与 A 一致，仅减少状态分支）：**
1. 选股 → 250ms 防抖搜索 → 下拉 5 条 → 点选 → 先渲染上次结果再刷新。
2. T+N → 填涨幅 → 失焦本地重算（100ms，不请求网络）→ 刷新行情保留输入。
3. 刷新 → 按钮 loading 且禁用 → 3 秒内返回快照或任务状态 → 成功更新并对比上次结果（有新增则提示，首次不提示）→ 失败保留旧数据 + 重试。

## 8. 状态覆盖

| 状态 | 表现 |
| --- | --- |
| 骨架屏 | 与真实行同高灰块，含筛选条占位；1.5 秒内出现 |
| 空态 | 统一模板「一句话结论 + 一个动作」；三种文案：未选择 / 已扫描无候选 / 筛选无结果（含「清除筛选」） |
| 成功 | 数据替换，扫描信息与时间更新 |
| 新触发反馈 | 浅红条「新增 3 只触发（对比 14:35）· 名单」+「查看 ›」定位 |
| 输入校验错误 | 该单元格红框 + 表下一行说明；其他行不受影响 |
| 刷新失败 | 保留旧数据（降透明度）+ 顶部失败条（原因 + 上次成功时间）+ 重试；按钮禁用 |
| 无网络 | 顶部「当前无网络，未更新」+「缓存数据」标签 + 缓存时间；刷新按钮禁用 |
| 数据不足 | 「暂无法判定」灰徽章 + 具体缺失项；不显示安全空间、不用 0 补齐 |
| 部分失败 | 扫描信息行「失败 12 只（限流）」；诊断区 `data_quality = partial` |
