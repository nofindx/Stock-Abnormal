# 2.0.0官方广告版本：产品与实施方案

> ADS-V2-20261112.2；2026-11-12；状态：设计稿，待用户评审；版本号2.0.0为规划值，尚未修改运行元信息。
> 基线：`freeze/v1.0.21-20261112`，小程序1.0.21 / 后端20261111.1 / 预测v75。独立分支：`codex/ads-v2-design-20261112`。
> 本稿替代根目录《广告版本方案_20261112.md》的位置及生命周期建议；旧方案随冻结标签保留。当前只设计，不改代码、不上传、不部署、不请求真实广告。

## 1. 版本目标

在已有股票工具中增加少量微信官方广告，通过流量主获得收入补贴运行成本。查询、刷新、模拟、四项预警、重点监控、公告阅读继续按冻结版本提供；广告不决定任何股票风险结论或功能权限。

首版只使用微信官方 `ad-custom` 原生模板广告。实际模板、尺寸和可用能力在开通后由平台后台确认；若不支持该形态，应调整设计后再实现，不静默换成插屏或其他平台广告。Banner、插屏、激励视频、看广告解锁、会员、自营广告及第三方SDK不在本版。

## 2. 开通前后分别能做什么

用户提供的当前条件：累计独立访客UV > 100；无刷粉行为且未曾有严重违规记录。当前未满足。平台UV定义与去重由平台统计，不用自建本地计数替代，也不承诺达到数量后自动开通或自动获批。

| 阶段 | 可以做 | 不得宣称已完成 |
| --- | --- | --- |
| 当前设计 | PRD增量定义、组件契约、配置契约、布局、异常和回归用例 | 流量主已开通、广告已投放、已有收入 |
| 后续获准开发、尚无资格 | 独立分支实现；默认关闭；自动化中模拟load/error，不挂载真实广告 | 模拟事件通过等于真广告/真机投放通过 |
| 条件达成且平台开通 | 创建归属本AppID的广告位，按官方方式验证真实加载与页面行为，补齐隐私和审核材料 | 广告审核中/无填充等于可稳定投放 |
| 新包提审与发布 | 用实际广告配置核验后提交2.0.0；通过并发布后再启用投放 | 只上传开发包等于正式上线 |

无资格时，不填假的广告位ID、不请求其他AppID广告位、不刷UV、不点击自己广告制造收入。可以完成关闭路径和错误路径开发；真实投放验收须等开通。本版不主动上传一个带不可用广告占位的候选替换1.0.21。

## 3. 页面产品定义

### 3.1 位置与数量

| 页面 | 位置 | 条件与数量 |
| --- | --- | --- |
| 异动预测 | 当前列表全部业务卡之后、法律页脚之前，随页面滚动 | 当前标签读取成功且业务卡数≥1时可展示；每个页面实例1个广告位 |
| 单股计算 | 模拟计算区域之后、法律页脚之前，随页面滚动 | 已选股且详情读取成功可展示；每个页面实例1个广告位 |
| 重点监控 | 无广告 | 不插入监管事实列表 |
| 初始搜索、无结果、错误页、规则、隐私、PDF阅读 | 无广告 | 不放空壳、弹窗、悬浮或全屏广告 |

相比首稿，预测广告改为固定列表末尾。其曝光可能较少，但不会因4/5张卡边界或列表顺序变化而移动、反复创建广告。先验证体验与实际收入，再单独评审是否需要列表中间位置。

单股IPO暂不适用、已有监管事实等正常详情均按同一位置处理，不根据股票风险等级定向投广告。主要数据不可用且页面进入整体错误态时不展示；单项指标不可用但其余详情正常时，不影响已有功能，也不由广告改变状态。

### 3.2 内容和交互

广告不是股票卡，不计入数量、排序、筛选、收藏或跳转目标。预测 `items` 和监控数据中不插入广告对象；广告位是前端模板的独立兄弟节点。平台广告标识、原生关闭/操作入口（若选定模板提供）及素材不得遮挡、裁剪或伪装。

不使用红黄预警背景装饰广告，不添加“交易所推荐”“安全机会”等文案。与相邻可点击区域隔开，不覆盖刷新、股票、模拟输入、清空、页脚或底部Tab。实际最小尺寸与间距服从官方模板规范，再做iOS/Android验收，不预先编造固定平台尺寸。

页面业务内容先展示。广告加载、错误、关闭不会改变行情、S1/S2、四项计算、模拟输入、监管期限及PDF下载。业务请求失败后仍有明确原提示，不能因广告成功把页面标成成功。

### 3.3 次数与生命周期

不传 `ad-intervals`，不增加应用层轮播或定时刷新广告；一个页面实例最多一次应用层挂载尝试。新页面实例或新一次小程序冷启动可按平台规范重新加载，不建立用户级曝光计数器。

先取得业务S1成功结果，再独立加载广告，不等待S2成功，也不延迟或改变S2。配置获取也与S1/S2并行，广告就绪不进入业务loading状态。

| 用户操作/事件 | 业务行为 | 广告行为 |
| --- | --- | --- |
| 首次进入有效内容页 | 原S1→S2流程 | 配置允许后独立尝试1次 |
| 当日/次日标签切换 | 原标签读取，不新增自动行情刷新 | 复用本页广告组件；不重新创建或主动刷新 |
| 更换股票、清空/展开模拟、手动行情刷新 | 维持现有交互 | 不重新创建广告 |
| 内容变为空、整体错误或广告关闭 | 业务照常呈现对应结果 | 隐藏并折叠广告区域，不因同页再次有内容自动重建 |
| 隐藏后返回同一页面 | 原日期/行情策略 | 允许恢复已有广告区域；不主动重载 |
| 跨日/跨阶段 | 原业务时钟切换 | 不额外请求广告；未失效且内容条件满足才可保持已有展示 |
| 配置关闭或过期、无效/失败 | 业务不受影响 | 停止新的广告挂载；发现已关闭时隐藏当前区域 |
| 页面销毁 | 原清理流程 | 清理应用层监听/任务，调用存在且适用的官方清理能力，不编造组件API |

条件不成立时可以隐藏已有组件外层，不通过切换 `wx:if` 频繁销毁/重建。折叠不创建透明遮挡层，也不以屏外1px等方式请求不可见广告。隐藏外层的实现需遵循官方模板可见性要求；平台不允许该保留方式时采用终止本页展示、其后不再挂载，不以实现约束驱动反复请求。

## 4. 结构与接口

保持当前前后端、MySQL、Redis、云托管及行情链路，不扩展规则模块或公告模块。

### 4.1 前端

两个新增单元：共用广告位组件 `components/official-ad`，配置读取工具 `utils/ads-config`。页面仅声明placement和内容是否允许显示；组件封装 `ad-custom`、load/error和布局，不接收股票价格、搜索词或监管事实。

广告使用私有UI状态，例如idle/loading/loaded/failed/disabled，与股票的交易、监管、数据状态完全独立。仅在有效配置、支持的基础库、页面前台且有合适内容时挂载；不支持时直接关闭广告能力。

不新增登录、用户账户、跨用户频控或个性化画像，不为广告上传搜索历史、模拟输入或股票风险标签。

### 4.2 后端配置

新增公开只读 `GET /api/client-config`，沿用现有云托管入口；不使用S1/S2签名、不新建读上下文、不读取行情与公告、不取得MySQL或Redis连接。配置为随部署维护的固定映射/开关，不做广告管理后台。

示例为尚未开通时的有效返回：

```json
{
  "code": 0,
  "data": {
    "configVersion": "ads-v2-1",
    "ads": {
      "enabled": false,
      "allowedVersions": ["2.0.0"],
      "cacheTtlSeconds": 600,
      "placements": {
        "prediction_footer": {"enabled": false, "type": "ad-custom", "unitId": ""},
        "stock_footer": {"enabled": false, "type": "ad-custom", "unitId": ""}
      }
    }
  },
  "message": "ok"
}
```

生产开关默认false；平台开通且真实广告位核验后，才将相应位置设为true并填入广告单元ID。广告位ID是展示标识，不是密码；签名密钥及数据源凭据绝不包含在此接口。

客户端精确匹配自身版本；版本信息仅控制展示，不是鉴权。未知placement、未知type、空ID、格式错误、无效TTL、网络/HTTP错误一律广告关闭，业务继续。响应不使用共享CDN长缓存，避免叠加关闭延迟；服务端固定配置不依赖客户端query改变。

### 4.3 缓存和运营关闭

成功配置600秒有效，仅进程内共享，不持久化广告开启状态到本地磁盘。进程内并发获取合并为1个请求；客户端失败后60秒内不自动重试，下次页面展示或新加载机会再判断，不启动重试定时器。不缓存超时失败为业务失败，不在每次业务刷新时获取配置。

客户端冷启动或页面可见且需要配置时获取；未过期复用，过期后停止新挂载并异步获取。对已展示广告，页面onShow/内容变化等已有生命周期检查到过期时先隐藏，待新配置有效且允许时可恢复同一组件，不触发重建。

运营急停优先在微信流量主后台关闭广告单元；服务配置总开关作补充。由于页面可能持续停留或离线，不能保证配置变更后600秒内全部终端消失，不额外增加常驻轮询。若将来需要严格的即时急停时限，另行评审，不把缓存TTL当成在线推送能力。

### 4.4 数据与成本

不新增MySQL表、Redis键或实例，不改变数据库结构，不触发预测重算、基础数据回建和公告重采。Redis继续服务原有行情协调与授权视图，广告配置不依赖它。

广告素材和投放由官方组件处理，后端不代理、缓存或存储广告图片/视频。UV、有效曝光、填充、收入采用微信后台统计；load仅表示加载成功，不能当曝光、点击或收入。首版不自建点击上报或用户行为库。

## 5. 隐私与审核

在实际接入前核对官方组件、公众平台隐私指引、流量主协议、个人主体结算和税务要求，再修改隐私页面及平台填写项。准确说明微信官方广告及平台侧处理，保持不申请无关的个人权限；不能未经核对就承诺“平台完全不处理信息”，也不虚填本程序没有调用的权限。

业务描述仍为当前实际股票工具，新增广告不改变类目事实。审核备注说明广告位置、广告失败不影响功能、官方广告组件、核心功能免费；不以广告设计为理由包装或变更原有业务性质。已审1.0.21不混入此版材料变更。

## 6. 验收矩阵

| 范围 | 关键场景 | 通过标准 |
| --- | --- | --- |
| 资格未达成 | 空ID/默认关闭/配置不可用 | 无真实广告组件挂载和请求，无占位卡；所有现有功能可用 |
| 配置 | 总关/分位关、版本不匹配、未知形态、超时、600秒边界、60秒失败退避 | 状态明确且不保留无限期旧开启配置；并发配置获取合并 |
| 官方事件 | load、1000–1008各类错误、无填充、迟到回调、反复事件 | 广告独立处理；不破坏布局和业务状态，无无限重试 |
| 生命周期 | 快速切标签、换股票、返回、手动刷新、清空、展开、跨日、PDF返回 | 每页面最多1次应用层挂载；不增加S2次数，不丢输入，不回显旧业务结果 |
| 布局 | 长/短/空列表、IPO暂不适用、单项不可用、窄屏、字号、键盘、底部导航 | 数量不变、无遮挡、广告原生标识完整，无误触诱导 |
| 旧包兼容 | 1.0.21客户端与增加配置接口的后端 | 现有API契约、规则结果和刷新策略不变 |
| 故障隔离 | 广告/配置源不可用，业务健康 | 不等待广告超时再显示结果，不重试行情或污染数据集 |
| 真投放 | 开通后iOS/Android真实广告加载、原生返回/关闭（如支持） | 广告与页面可用；按官方测试方式核验，不自行反复点击制造收益 |
| 核心回归 | 四项、模拟上涨距离与初态、同向计次、重置、IPO、日期切换、监管期、PDF | 既有前后端自动化及受影响真机用例通过，规则版本不因广告改变 |
| 关闭 | 微信广告位关闭、配置总关/分位关、已显示页面和新页面 | 新加载停止；已有显示行为与实际生命周期相符，不声称瞬时全端关闭 |

性能验收聚焦可验证的非阻塞与请求次数：配置/广告慢或失败时，业务完成无需等待；相同业务路径不增加行情、数据集和数据库请求。开通后以相同设备和网络比较页面内容就绪耗时，记录真实差异，不编造当前容量或收益指标。

## 7. 实施顺序与上线条件

1. 现在：冻结1.0.21，交付本设计稿。用户评审位置、广告形态和免费边界后，再开始代码。
2. 开发：独立分支实现共用组件、配置接口和两页接入；默认关闭；自动化验证关闭/失败路径。无需等UV条件达成才写代码，但不得用模拟结果充当投放通过。
3. 开通：UV及账号条件达成后，由用户在平台办理开通与结算；取得真实单元后补齐投放、隐私和真机测试。
4. 提审：同步前后端新发布标识、2.0.0元信息、PRD增量和测试证据。后端仅向后兼容地增加配置接口，不升级行情规则、不重建数据、不改变冻结标签。
5. 发布：保持广告关闭完成新包上线；真实广告与审核条件全部满足后，先启用预测页，稳定后再启用单股页。若平台要求审核时广告可验证，则通过实际测试配置呈现，不对审核流量隐瞒生产功能。
6. 观察：用7–14天后台有效曝光、收入、错误与反馈决定保留位置；如曝光不足，再评审改版，不自动叠加广告。日收入粗估=实际有效曝光×实际eCPM÷1000，不按UV直接承诺收入。

本阶段无须用户提供密码或广告ID，也无需购买新资源。下次可评审事项为本方案的广告形态与两个末尾位置；资格开通是将来的投放前置条件，不阻断当前设计。

- [ad](https://developers.weixin.qq.com/miniprogram/dev/component/ad.html)：Banner等能力参考，本版不同时启用。
