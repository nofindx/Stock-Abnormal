# 云服务成本优化评估

评估日期：2026-11-10。仅为方案，未修改线上规格、实例数、数据库或计费模式。

## 1. 结论

优先核对账单并评估现有云托管降配，不为每天约3元立即迁移整套服务。当前尚未取得该笔费用的产品名和计费项，因此不能确认它是云托管计算费、云开发套餐还是其他费用。

官方微信云托管刊例价为CPU 0.055元/核小时、内存0.032元/GB小时。用户本轮确认当前为1核2GB；单实例连续运行24小时的计算费为2.856元/天，与用户报告金额接近，最终费用构成仍需账单核实。

## 2. 同平台降配测算

以下按单实例、全天运行、30天计算，只包括容器CPU和内存，不含MySQL、Redis、流量、构建及其他费用；实际以账户账单为准。

| 实例规格 | 元/天 | 元/30天 | 使用建议 |
| --- | ---: | ---: | --- |
| 1核2GB | 2.856 | 85.68 | 用户确认的当前规格；按单实例连续运行测算 |
| 1核1GB | 2.088 | 62.64 | 内存峰值允许时可评估 |
| 0.5核1GB | 1.428 | 42.84 | 优先评估候选；相对比较基准计算费降低50% |
| 0.25核0.5GB | 0.714 | 21.42 | 暂不建议直接采用，需关注全市场计算和公告处理峰值 |

不把最大实例数从5改成1作为固定节省：按量费用取决于实际运行实例和时长，单纯降低上限还会限制并发容量。旧版本若实际运行仍产生费用，需单独核对，不能只看流量分配比例。

当前server/app.py的main()会启动行情及公告后台调度。若直接把最小实例数改为0，缩容后后台任务无法按时运行；要采用零实例模式需先调整调度方式，本轮不建议为此改造。

## 3. 其他方案及边界

- 包月与资源包：微信云托管容器基础计费仍为按量付费，官方提供不定期优惠资源包，具体规格和价格以控制台为准；不是固定不限用量包月。当前1核2GB单实例运行30天需要720核小时、1440GB小时，购买时需同时核对CPU、内存额度、有效期和适用环境。资源包发货后即计算有效期，到期未用完不能继续抵扣；未确认当前账户有可用优惠，不承诺折扣。
- 云开发基础套餐：微信官方当前公布19.9元/月、40000资源点/月。但这是云开发套餐，并不代表现有云托管后端和MySQL可以整体按19.9元/月运行；不能只比较套餐标价。
- 轻量服务器：可另行比较当前续费价，但需要评估现有MySQL/Redis私网连接、域名HTTPS、小程序接入及维护成本；未核实可用报价，本轮不承诺具体节省金额。
- Redis：用户已预付五年，且当前用于共享缓存、请求合并及实时视图。删除不会自然变成每月可节省的现金，不作为本轮降本动作。
- MySQL：算力与存储单独计费。若账单主要是数据库，应先定位频繁访问及资源用量，不能用容器降配替代数据库成本分析。
- 前端正式版继续复用callContainer。官方说明仅通过callContainer访问服务不产生对应的容器公网流量用量；服务主动访问公网等用量仍需另计。

## 4. 最小执行步骤

1. 在微信云托管“费用中心→充值与账单”查看最近7天，区分CPU、内存、MySQL、构建、流量等计费项；如实际是云开发套餐，则记录套餐名称和资源点消耗。
2. 对照当前实例规格和运行实例数，查看最近7天CPU、内存峰值，覆盖收盘计算、夜间公告和正常请求。
3. 若峰值有余量，选择0.5核1GB等可用规格小幅降配；保留最小1实例以维持当前后台调度。降配前确认规格支持及恢复原规格方式。
4. 降配后检查单股/预测刷新、收盘计算和夜间公告任务，比较实际账单；若计算超时、内存不足或任务失败，恢复原规格。

尚缺：具体账单计费项、高峰监控和控制台可购资源包价格。不据此直接变更生产配置。
