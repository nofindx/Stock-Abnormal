# 最新行情刷新回退：原因、修复与验收

日期：20261109；时区：Asia/Shanghai。本文记录本地候选修复，不是云端发布回执。

## 1. 结论与历史依据

本次不是手机缓存导致。11月9日午休，线上直接报价接口已能返回11月9日腾讯报价，但单股/预测S1返回 `realtimeRefreshAllowed=false`，S2返回 `not_allowed` 并保留11月6日数据。问题发生在业务刷新权限与结果表达层。

| 提交 | 时间 | 与本问题的关系 |
| --- | --- | --- |
| `98ab8da` | 20261029 | vNext文档引入午休、盘后、非交易日跳过实时阶段的限制；这是错误的产品边界，不是行情源限制 |
| `1d0b82f` | 20261101 23:29 | 授权读取流程把时段不允许、非current角色的S2直接返回ready/fresh + not_allowed，实际未取价却表现为成功 |
| `726b691` | 20261107 10:45 | 修复复牌基线时同时将原09:15–15:00取价区间缩为09:15–11:30、13:00–15:00；预测v72→v73，新增午休禁用，因此最近版本出现回退 |
| `7eab9ba` | 20261108 | v74历史缺口修正继承上述限制，没有恢复午休刷新 |

根因：将“交易日/预测开放时段”误当成“允许获取来源最新报价的时段”。验证遗漏：旧测试把午休禁止取价写成预期，且周末接口检查只验证了旧合同；没有用午休下真实来源有新报价、页面仍显示旧价的场景核验。复牌计算修复与刷新时段变更混在同一提交，扩大了改动范围。

## 2. 已实施修复

- 单股与预测页面实例首次打开按S1→S2执行，午休、盘前、盘后、周末均允许获取来源最新可用报价；后续返回/切标签不重复自动S2，用户手动刷新仍有效。
- 仅刷新已发布名单或所选证券及指数，不扩池、不做全市场盘中扫描。next角色仅更新显示价格/涨跌幅，不重算未来触发条件。
- 保留真实来源日期时间。周末周五报价仍为周五，不追加周末收益、不改写为今天。
- 股票报价有效、指数缺失或时点不匹配时仍更新价格，但保留原规则与模拟基线并明确提示。价格日期与计算日期分开，不推进未配对的模拟日期。
- 取价失败保留授权视图原内容并报告stale/fallback；不得返回“跳过且fresh”。重复手动刷新失败保留上次报价，共享任务同时绑定输入实时视图，避免不同视图的失败回退串用旧价格。
- 无时间、无效价格、早于已存基准日、未来时间报价不覆盖。东方财富回退源使用小数价格参数并将epoch转为上海时间。
- Redis与来源就绪检查保持有效。本轮无数据库结构、行情重建、公告事实或规则阈值变更，预测规则版本仍为v74；不因刷新权限变化强制全市场重算。
