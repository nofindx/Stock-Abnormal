# vNext 实施前置门禁执行计划

> 版本：GATE-PLAN-20261029.5

> 适用基线：PRD-NEXT-20261030.22、ARCH-NEXT-20261030.21、DEV-NEXT-20261030.28、TEST-NEXT-20261030.19

本文件把开发前必须完成的三个门禁拆成工作包。文档评审已完成，但下列门禁尚未执行，不能把计划、mock 单测或旧线上行为写成通过证据。

## 1. 总体顺序

1. **A：核心规则证据**：核对四板块核心参数、基准映射、公告重置和关键停复牌/除权边界，建立少量可重算夹具。
2. **B：PDF 阅读链路**：验证冻结版临时缓存、受控代理和小程序内打开，不建设 COS/PDF 对象系统。
3. **C：联合回归**：按测试文档执行规则、状态、并发刷新和临时 PDF 清理验收。

A 与 B 可并行准备；C 必须等待 B 的样本、预算和目标链路完成。任一 P0/P1 阻断项未关闭，不得放行 vNext 相关能力。

## 2. 工作包 A：收益构造与停复牌规则取证

**主责：**规则/开发负责人；**复核：**架构师、测试负责人；**签署：**产品经理（仅产品行为变化时）

### 当前盘点

- `server/rules/catalog.py` 当前已有阈值/四规则/重置范围定义；下一版本需要补齐四板块核心证据表、基准映射和关键边界的来源与生效日期。
- `server/core/models.py` 有 `adj_factor` 基础字段；`TushareClient.suspend_d()` 可读取停牌状态，但尚未形成可审计的停复牌事实账本。
- 现有测试已覆盖部分停牌/重置路径；vNext 产品规则夹具补齐独立重放案例。门禁不要求逐板块官方证据，但仍要求产品依据、内容哈希和实际重放结果。
- 已有旧 PRD 的来源链接和现有单测不能替代规则原文、条款、生效日及行情样本的证据封存。
- 因此 A 当前为 `BLOCKING_ON_EVIDENCE`。范围限定为四板块核心参数、基准映射、普通/严重公告重置、普通/严重相关停复牌复牌基线和除权边界；不要求逐证券逐交易日覆盖或穷举全部停牌组合。

### 输入

- 适用交易所、板块、证券类别、规则生效日期和交易日历。
- 官方交易规则、停复牌/复牌公告、除权除息公告及可核验的行情样本。
- 当前规则包中的 `source_ref`、`return_policy_id`、停牌原因和复牌首个有效收益日字段。

### 操作

1. 对四板块和关键情形记录官方来源、适用日期、基准指数、价格构造、复牌首个共同有效收益日、停牌原因和比较基点；官方未明确的内容标记为产品口径。
2. 建立少量版本化 fixture，覆盖：四板块阈值与映射、普通公告重置、严重公告重置、普通事项停牌复牌保留同向事件、严重异动相关停牌复牌清零、除权/复牌边界。
4. 运行规则重放，记录输入 manifest、输出、来源证据、复核人和差异结论；没有证据的策略标 `pending_verification`，不得生成正式触发或安全结论。

### 通过条件

- 每个会影响正式结果的四板块核心边界都有已审核证据或明确产品口径，不能默认继承相邻板块规则。
- 规则、证据、fixture 哈希和重放结果可追溯。
- 停牌原因无法确认时输出待核验，不猜测清零或延续。
- 相关收益构造门禁通过前，不启用对应生产结论。

## 3. 工作包 B：PDF 阅读链路准备

**主责：**开发/数据负责人；**架构预算：**架构师；**体验签署：**产品经理；**环境：**运维负责人

### 当前审计结论

- 现有 `server/services/monitor_service.py` 将支持阅读的正式公告 PDF 写入 `/tmp/stock-abnormal/monitor-pdf`，`server/app.py` 通过受控短期签名入口返回；不写 Redis/COS。
- 需要验证普通异动、严重异动、退市整理三类可用直链均能缓存并在小程序内打开；普通风险提示公告不提供 PDF 入口。
- 该链路不使用 COS/Redis 保存 PDF；实例临时目录是有界缓存，监管展示期结束时清理。

### 操作

1. 选取已授权的普通异动、严重异动、退市整理 PDF 进行本地/真机合同测试，不将受限原件或生产用户数据提交公共 Git。
2. 验证实例临时目录、受控 key、`%PDF` 文件头校验、非 PDF 拒绝、失败清理和监管期结束清理。
3. 验证微信合法下载域名、`wx.downloadFile` 和 `wx.openDocument`；不要求复制 URL 或跳转浏览器。

### B 通过条件

- 三类公告阅读合同、失败文案和清理行为有测试证据。
- 受控代理只返回当前有效快照中已缓存 PDF，不接受任意 URL。
- 双实例/并发刷新不影响 PDF 临时缓存的正确性；PDF 阅读不写入 Redis/COS。

## 4. 工作包 C：联合回归与发布验收

**主责：**测试负责人；**执行：**开发/运维；**复核：**架构师、产品经理

### 阶段

1. **本地合同测试**：PDF 魔数、非 PDF、受控 key、到期清理、超时、取消下载清理、任意 URL 拒绝、错误码和 `wx.openDocument` 调用契约。
2. **真机烟测**：普通异动、严重异动、退市整理三类文件；确认小程序内下载后打开，不跳浏览器。
3. **联合回归**：按测试文档执行规则、公告事实、状态组合、两阶段刷新、Redis 并发隔离和发布门禁；PDF 仅作为独立阅读能力，不混入规则事实正确性。

### 通过条件

- 非 PDF、无效 key、过期缓存和下载失败均不进入阅读器。
- 真机可在小程序内打开有效 PDF，返回原页面后临时文件可清理。
- 规则/事实/状态/并发回归通过；PDF 失败不改变事实、计次和重置。

## 5. 明确阻断项

以下任一项存在，相关规则或 PDF 阅读门禁保持 BLOCKING：

- 没有可用于真机合同测试的三类公告 PDF 样本。
- 受控代理、下载域名或实例临时目录未验证。
- 无效 key、非 PDF 或到期缓存仍能生成死入口。
- 对巨潮、Tushare 或其他公开行情/公告源直接压测。
- 哈希/内容错误、未授权对象可读、错误率超标、资源不恢复或证据缺失。
- 收益构造/停复牌规则缺少来源证据、策略覆盖或确定性重放结果。
