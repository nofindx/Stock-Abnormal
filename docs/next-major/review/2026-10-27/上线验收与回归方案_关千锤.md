## ① 总评结论

**一句话总判：13 条验收标准中 10 条具备"可写成语句级断言"的条件，3 条（#6、#7、#13）存在定义歧义或证据缺口，必须先做"可测化改造"才能进入验收；现网质量资产（4 个 tools 脚本 + 246 项 unittest + 4 组 Node 测试）可复用为验收检具的底座，但全部绑定 1.0.x 的 `today/next_day` 口径与自由文本缺因，vNext 必须升级后才能充当发布门禁的执行器。**

分五层判断：

1. **验收标准本身是"语义合格、断言缺失"。** PRD §11 的 13 条全部是行为描述（如"数据不可用不显示安全"），没有一条直接给出"查哪张表、比哪个字段、阈值是多少"。四份评审实际上已经把断言补齐了（顾图南 G11 `no_silent_safe`、宋砚秋 `UNAVAILABLE_REASON_PRESENT`、夏小笺"不存在 `state=undetermined` 且 reasons 为空"断言），但**没有人把断言逐条映射回 PRD §11 的 13 条并声明归属阶段**——这正是本文第 ④ 章补上的缺口。结论：13 条中 10 条可全自动化机检，2 条（#6 首开刷新、#7 时间场景）需"注入时钟/抓包 + 真机抽验"混合判定，1 条（#13 PDF）需构造"清理后"场景的夹具才能断言。
2. **统一发布门禁是"三套清单、两套严重级、无豁免规则"。** 顾图南 G01–G15（§7.9）、宋砚秋 13 block + 6 warn（§9.1/9.2）、霍承钧 §7.3 的 19 项之间存在大量语义重叠但阈值不一致：正文可读率顾图南定 ≥98%（G06）vs 宋砚秋/霍承钧定 ≥90%；公告批次完成度顾图南定 block vs 霍承钧定 warn；宋砚秋的 `HISTORY_INSUFFICIENT` 定 block 但同时说"仅影响依赖该窗口的项"（自相矛盾，顾图南 7.10.3 已定为"逐只标 unavailable 不阻断"）。**必须合并去重成一份统一清单并定死阈值**，否则 M7 验收时会出现"同一数据集在两套门禁下一个过一个不过"的仲裁僵局——本文第 ⑦ 章完成合并。
3. **回归测试资产"现网强、缺口清楚"。** 现网已具备：全市场同向对账（`same_direction_check.py`，5577/5577 活跃股票）、契约检查（`api_contract_check.py`）、迁移/健康审计（`prediction_migration_check.py` / `health_alert_check.py`）、注入时钟的时间边界用例（TIME-001~008）和真实历史案例（近岸蛋白 23 日 +142.3258%、*ST元道倒计时、新华传媒双事实等）。缺口：无 Golden fixture 重放机制、无双跑对账工具、无 `undetermined`/缺因码级用例、无停复牌语义反转的专门用例（现网语义与 vNext 相反，直接复用会掩盖错误）。本文第 ⑤⑥ 章补齐。
4. **发布门禁之外的"验收门禁"有 4 条漏项**：`undetermined` 裸值断言、UNKNOWN 占比阈值（已定稿 >1% block / 0.2%~1% warn 但未进任何门禁清单）、下拉刷新路径禁触 S2 的 CI 断言、门禁执行本身必须全量留痕。已补进第 ⑦ 章 G16–G20。
5. **最高风险不在代码而在两个"外部不确定性"**：实时行情源无授权/SLA（顾图南 R5）与公告源覆盖不全导致长期待核验（顾图南 R2）。这两项决定验收策略必须"按能力降级设计验收"：盘中能力关闭是可验收状态而不是缺陷；长期待核验必须量化上限（PENDING_RATE ≤15%，霍承钧 §7.3）而不是默认为零。

**判定：有条件通过进入实施。** 采纳本文 ② 章 5 项 P1（全部是"验收可行性"阻塞，不改则 M7 无法给出通过证据）后，PRD §11 + 第 ④ 章映射表 + 第 ⑤ 章测试矩阵 + 第 ⑦ 章统一门禁可直接作为 M7 验收执行文档。

## ② P1 阻塞清单（验收可行性阻塞，必须在对应里程碑前闭合）

> 与四份评审的 P1 不重复：他们的 P1 是"实现/设计缺陷"，本文的 P1 是"不改则验收标准无法被判为通过/失败"。

### V-P1-1 三条验收标准存在歧义，必须改写为可断言表述

**证据：** PRD §11 第 237 行（#6）"首次打开"未定义周期——现网 `prediction/index.js:42-54` 用永久 localStorage 实现成"设备一生一次"（顾图南 P2-4），说明该措辞可被两种实现同时"满足"；第 238 行（#7）"三页面日期、状态、数值**同步**切换"没有定义"同步"的可观测证据；第 244 行（#13）"验证清理后页面状态"没有给出清理后接口应返回什么字段。

**建议改法（改 PRD §11 措辞，同时给出断言）：**
- #6 改为："**每次进入**异动预测或单股详情页面的首次会话编排均触发 S1；仅当接口返回 `session.intradayEligible=true` 时发起 S2；S2 失败响应必须含 `quoteLayer.asOf=null` + `reasonCode=SOURCE_QUOTE_FETCH_FAILED`，且不出现安全色"（与夏小笺 §0.5/0.8、P1-10 一致）。
- #7 改为："任一时刻三页响应的 `dataset.version` + `dataset.publishedAt` + `dateRole.code` 三元组完全一致（同一响应采样）；在 09:00:00 切换时刻前后各取一次三页快照，切换后三页 `dateRole.code` 同帧变更且 `businessDate` 同帧更新"——"同步"落为"同一版本指针 + 同帧变更"两个可断言条件。
- #13 改为："监管期内 `pdfAvailable=true` 且对象可下载；清理后接口返回 `pdfAvailable=false` + `pdfCleanedReasonCode` + `sourceUrl`，不返回失效直链；`pdf_purge_log` 存在对应记录"（与夏小笺 §0.7 pdfCleanedReasonCode 枚举一致）。

### V-P1-2 缺验收用的 Golden fixture 与双跑对账工具

**证据：** 顾图南 P2-12"无重放工具"；宋砚秋 P1-3"不保存原始日线，不可重放"；现网 `docs/测试规范与用例.md:70` 的真实案例（近岸蛋白等）散落在文字描述里，未固化为可机器重放的数据集。M6 双跑（顾图南 §8）没有定义差异的分类标准和判定人。

**建议改法：** 按本文第 ⑥ 章建设 `server/fixtures/golden/`（结构化夹具 + 期望结果 JSON）与 `server/tools/dual_run_check.py`；差异分类四档（本文 ⑥.3）在 M6 启动前定稿。

### V-P1-3 三套门禁清单阈值冲突，无豁免与留痕规则

**证据：** 见 ①.2；另顾图南 §7.9 门禁执行段落要求"run_gates() 返回全量留痕"，但没有任何门禁条目定义"豁免怎么办、谁批、留什么痕"——而 13 block 中至少 `HISTORY_INSUFFICIENT`（新上市股票天然不足）需要豁免路径，否则新股密集期天天阻断。

**建议改法：** 按第 ⑦ 章合并为统一清单 G01–G20；豁免规则统一为："warn 级可由值班人豁免并在 `quality_check_result` 留 `waived_by/waived_at/waived_reason`；block 级不可豁免，只能修复后重跑或放弃本次发布"。

### V-P1-4 已定稿口径未落入门禁执行器

**证据：** UNKNOWN 占比 >1% 阻断 / 0.2%~1% 告警（夏小笺 §0.7 已拍板"该阈值由统一门禁清单维护"）——但顾图南 G01–G15 与宋砚秋 13+6 里都没有这一条；`undetermined` 裸值断言（夏小笺 §0.6 约束 d"追加验收断言"）同样无人认领。

**建议改法：** 补 G16（undetermined 不变量）、G17（UNKNOWN 占比）、G18（前端文案表回归）等，见第 ⑦ 章。

### V-P1-5 现网检具与 vNext 契约不兼容，需在 M4 前完成升级

**证据：** `server/tools/api_contract_check.py` 按现网字段断言（`targetTradeDate/baseTradeDate/scope=today|next_day`，`docs/测试规范与用例.md:159`），与 vNext 定稿的 `dateRole= current|next`（顾图南 B-2）、`dataset.version = YYYYMMDD-NN`（宋砚秋）不兼容；`same_direction_check.py` 按"公告确认 ordinaryEvents + 行情向量复算"对账，未覆盖 `fact_end_date` 入窗与幂等键断言。

**建议改法：** M4 交付升级版三件套：`api_contract_check_vnext.py`（按顾图南 §7.4.8 契约 + 夏小笺 §0 信封断言）、`same_direction_check.py` 升级（增加入窗日/幂等/重叠计次断言）、新增 `gate_runner.py`（执行第 ⑦ 章 G01–G20 并落 `quality_check_result`）。现网脚本保留到 G3 下线（韩渡川 §6.3）。

### ⑧.4 发布后 24 小时观察项与回滚触发条件

**观察项（每小时汇总一次）：**
- 每日数据集是否按时发布（`published_at` 与 23:00 截止线距离）；
- 门禁阻断次数与 code 分布（`quality_gate_blocked_total`）；
- UNKNOWN / 待核验占比走势（G17 阈值内）；

- 前端埋点：缺因分布、版本不一致次数、刷新失败率。

**回滚触发条件（任一命中即执行）：**
1. 任一 block 门禁在发布后复检失败（如 G08 匿名计数 >0、G11 出现 silent safe）；
2. 数据集较截止时间晚 2 小时仍未发布且无告警闭环；
3. 出现任何"不可用被渲染为安全/0"的用户可见案例（P1 级，立即指针回切）；
4. 5xx 率 >0.1% 持续 30 分钟；
5. 事实账本污染（错误事实入账）：按韩渡川回滚矩阵置 `revoked` + 触发重算发布，<30 min。
