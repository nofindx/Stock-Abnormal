## 一、总评结论

**有条件通过进入实施——两份文档在"规则语义"层面已达可开发水准，但在"工程可落地性"上不具备直接开工条件。**

- **规则口径（产品层）**：四组状态、四项指标、10 日同向计次、重置边界、"数据不可用不得变安全"等核心原则自洽且正确，保持。
- **工程落地（实现层）**：架构稿宣称的关键机制（三页同版本、原子发布、规则唯一口径源）在现网代码中**均不存在**；10 日同向入窗、停复牌语义等实现与 PRD **方向相反**；直接按现网结构做 vNext 会把 1.0.x 的耦合固化成"模块化外壳 + 上帝模块内核"（`market_service.py` 单文件 3929 行 / 约 100 方法）。
- **性能**：纯计算不是瓶颈（全市场 3–11 秒）；瓶颈是公告 OCR（单篇最坏 96 秒）与逐股全量遍历 O(N×M)≈1.3×10⁷。按本报告优化方案，**不换技术栈**即可达成全部 SLO。
- **结论**：先闭合第一节列出的阻塞项与拍板项，再进入开发；口径先定，再建表，最后调实现——顺序不能反（先建表会把错误口径固化进结构，改正需重放全部历史）。

## 五、详细模块开发设计方案（要点索引）

完整设计在各分报告，此处为汇编索引：

1. **目标架构 9 包**（顾图南）：`domain / rules / data / calculation / announcements / orchestration / release / serving / api`——在 PRD 五层基础上把"业务服务"拆出 `orchestration`（编排/匹配调度/租约）与 `release`（门禁/原子发布/回滚/重放），消除门禁散落 if 分支的结构性问题。依赖单向化，CI 机检。
2. **规则模块**（霍承钧）：YAML + JSON Schema，加载即冻结 FrozenRuleSet，config_hash 入 dataset_version；每个配置叶子带 `basis: official|product_inference`，规则页分两栏展示（落实 PRD §4）。升级走 shadow → 影子重放 → 对账（差异率>0.5% 打回）→ canary → full → retired 六步。
3. **计算模块**（霍承钧）：次日口径方案 A；缺因传播三硬规则；输入改收盘价序列（废弃向量路径），消灭 engine.py 与 market_service 两条计算实现。
4. **数据模型**（宋砚秋）：31 张表 8 组（身份/映射 SCD-2、日历/停牌、行情、公告、事实/事件/重置、结果/版本、运维/质量/审计）；关键幂等键 `uk_fact_key`（不含来源）与 `uk_event_fact`（事实→事件 1:1）；发布前 CHECK 约束兜底"unavailable 必须有缺因码"；新增 `stock_fact_projection` 投影表防预测页 N+1。
5. **前端展示契约**（夏小笺）：统一响应信封（traceId）+ 公共块 `dataset{}`/`dateRole`/`session.intradayEligible`（交易时段判定必须后端下发）；四卡 MetricResult 同构（status 四值 + ring + retainUntil + unavailable）；模拟卡可行（向量 ≤31 个、<2KB、<5ms，golden fixture 校验口径漂移）；刷新两段式 + 全局 refreshCoordinator。
6. **部署运维**（韩渡川）：worker/API 分进程、MySQL 租约、CI 流水线、版本化迁移、结构化日志与告警分级、双跑灰度 G0–G3、备份恢复演练。
7. **验收体系**（关千锤）：13 条验收 → 断言 → 检具 → 阶段映射表；9 组 45 条回归用例（含近岸蛋白、新华传媒双事实等真实锚点）；统一 G01–G20 门禁（<60s 执行完，block 任一失败指针不动）；灰度与 24h 观察项、5 条回滚触发条件。
