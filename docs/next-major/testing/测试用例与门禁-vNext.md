# 异动查查 vNext 测试用例与发布门禁

> 版本：TEST-NEXT-20261030.19
> 对应文档：PRD-NEXT-20261030.22、ARCH-NEXT-20261030.21、DEV-NEXT-20261030.28
> 状态：本轮联合复核后条件通过；不代表测试已执行或 vNext 已上线。
> 范围：仅约束下一大版本目标，不改变当前 1.0.x 冻结验收基线。

## 1. 约定

PRD 定义产品预期，架构定义职责/依赖和故障域，开发设计定义可实现契约，本文件将三者转成测试断言。发现相互矛盾时先登记冲突并由对应产品/架构/开发责任人确认；测试不得自行选择口径，也不得把文档测试写成“通过”代替可运行代码测试。

优先级：P0 阻断规则/数据正确性或用户可见错误；P1 阻断核心可用性、并发安全或上线；P2 非阻断体验/运维改进。每个执行结果须记录用例 ID、代码提交、`rule_version`、`dataset_version`、行情源/报价时间、环境、执行时间、结果、证据引用和缺陷 ID。

每个测试夹具须有稳定 ID、fixture 文件路径、预期结果和适用用例；执行时计算并记录该 fixture 文件清单的 SHA-256 manifest，测试报告不得只写 fixture 名称。初始夹具 ID 规划：`F-Q2-ORDINARY-DIRECTION-PENDING`（方向待核验/两侧计数）、`F-Q2-SEVERE-RESET-D1`（严重公告 D+1 重置）、`F-REF-S1-POOL-FIXED`（S1 固定名单）、`F-API-S2-STATE-MATRIX`（S2 状态组合）、`F-REDIS-FENCE-FAILOVER`（分区与切主 fencing）、`F-PDF-INAPP-READ`（小程序内 PDF 阅读）。具体输入文件及哈希须在实现/测试阶段落入版本控制，并由执行报告实际记录；本文件不伪造尚不存在的哈希。
