## 3. 已发现的实现差异

这些是对本轮设计的符合性检查，不因单测通过而自动关闭。优先级表示对“完整 vNext 定版”的影响，不表示本轮已修改业务代码。

### R01 / P0：公告与正式数据仍不是同一持久化发布链路

开发设计要求事实、覆盖批次、重置及统一结果由 MySQL 版本化保存，通过持久化任务/outbox 请求重建。实际 `MonitorRepository` 和事实账本仍使用 SQLite（代码默认目录为实例 /tmp，路径可配置），而不是设计中的共享 MySQL 事实存储；公告发布后直接启动进程内 daemon Thread 调用预测重建。本轮不读取环境变量，因此不把默认目录当成已证实的生产挂载配置。现有实现不能据此宣称具有设计中的跨实例一致性或重放恢复能力。

证据：`server/services/monitor_service.py` 的 `MonitorRepository`、`OfficialMonitorService.refresh`；`server/data/fact_ledger.py`；DEV §2.2、§11、§13、§14。

### R02 / P0：S1 令牌尚未真正固定读取版本

实际 `/api/v2/context` 使用预测更新时间作为版本、`pool_hash` 缺失时填 `legacy`；预测读取时调用当前 `SERVICE.predictions(...)`，再附上令牌旧版本字段。令牌签名和 scope 检查不等于读取了令牌授权的不可变版本。需要在指针切换情况下证明旧 token 不读新数据，当前实现不能通过设计的 RELEASE-02。

证据：`server/app.py` 的 `/api/v2/context`、`/api/v2/predictions`；DEV §9、§12、§14。

### R03 / P1：预测页首开仍使用设备持久标志

PRD/DEV 要求每次页面进入会话执行 S1，再按交易时段执行 S2；当前 `prediction/index.js` 仍读取/写入持久存储的 `FIRST_OPEN_REFRESH_KEY`，已有标志时仅执行 `loadData()`。现有首次打开测试验证的是当前旧行为，不能证明新要求已实现。

证据：`miniprogram/pages/prediction/index.js` 的 `onLoad`；PRD §5、DEV §10.1、REF 用例。

### R04 / P1：S2、任务和前端协议尚未完整接通

设计要求 stock/prediction scope、`request_id`、有界 202 排队、持久 job 轮询、授权实时视图和替换 token。实际刷新路由主要支持 today/next_day 预测，未提供设计中的完整单股 S2 和 jobs 流程；新协议仍混合旧 camelCase 字段；前端请求层把错误收敛为文本 Error，不能据此证明 409 上下文整体重取、202 轮询和 stale 行为符合文档。

证据：`server/app.py` 的 `do_POST`；`miniprogram/utils/api.js`、`request.js`；DEV §10、§12、§13。

### R05 / P1：PDF 单元能力不等于页面入口覆盖完成

生产 `GET /api/monitor?type=all` 的基线样本中，凡拓数创严重异动、*ST卓然严重异动和萃华退退市整理条目均为 `pdfAvailable=false`；大业股份为 true。必须逐项核查实际来源与阅读入口，不能把“签名密钥已配置/PDF 单测通过”记成普通、严重、退市三类真机阅读通过。

证据：本轮生产接口抽样；DEV §15、PDF-01/05。

### R06 / P1：非交易时段的行情语义需核实

生产世纪恒通单股样本在休市日返回 `stage=formal`，同时 `intraday=true/realtime=true`，报价时刻为 `2026-10-30T16:14:45`；需区分“读取到行情源最后报价”与“当前实时交易结果”，核实单股是否在非交易时段仍向实时源取数。不能仅凭报价存在就称为当前实时。

证据：生产 `GET /api/stocks/detail?ts_code=301428.SZ`；PRD §3.4/§5，DEV §10。

### R07 / P1：发布记录与实施证据过期

### R08 / P0：正式预测生成没有完整覆盖 10 日同向

实际 `_compute_prediction_from_repository` 的规则列表只有 `severe_10d`、`severe_30d`，条件分支再插入 `ordinary_3d`；正式仓储路径没有把 `same_direction_10d` 加入该列表。详情页已有同向数值并不能证明同向预测池已生成。需建立同向即将达阈值的公告事实夹具，验证正式名单和详情一致，不能因本次 6/2 张均为偏离卡而漏验该项。

证据：`server/services/market_service.py` 的 `_compute_prediction_from_repository`；PRD §7、DEV §7.3/7.4。

### R09 / P0：公告分页截断被误标为覆盖完整

本轮已使用不联网的模拟来源复现：每一页均返回一条合法公告且 `hasMore=True`，采集在第 8 页达到硬上限后结束；最终仍返回 `status=available, available=True, partial=False`。本地共执行 96 个模拟请求（3 栏目×4 关键词×8 页）。这不能证明线上实际漏了哪些公告，但证明“来源全绿/已读正文全部成功”不足以证明列表覆盖完整。若 90 天范围超过页数上限，正式同向次数可能被错误地当成精确值。

证据：`server/services/announcement_service.py` 的 `query_market`；PRD §6/§11，SOURCE-02。

### R10 / P1：状态、日期和协议仍保留旧语义

线上萃华退和新华传媒 `stockState.dataState=partial`，而 PRD 限定数据状态为可用/不可用；新华传媒部分预警显示 `--` 但 `className=safe`。实际业务日期如 `tradeDate`、`targetTradeDate` 仍含 `YYYY-MM-DD`；开发者工具页面也显示连字符日期。需要通过兼容适配明确哪些是原始时间/展示文本、哪些是业务日期，不能认为全部已统一为 `YYYYMMDD`。

证据：本轮单股接口抽样与模拟器；PRD §2/§3.4、DATE-02/PARTIAL-01。
