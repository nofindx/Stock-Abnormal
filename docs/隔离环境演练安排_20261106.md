# T2/T4/T6 隔离环境演练安排

版本：`DRILL-20261106.2`。状态：**用户决定暂不执行真实演练**。本文件保留恢复演练步骤，供未来重新启动时使用；当前这些门禁均记为未验证，不记为通过。

## 顺序

1. **准备隔离环境**：单独的可销毁 MySQL 恢复目标、单独的测试 Redis 实例、独立 CloudRun 测试服务（至少 2 个实例）。服务只使用测试 DB/Redis 和模拟或回放行情源；不配置生产写入凭据，不连接生产发布指针。
2. **T2 数据库恢复**：从已验证的生产备份恢复到隔离 MySQL；核对 migration ledger、schema、公告事实、行情输入及已发布结果的数量/摘要；执行恢复后的只读查询和重放一致性对账，实测 RPO/RTO。门槛按测试文档：RPO ≤24h、RTO ≤2h。只允许在隔离目标上执行恢复、迁移中断/重试和清理。
3. **T4 Redis 故障切换**：用两个隔离实例验证同 key 请求合并、租约到期接管、fencing 拒绝旧 worker 写入、Redis 重启/切主/短暂不可达时的恢复与降级。只操作测试 Redis；记录切换时间、请求状态、视图版本及是否有旧写覆盖。
4. **T6 性能与降级**：在两个隔离 CloudRun 实例，以 mock/回放行情源运行 100 活跃会话 30 分钟（2 分钟升压），再运行 200 会话突发 5 分钟；测试混合比例、09:00 突发及 20 路 PDF 下载按测试门禁执行。校验 P95/P99、错误率、队列、资源水位、Redis/MySQL连接等待、恢复和告警。不得压测 Tushare、腾讯行情、巨潮等公开来源。
5. T2/T4/T6 当前暂缓。若未来恢复演练，再安排 **T5 PDF 多实例/分类阅读** 和 **T7 可执行回滚**；T5 验普通/严重/退市整理 PDF 与真机内打开，T7 验按固定提交重建并切回，不依赖已删除的 287/288/289。

## 环境隔离验收条件

- 测试服务的 MySQL 与 Redis 地址均指向专用测试资源；环境变量名可沿用服务约定，但凭据只由操作者在云托管控制台写入，绝不粘贴到聊天、日志或验收报告。
- 测试服务实例名/服务名明显带 `acceptance` 或 `staging`；生产 URL、生产发布指针和生产 Redis 地址不得出现在测试配置中。
- T2 使用恢复副本，测试服务的数据库账号只对隔离数据库有权限。测试结束后保留报告与哈希，按资源清理流程销毁临时实例/副本。
- 开始故障注入前，由操作者在控制台二次确认目标资源名称；执行前后都记录资源标识，避免误操作生产实例。

## 当前准备状态与所需操作

本机当前没有 Docker/Podman、MySQL 或 Redis 服务端；工作区也没有测试数据库/Redis 连接环境变量。不能据此执行真实 MySQL 恢复、Redis 切主或双实例压力测试。

只有未来重新决定执行 T2/T4/T6 时，才需要在腾讯云准备或确认以下隔离资源，并仅在隔离 CloudRun 服务中录入凭据：

- 可从生产备份恢复出的专用 MySQL 测试实例/副本；单独的测试库和最小权限账号。
- 与生产拓扑相近、允许单独重启/故障切换的专用 Redis 测试实例及账号。
- 独立 CloudRun 测试服务，固定为 2 个实例，配置上面两项测试地址及 mock 行情源；不接生产任务调度或生产数据发布。

资源准备好后，只需告知测试服务 URL、测试 DB/schema 标识、测试 Redis 实例标识和允许的执行窗口；不要发送密码或连接串。未收到隔离资源确认前，不触碰生产环境。
