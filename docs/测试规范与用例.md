# 异动查查测试规范与用例

> 版本：V2.0（2026-10-10）

## 1. 范围与质量门槛

覆盖交易日历、数据源、四类规则、today/next_day 数据集、盘中双向状态、API 契约、公告分类和微信页面验收。不覆盖交易下单、投资收益和第三方平台内部实现。

提交前执行：

```bash
python3 -m unittest discover -s server -p 'test_*.py'
python3 -m unittest discover -s server -p 'test_*.py' -v
python3 server/tools/api_contract_check.py                 # 本地无上游凭证时验证传输契约
python3 server/tools/api_contract_check.py --require-data  # 生产验收要求真实数据
find miniprogram -name '*.js' -print0 | xargs -0 -n1 node --check
python3 -m json.tool miniprogram/app.json >/dev/null
git diff --check
```

微信开发者工具必须 Problems 为 0，单股、重点监控、异动预测可编译；预测页可切换、刷新、点击卡片，不显示行情延迟提示。

## 3. 规则测试

### RULE-001～002：交易日和实际窗口

输入股票与指数不完整自然日序列，断言只使用共同交易日、不补 0。10 日规则输入 1、3、7、10 个有效日，显示对应实际窗口；数据不足返回不可判定。

### RULE-003～005：方向、单股同向和阈值

正向偏离达到阈值时预测卡触发；负向偏离不进入预测页，但单股页保留下跌状态。分别验证四类市场阈值。单股页验证同向次数，预测页不生成同向卡。连续上涨形成多个重叠 3 日窗口时，命中窗口被消费且只计一次；上涨和下跌次数不互相抵消。缺指数时不得计算理论触发价格。

## 4. 预测数据集

### PRED-001～003：三类独立卡

同一股票同时满足 3 日、10 日、30 日规则，断言返回三张卡，`predictionKey` 不同且都包含目标交易日；10 日卡触发不删除 30 日卡。断言不返回 `same_direction_10d`。

### PRED-004：条件稳定

未触发、触发和回落三个阶段均断言 `triggerCondition` 与 `triggerValue` 不改变；不得出现“已达到阈值”或“上涨 ≥”。预测数据集不得返回 `same_direction_10d`。

### DATA-001～004：当日和数据质量

- 当日返回已触发及在单日涨幅上限内可达的未触发候选。
- 计算失败或股票/指数不完整时不发布 `status=ready` 空集。
- 完整计算后真实无候选才允许空列表。
- 同一 `dataset_role + targetTradeDate` 重建覆盖原行，不产生重复。

### DATA-005～010：次日

- 当日触发 `severe_10d`，次日不出现同股票同规则。
- 同股票 `severe_30d` 仍可出现。
- 重点监控 10 日只排除 10 日卡。
- 同向规则不参与预测数据集排除。
- 次日遍历全市场而非当日候选。
- 健康接口返回排除原因数量。

### DATA-011～014：次日可见性边界

- 休息日与交易日 `09:00:00` 前，today 返回上一交易日数据，next_day 返回目标日匹配的已生成数据集，`nextDayAvailable=true`。
- `09:00:00` 切换后，刚才的 next_day 数据转为 today；次日接口不显示已切换的数据。
- `09:00:00` 至盘后新次日集落盘前，next_day 返回空列表及不可用原因，不得返回旧日期卡片。
- 盘后初态数据集以 `nextTradeDate` 为目标日期且 `dataStage=initial` 时可见；正式收盘确认后要求 `dataStage=formal`。

## 5. 时间边界

使用可注入时钟，不读取真实系统时间：

| 用例 | 时间 | 预期 |
| --- | --- | --- |
| TIME-001 | 08:59:59 | 旧 today，禁止实时刷新 |
| TIME-002 | 09:00:00 | next_day 成为 today |
| TIME-003 | 09:14:59 | 新 today，只读 |
| TIME-004 | 09:15:00 | 允许主动刷新 |
| TIME-005 | 14:59:59 | 允许主动刷新 |
| TIME-006 | 15:00:00 | 进入盘后阶段 |
| TIME-007 | 休息日 | 沿用有效数据，不请求行情 |
| TIME-008 | 边界前后 | 不受 30 秒缓存影响 |

## 6. 盘中刷新

股票与指数同时成功且达到阈值，断言 `triggered=true/cardTone=triggered` 和“已触发”。下一次回落断言状态清除但卡片保留。条件字段始终不变。股票行情缺失或指数行情缺失时不重算偏离并返回稳定值。全市场出现新候选时盘中刷新不得新增卡片。

## 7. 行情质量

| 用例 | 条件 | 预期 |
| --- | --- | --- |
| QUOTE-001 | 股票/指数时间相同 | 允许计算 |
| QUOTE-002 | 同一刷新任务中股票或指数缺失 | 不重算偏离，返回稳定值 |
| QUOTE-003 | `current<=0` | 无效报价 |
| QUOTE-004 | 实时源超时 | 稳定数据 + 错误元数据 |
| QUOTE-005 | 初态被正式数据替换 | `formal/confirmed` |

## 8. API 契约脚本

```bash
curl -s 'http://127.0.0.1:8787/api/predictions?scope=today'
curl -s 'http://127.0.0.1:8787/api/predictions?scope=next_day'
curl -s -X POST 'http://127.0.0.1:8787/api/predictions/refresh' \
  -H 'Content-Type: application/json' -d '{"scope":"today"}'
curl -s 'http://127.0.0.1:8787/health'
```

断言外层存在 `code/data/message`；预测返回 `targetTradeDate/baseTradeDate/quoteUpdatedAt/items`；每项存在 `predictionKey/ts_code/ruleKey/deviationLabel/triggerCondition/triggerValue/triggered/cardTone/quoteUpdatedAt`，不得返回 `currentPrice/price`，且 `triggered` 与 `cardTone` 一致；页面时间不是 `updatedAt`；次日未准备时返回 `nextDayAvailable=false` 和原因；非法 scope、非法 JSON 均返回 `40001`，不得返回成功空列表。健康接口必须报告 `intradayState.shared`、TTL 和单键容量。

## 9. 重点监控

普通风险提示必须包含从严认定语义；10 日严重必须同时包含 10 个交易日和约 100% 语义；30 日严重必须同时包含 30 个交易日和约 200% 语义；只有“严重异常波动”而缺少窗口/阈值时不纳入。主源成功时主源决定分类，主源失败时备源接替，两源失败且有旧快照时保留旧数据，结束日当天显示、次日移除。

## 10. 微信开发者工具验收

1. 打开 `miniprogram/`，编译并确认 Problems 为 0。
2. 进入异动预测，确认默认当日；切换次日只切换数据，不出现刷新 loading。
3. 点击刷新，确认按钮 loading、页面不抖动、卡片顺序不变。
4. 检查未触发和已触发卡：条件原文不变化，已触发为浅红背景和胶囊。
5. 确认涨红跌绿、不显示股票价格和实时延迟提示。
6. 进入重点监控，确认筛选行、快照行和首张卡片与预测页对齐。
7. 断网刷新，确认保留旧数据并显示错误状态，不伪装成空列表。
