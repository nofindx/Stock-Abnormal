# 项目文档与目录整理方案

2026-11-22 整理。日常开发只打开 `Projects/Wechat_Applet/Stock-Abnormal`。微信开发者工具继续使用其中的 `miniprogram/`。

| 目录 | 内容 |
| --- | --- |
| `miniprogram/`、`server/` | 当前小程序、后端、构建入口和回归测试。项目根目录的 Dockerfile 用于云托管构建 |
| `docs/` | 现行产品、规则、开发、测试和运维文档。这里仅存放 Markdown 文档 |
| `releases/` | [版本归档](../releases/README.md)，按版本查找上传回执、验收结果、Git 标签和代码快照 |
| `archive/` | [历史资料](../archive/README.md)，按主题或阶段保存过程稿、旧验证、UI 原型和冻结副本 |
| `.local/` | 本机凭据，Git 与容器构建均忽略。生产配置继续由环境变量注入 |

## 以后怎么归档

1. 仍要指导开发或运维的文档，更新在 `docs/`。被替代的方案和阶段报告放到 `archive/`，当前文档只留下入口链接。
2. 复核某个版本必须用到的回执、源码提交和验收结论，集中在 `releases/<版本>/`。冻结标签用于恢复源码，ZIP 用于直接解压，只有需要离线包时才导出。
3. 过程材料按主题或阶段归档。被多个报告引用的证据保留一处，用链接串起来。不同轮次的回执即使内容相同，仍保留各自的归属。
