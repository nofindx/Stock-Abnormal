# 异动查查详细设计

> 版本：V1.1（2026-10-14）
> 对应产品基线：《异动查查小程序 PRD》V3.7
> 定位：面向后端、前端、数据任务、联调、测试和发布的统一开发设计。

## 1. 设计目标与分层

### 1.1 产品范围

系统提供单股计算、重点监控、异动预测三项能力。单股计算和异动预测共用同一套行情规则；重点监控只处理公告事实。系统不提供交易下单、荐股、收益概率、价格目标、历史监控查询或消息推送。

### 1.2 分层原则

```text
数据事实 -> 统一规则 -> 产品过滤 -> 接口适配 -> 页面展示
```

- 数据源层只负责拉取、鉴权、标准化和失败记录。
- 规则层只负责共同交易日、收益率、偏离、普通异动、严重异动和同向次数。
- 产品层负责预测资格、可达距离、同规则排除和公告监管期。
- API 层只负责参数、响应、错误码和字段兼容，不复制计算逻辑。
- 前端只展示后端正式结果；单股 T+N 模拟是唯一允许的本地计算。
- 预测默认只允许 `severe_10d`、`severe_30d`；股票进入 10 日或 30 日严重异动重点监控期后，按候选条件额外允许 `ordinary_3d`、`same_direction_10d`。

## 2. 业务流程

### 2.1 服务启动与基础资料同步

1. 加载规则版本、数据库和数据源配置。
2. 同步交易日历、股票基础资料和股票到所属指数的映射。
3. 同步 `stock_basic(list_status=L)`，更新板块、ST、上市日期、退市整理和价格限制字段。
4. 同步失败不阻塞服务启动，但必须进入 `/health`；基础资料不完整时不得发布 ready 预测集。
5. 启动预测、行情基础数据和公告采集任务；任务锁使用数据库 lease。

### 2.2 统一行情计算

输入为股票日线、所属指数日线、板块规则、行情时间和质量元数据。

1. 按 `trade_date` 取股票和指数交集并升序排列。
2. 不补自然日、不补 0、不混用不同时间点；一方缺失时对应窗口不可判定。
3. 基准指数固定映射：沪市主板 `000001.SH`、深市主板 `399107.SZ`、创业板 `399102.SZ`、科创板 `000688.SH`、北交所 `899050.BJ`。
4. 对 3、10、30 日窗口分别取截至快照日最近共同有效交易日计算复合收益和累计偏离；分别在最多 3、9、29 个共同收益区间内，枚举以当前端点结束的有效区间并取最大上涨偏离，返回实际窗口。历史不足时使用可用区间，只有不存在有效共同收益区间时才返回数据不足：

```text
stockReturn = Π(1 + stockReturn[i]) - 1
indexReturn = Π(1 + indexReturn[i]) - 1
deviation = stockReturn - indexReturn
```

5. 普通异动服务于单股展示和 10 日同向次数；非监管股票不生成普通/同向预测卡，严重异动监管期内才可追加两类短窗口卡。
6. 负向偏离不触发、不进入预测、不升级单股状态。
7. 每项结果必须带实际窗口、收益、偏离、方向、触发状态和质量；数据不足为“不可判定”。

统一规则实现必须被单股详情、全市场预测和盘中刷新共同调用，不得在页面或任务中复制阈值和窗口逻辑。

### 2.3 单股计算与前端模拟

1. 前端搜索股票并请求详情。
2. 后端获取正式计算结果；盘中时股票和所属指数必须在同一批次成功才重算，否则返回稳定结果并标记 fallback。
3. 后端返回行情 `marketStatus/statusReason`、当前有效公告监管 `monitoring`、四项 `warnings`、`alerts`、`dataQuality` 和模拟输入。监管事实和行情触发原因分别表达；两者任一成立时顶部状态不得显示为绿色安全。
4. 前端直接展示正式结果，不用 `calculationInput` 重算状态。
5. 前端以 `simulationBase`、`futureTradeDates`、`simulationThresholds` 计算 T+N；修改某日后只重算该日及后续行，不发网络请求。

### 2.4 重点监控

1. 后台抓取 18.cn 主源和巨潮备源的公告列表及正文。
2. 主源正常时主源决定分类和主链接，主源失败时备源接替；双源失败保留上一份成功快照。
3. 分类基于正文：风险提示需要“从严认定”；10 日需要“严重异常波动”及上涨偏离值累计达到 100% 以上，公告可写 10 个交易日或实际连续 4/6/8 个交易日窗口；30 日需要 30 个交易日及约 +200%/+300% 语义。
4. 3 日普通异动不生成监控记录；三类监控记录监管期均为 10 个有效交易日。
5. 同股同类型重叠记录由最新公告覆盖，同日同类型多来源合并，随后原子发布快照。

### 2.5 盘后预测与阶段切换

1. 15:00 后读取完整活跃股票池、股票和指数正式数据。
2. 校验 ST、上市首日、退市整理、价格限制、停牌尾部和数据完整性。
3. 统一计算后只构造 `severe_10d`、`severe_30d`。
4. 已触发候选保留；未触发候选只有在下一交易日可达距离不超过板块单日上限时保留。
5. `next_day` 排除当前快照已触发任一严重规则的股票，并排除重点监控中的同规则项。
6. 以 `{ts_code}-{ruleKey}-{targetTradeDate}` 生成稳定主键并原子写入。

阶段边界：`09:00` next_day 成为 today，`09:15` 允许主动盘中刷新，`15:00` 进入盘后阶段。盘中刷新只更新已有卡片状态，不新增候选；回落卡片仍保留。

### 2.6 失败恢复

| 场景 | 处理 | 对外状态 |
| --- | --- | --- |
| 股票/指数一方缺失 | 使用稳定结果 | `fallback=true` |
| 正式任务失败 | 保留旧数据集 | `dataUnavailable=true`、`datasetStatus=failed` |
| 无历史成功集 | 不发布空成功 | 数据不可用 |
| 公告双源失败 | 保留旧快照 | `stale=true` |
| 盘中实时请求失败 | 返回稳定结果或错误状态 | 不写入盘中结果 |
| 规则版本变化 | 重建数据集和缓存 | 新旧版本不混用 |

## 3. 接口设计总表

本章集中定义所有对外业务接口、外部数据源接口和内部任务接口；接口字段和错误语义以本章为准。

### 3.1 通用响应与字段

成功：

```json
{"code":0,"data":{},"message":"ok"}
```

失败：

```json
{"code":40001,"data":{"requestId":"..."},"message":"参数错误"}
```

日期为 `YYYY-MM-DD`，内部交易日主键为 `YYYYMMDD`；百分比使用百分数数值，`100.0` 表示 `+100.00%`。`quoteUpdatedAt` 是行情事实时间，`updatedAt` 仅为技术兼容字段。

### 3.2 业务接口清单

| 方法 | 路径 | 用途 | 参数 |
| --- | --- | --- | --- |
| GET | `/api/stocks/search` | 搜索股票 | `q`，1～40 字符 |
| GET | `/api/stocks/detail` | 单股正式结果和模拟输入 | `ts_code` |
| GET | `/api/market/history-coverage` | 只读审计计算数据覆盖 | `offset`、`limit`（可选） |
| GET | `/api/market/calculation-bases` | 直接读取已落盘股票/指数计算基线 | `ts_codes`（逗号分隔，可选）、`offset`、`limit` |
| GET | `/api/market/dataset-status` | 直接读取预测数据集落盘元数据 | 无 |
| GET | `/api/market/jobs` | 直接读取行情计算和预测任务状态 | 无 |
| GET | `/api/monitor` | 当前重点监控 | `status=current`、`type=all\|risk\|severe` |
| GET | `/api/predictions` | 当日/次日预测 | `scope=today\|next_day` |
| POST | `/api/predictions/refresh` | 当日盘中刷新 | `{"scope":"today"}` |
| POST | `/api/quotes/realtime` | 盘中行情批量透传 | `{"ts_codes":["000001.SZ", "399107.SZ"]}`，1～99 个 |
| GET | `/health` | 健康检查 | 无 |
| GET | `/health/ui` | 浏览器可读健康检查页面 | 无 |

### 3.3 计算数据覆盖审计

`GET /api/market/history-coverage?offset=0&limit=100` 只读取 `stock_basic`、`stock_calc_base` 和 `index_calc_base`，不请求或保存日线、实时快照；另用 Tushare `suspend_d` 只读核对停牌日期，不持久化停复牌明细。以指数日期并集的最近日期为参照，要求每只活跃股票有 30 个共同收益点（对应 31 个交易日价格）；返回完整/不完整数量、分类计数和分页异常列表。分类包含缺股票向量、缺指数向量、新上市历史不足、指数历史不足、股票/指数基准错位、停牌造成的历史不足、已确认上游行情缺记录及停牌状态源不可用时的未分类缺口。

收益向量缺日期只能证明该日期无股票收益记录，不能单独区分停牌和上游漏数；该接口必须标为待确认，不可自行归因。`offset` 必须不小于 0，`limit` 范围 1～500；数据库不可用或读取失败返回 `50302`，参数错误返回 `40001`。

`GET /api/market/calculation-bases?ts_codes=600123.SH,000001.SZ&limit=100` 直接读取 `stock_basic`、`stock_calc_base` 和所需的 `index_calc_base`。返回股票基础资料、最新收盘基准、3/10/30 日已计算指标、同向次数及完整收益向量，并在顶层返回所属指数向量；这是数据库落盘数据的只读接口，不请求 Tushare 日线、不读取或保存盘中快照。未传 `ts_codes` 时按活跃股票分页，单次最多 100 只，并返回 `containsRawDaily=false`、`containsIntradaySnapshot=false`。

`GET /api/market/dataset-status` 只返回 `prediction_dataset` 的角色、目标日期、基准日期、数据阶段、完整性、条数、排除统计、规则版本和错误状态，不展开预测卡片。预测卡片仍由 `/api/predictions?scope=today|next_day` 读取。

`GET /api/market/jobs` 只返回 `market_calc_job` 和 `prediction_job` 的任务尝试、成功日期、阶段、状态、重试标记和错误信息，用于发布验收；不触发任务、不修改数据库。

### 3.4 股票搜索

`GET /api/stocks/search?q=平安`

```json
{"items":[{"ts_code":"000001.SZ","symbol":"000001","name":"平安银行","market":"SZSE","board":"主板","isSt":false}]}
```

最多返回 5 条；空查询或超长查询返回 `40001`；无匹配返回成功空数组。

### 3.5 单股详情

`GET /api/stocks/detail?ts_code=000001.SZ`

`data` 至少包含：

```text
ts_code, symbol, name, market, board
currentPrice, change, tradeDate, quoteUpdatedAt
marketStatus, marketStatusClass, statusReason, monitoring
status, statusDisplay, statusClass, statusIcon, warnings[4], alerts[], dataQuality
futureTradeDates, simulationBase, simulationThresholds, calculationInput
```

`warnings` 固定为 3 日偏离、10 日偏离、30 日偏离、10 日同向。正式详情只读本地 MySQL 计算基线；数据库不可用、股票/指数基线缺失、基准日期不一致或不足 30 个共同收益点时返回 `50302`，不得转去 Tushare 日线拼另一套正式结果。`calculationInput` 是前端模拟基础输入；模拟值变化仅在小程序本地计算，不重复请求后端。

模拟输入示例：

```json
{
  "futureTradeDates":["2026-10-13","2026-10-14"],
  "simulationBase":{"stock":[0.5,-1.2],"index":[0.2,-0.4]},
  "simulationThresholds":{"3":{"up":20.0},"10":{"up":100.0},"30":{"up":200.0}},
  "calculationInput":{"stock":[],"index":[],"ordinaryDeviation":20.0,"severe10":{"up":100.0},"severe30":{"up":200.0},"sameDirectionThreshold":4,"ruleVersion":"..."}
}
```

股票不存在返回 `40401`；实时行情不完整仍可返回稳定结果，但必须在 `dataQuality` 标记 fallback。

### 3.6 重点监控

`GET /api/monitor?status=current&type=all`

每项至少包含：`monitorKey`、股票代码和名称、标题、`riskTone`、`monitorType`、`startDate`、`endDate`、`remainingDays`、`monitorPeriod`、`sourceStatus`、`sourceUrl`/`sourceUrls`、数据质量。返回 `items`、`updatedAt`、`stale`、`dataQuality`、`sourceHealth`。

风险提示链接必须为空；严重异动监管期结束后链接不可用。双源失败但有旧快照时返回 200 且 `stale=true`。

### 3.7 预测读取

`GET /api/predictions?scope=today|next_day`

顶层字段至少包含：`scope`、`targetTradeDate`、`baseTradeDate`、`phase`、`todaySourceScope`、`realtimeRefreshAllowed`、`datasetQuoteUpdatedAt`、`quoteUpdatedAt`、`dataStage`、`dataQuality`、`dataUnavailable`、`datasetStatus`、`nextDayAvailable`、`exclusionStats`、`items`。

每张卡至少包含：

```text
predictionKey, ts_code, name, symbol, ruleKey,
predictionWindow, deviationWindow, deviationLabel, deviationPercent,
triggerCondition, triggerValue, triggered, cardTone, alertText,
change, quoteUpdatedAt, targetTradeDate, scope
```

`ruleKey` 只能为 `ordinary_3d`、`same_direction_10d`、`severe_10d` 或 `severe_30d`；普通/同向卡只有对应股票处于 10 日或 30 日严重异动重点监控期时才允许返回，不返回股票价格字段。失败但有旧数据时保留 `items` 并标记不可用；真正无候选才返回 ready 空数组。

### 3.8 盘中行情批量透传

`POST /api/quotes/realtime`

请求体：`{"ts_codes":["000001.SZ","399107.SZ"]}`。代码必须为 `6 位数字 + .SH/.SZ/.BJ`，去重后数量为 1～99。后端按批次访问腾讯行情，缺失时依次回退新浪和东方财富，返回 `quotes`、`requestedCount`、`returnedCount`、`quoteUpdatedAt`、`persisted=false`。只透传本次请求结果，不写入 MySQL、Redis、进程缓存或日志正文。单股和预测页面不直接调用第三方行情源；正式结果由后端统一取数和计算。

### 3.9 预测刷新

`POST /api/predictions/refresh`，请求体 `{"scope":"today"}`。只有 intraday 阶段允许实时请求；只更新已有 `predictionKey`，不扫描新增候选。返回完整列表并保持顺序。盘中结果只存在于本次 HTTP 响应，不写入 MySQL、Redis 或进程缓存；刷新后再次 GET 仍读取稳定数据集。阶段不允许刷新返回 `40901` 或 `refreshStatus=not_allowed`；一方行情缺失返回稳定值和 fallback。

### 3.10 健康检查

`GET /health` 必须报告数据源、当前阶段、today/next_day 数据集、行情水位、完整性、卡片数量、排除统计、规则版本、最近失败，以及：

```text
marketCalc.stockBasicCoverage, predictionMigration
```

同时返回实时源来源级请求统计；不再以 Redis 作为盘中结果存储前提。

`/health` 默认返回机器可读 JSON，供云托管探针、告警脚本和 API contract 使用。`/health/ui` 返回浏览器可读的 HTML 摘要，展示总体状态、数据源、行情数据日期与阶段、当日/次日预测数量、股票池完整性、重点监控和待处理事项；浏览器以 `Accept: text/html` 访问 `/health` 时也返回该摘要，不改变程序请求的 JSON 行为。

### 3.11 外部数据源接口

| 来源 | 内容 | 口径 |
| --- | --- | --- |
| Tushare `stock_basic` | 股票池和资格字段 | `list_status=L` |
| Tushare `trade_cal` | 交易日历 | 不用自然日替代 |
| Tushare `daily` | 股票正式收盘 | 不混入盘中 |
| Tushare `index_daily` | 指数正式收盘 | 与股票按共同日期对齐 |
| 腾讯/新浪/东方财富 | 盘中股票/指数 | 同批次双成功才重算 |
| 18.cn/巨潮 | 公告列表和正文 | 主源/备源切换 |

### 3.12 内部任务接口

内部任务包括基础资料同步、交易日同步、股票/指数基础向量更新、today/next_day 重建、盘中临时刷新、公告采集和监控快照发布。任务记录任务名、目标日期、数据阶段、状态、lease、尝试次数、输入水位、输出数据集和错误信息。

### 3.13 错误码

| 业务码 | HTTP | 含义 |
| ---: | ---: | --- |
| `40001` | 400 | 参数错误 |
| `40401` | 404 | 股票或资源不存在 |
| `40901` | 409 | 当前阶段不允许刷新 |
| `50301` | 503 | 上游数据源不可用 |
| `50302` | 503 | 数据集未准备 |
| `50001` | 500 | 内部错误 |

## 4. 规则与数据模型

### 4.1 规则参数

| 规则 | 单股 | 预测 | 说明 |
| --- | --- | --- | --- |
| `ordinary_3d` | 是 | 否 | 3 日普通异动和同向统计 |
| `severe_10d` | 是 | 是 | 10 日上涨严重异动 |
| `severe_30d` | 是 | 是 | 30 日上涨严重异动 |
| `same_direction_10d` | 是 | 否 | 上涨普通异动次数和状态解释 |

### 4.2 数据表

```sql
stock_calc_base(
  ts_code PRIMARY KEY, as_of_trade_date, latest_close,
  stock_return_vector JSON, data_stage, quote_updated_at, updated_at
)

index_calc_base(
  index_code PRIMARY KEY, as_of_trade_date, latest_close,
  index_return_vector JSON, data_stage, quote_updated_at, updated_at
)

prediction_dataset(
  dataset_role, target_trade_date, base_trade_date,
  data_stage, data_quality, rule_version,
  dataset_quote_updated_at, dataset_quote_as_of,
  dataset_quote_source, dataset_quote_complete,
  item_count, exclusion_stats JSON,
  status, items JSON, updated_at, last_error,
  PRIMARY KEY(dataset_role, target_trade_date)
)

prediction_job(
  job_name PRIMARY KEY, target_trade_date, data_stage,
  status, lease_until, started_at, finished_at,
  attempt, input_watermark, output_dataset_key, last_error
)
```

盘中实时行情和预测刷新结果只在当前请求生命周期内存在；不写入 Redis、MySQL 或进程缓存。

## 5. 前后端实现分工

### 5.1 后端

后端负责数据源、统一规则、资格过滤、预测生成、公告分类、监管期、数据集、失败回退、API 和健康检查。统一计算只在 `server/core/abnormal_rules.py` 与 `MarketService` 中实现。

### 5.2 前端

前端负责搜索、导航、Tab 切换、加载/失败/空态、卡片展示和主动刷新。预测页不得自行筛选或排序卡片；重点监控页不得解析公告正文；单股页不得用接口基础向量重算正式 `status/warnings/alerts`。

### 5.3 T+N 模拟算法

1. 使用 `simulationBase` 作为历史收益序列，使用 `futureTradeDates` 生成未来行。
2. 用户修改一行后，将该行追加到历史序列，按统一规则计算 3/10/30 日偏离：3 日在最近 3 个、10/30 日在最近 9/29 个收益率区间内枚举以当前端点结束的有效区间，取最大上涨偏离，并保留实际区间长度。
3. 3/10/30 日分别和 `simulationThresholds` 上涨阈值比较；安全空间取三项规则中已触发优先、否则剩余空间最小的结果。
4. 只更新当前行及后续依赖行；清空输入后恢复不可判定/空值。
5. 不调用网络，不修改正式状态、预测结果或后端存储。

## 7. 附录：现有实现与部署细节

### A.1 系统边界

```text
微信小程序 -> Python HTTP 服务 -> MySQL / Tushare / 盘中行情 / 公告源
```

前端不调用 Tushare、不保存 Token、不执行全市场循环计算，也不根据展示字符串推断生产规则。后端负责数据源、规则、数据集和状态；单股 T+N 模拟是例外，前端基于接口返回的收益率向量、未来交易日、3/10/30 日阈值和规则版本，按统一窗口枚举规则本地计算，不回写生产结果。

### A.2 数据源适配

| 接口/来源 | 必要参数 | 用途 | 口径 |
| --- | --- | --- | --- |
| `stock_basic` | `list_status=L` | 全市场股票池 | 交易日后台更新 |
| `trade_cal` | `exchange,start_date,end_date` | 交易日和阶段 | 日期 `YYYYMMDD` |
| `daily` | `trade_date` 或日期范围 | 股票正式收盘 | 不混入盘中数据 |
| `index_daily` | `index_code,start_date,end_date` | 指数正式收盘 | 与股票按交易日对齐 |
| 腾讯/新浪/东方财富 | 股票或指数代码 | 盘中临时行情 | 仅主动刷新 |
| 18.cn/巨潮 | 公告列表和详情 | 重点监控 | 主源/备源四态决策 |

请求前检查 Token、权限、日期范围和交易日。空结果要区分非交易日、无数据、未上市、参数错误、权限不足和网络失败。辅助源只交叉核验，不静默覆盖 Tushare 正式结果。

盘中实时行情请求必须在同一刷新任务中同时取得股票和所属指数，收到两边响应后再计算；缺一边或时间不可解析时沿用稳定数据，不混合不同请求批次。

### A.3 阶段状态机

阶段函数输入当前上海时间、交易日历、基础数据日期和数据集状态，输出：

```json
{
  "phase": "pre_open|dataset_open_pending|intraday|post_close_pending|post_close_confirmed|rest_day",
  "targetTradeDate": "20261012",
  "todaySourceScope": "today|next_day",
  "realtimeRefreshAllowed": false
}
```

固定边界：

```text
09:00:00  next_day 成为 today
09:15:00  允许用户主动实时刷新
15:00:00  进入盘后任务阶段
```

预测接口在下一交易日 `09:00:00` 前返回上一交易日的 today 数据，并允许读取已生成且目标日期匹配的 next_day 数据。到 `09:00:00`，该 next_day 数据集成为 today；`09:00:00` 至盘后新数据集落盘期间，次日接口返回不可用状态，不返回错误日期的数据。盘后初态/正式数据集以 `nextTradeDate` 作为次日目标日。

阶段判断不得使用跨越边界的固定缓存。每次请求必须根据当前上海时间和最近边界重新判定。休息日和下一交易日 09:00 前保留上一交易日 today；收盘已触发卡片不得提前清除。

任务锁、失败状态和重试状态使用以下任务表：

`prediction_dataset` 只保存业务结果；任务锁、失败和重试只使用 `prediction_job`。现有 `prediction_cache` 只读兼容，迁移完成后停止使用。

### A.5 后台任务流程

#### A.5.1 15:00 初态

交易日 15:00 后读取全市场股票池、股票行情和所属指数，写入基础向量并标记 `initial/provisional`，随后生成 `today` 和 `next_day`。股票和指数不完整时不得发布 `status=ready` 空数据集。

#### A.5.2 正式收盘

正式 Tushare 数据成功后覆盖基础向量，重算两个数据集并标记 `formal/confirmed`。失败时保留上一份可用数据集，不发布空成功结果。

#### A.5.3 次日计算

次日必须遍历完整 `stock_basic(list_status=L)`，不是复制当日候选。按 `ts_code + ruleKey` 排除当日同规则已触发、重点监控同规则、数据不足、停牌尾部和不可达候选。`exclusion_stats` 记录排除原因。

### A.6 API 设计（历史实现索引）

#### A.6.1 统一响应

```json
{"code":0,"data":{},"message":"ok"}
```

错误响应使用固定 HTTP 状态和 `code/data/message` 外壳：

| 业务码 | HTTP | 含义 |
| ---: | ---: | --- |
| 40001 | 400 | 参数错误 |
| 40401 | 404 | 资源不存在 |
| 40901 | 409 | 当前阶段不允许刷新 |
| 50301 | 503 | 数据源不可用 |
| 50302 | 503 | 数据集未准备 |
| 50001 | 500 | 内部错误 |

预测数据不可用时，读取接口仍返回 HTTP 200 和 `code=0`，`dataUnavailable=true`、`datasetStatus=failed|missing` 和 `error` 供前端在更新时间位置显示“当日数据不可用”。任务失败但上一份数据集存在时，接口保留上一份 `items`，同时将 `datasetStatus` 置为 `failed`，不伪造空成功结果。

#### A.6.2 搜索和单股

`GET /api/stocks/search?q=`：`q` 至少一个字符，最多返回 5 条 `ts_code/symbol/name/market/board/isSt`。

`GET /api/predictions?scope=today|next_day`，默认 `today`。返回：

```json
{
  "scope":"today",
  "targetTradeDate":"20261012",
  "baseTradeDate":"20261009",

  "todaySourceScope":"next_day",
  "realtimeRefreshAllowed":true,
```

#### A.6.5 预测刷新

`POST /api/predictions/refresh`，请求体 `{"scope":"today"}`。只有 `scope=today` 且阶段为 `intraday` 时获取实时行情；其他时段只读数据集。只处理已有 `predictionKey`，返回完整列表并保持顺序。盘中结果只随本次响应返回，不写入任何存储；后续 GET 仍读取稳定数据集。返回 `refreshStatus=applied|not_allowed|fallback`。

`GET /health` 必须报告数据源统计、基础数据日期、当前阶段、两个数据集的目标日期、数据阶段、行情水位、完整性、卡片数量、排除数量、规则版本、最近成功/失败和错误信息，以及 `marketCalc.stockBasicCoverage` 和 `marketCalc.predictionMigration`。`updatedAt` 仅兼容；不要求盘中 Redis 状态。

#### A.10.1 统一行情规则实现

统一规则的输入是股票日线、所属指数日线、板块规则和数据质量元数据。输入必须先按 `trade_date` 取交集并升序排列；不得补自然日、补 0 或把股票和指数不同时间点的数据拼接在一起。

基准指数固定映射为沪市主板 `000001.SH`、深市主板 `399107.SZ`、创业板 `399102.SZ`、科创板 `000688.SH`、北交所 `899050.BJ`。3 日在最近 3 个、10/30 日在最近 9/29 个有效共同收益区间内，枚举以当前端点结束的连续收益区间并选择最大上涨偏离；有效历史不足时，枚举范围上限缩短为实际有效天数。单股、预测和模拟均调用同一计算口径。

```text
stockReturn = Π(1 + stockReturn[i]) - 1
indexReturn = Π(1 + indexReturn[i]) - 1
deviation   = stockReturn - indexReturn
```

百分比字段在接口中统一使用“百分数数值”，例如 `100.0` 表示 `+100.00%`。每个窗口独立返回 `actualWindow`、`stockReturn`、`indexReturn`、`deviation`、`direction`、`triggered` 和 `dataQuality`。

生产异动规则只判定上涨方向：

- 普通异动使用 3 个有效交易日，只服务于单股展示和 10 日同向次数统计。
- 10 日严重异动使用最多 10 个价格日（最多 9 个收益率区间），可生成 `severe_10d` 预测卡。
- 30 日严重异动使用最多 30 个价格日（最多 29 个收益率区间），可生成 `severe_30d` 预测卡。
- 10 日同向异动只统计上涨方向普通异动；重叠窗口消费后只计一次，只服务于单股状态和解释。
- 负向偏离可保留为原始字段，但不得设置生产 `triggered=true`、不得进入预测、不得升级单股状态。

数据不足时返回 `判定状态=不可判定` 和缺失原因；不能用 `triggered=false` 代替数据不足。统一计算层是单股详情、全市场预测和盘中刷新唯一的规则来源。

#### A.10.2 预测生成顺序

后台对每只股票按以下顺序处理，任何一步失败都记录排除原因并继续处理下一只股票：

1. 从完整 `stock_basic(list_status=L)` 读取股票，并校验 ST、上市首日、退市整理、价格限制和目标交易日资格。
2. 根据股票板块映射所属指数，加载股票/指数共同有效收益率向量。
3. 调用统一计算层，先构造 `severe_10d`、`severe_30d` 候选；读取重点监控快照，股票处于 `severe-10d` 或 `severe-30d` 监管期时，再构造 `ordinary_3d`、`same_direction_10d` 候选。
4. 丢弃负向偏离、不可判定、停牌尾部或数据质量不完整的结果。
5. 对已触发项保留卡片；当日按当前交易日待完成涨幅、次日按下一交易日涨幅计算达到上涨阈值所需距离，超过板块单日上限则排除。
6. `next_day` 额外排除当前快照已触发任一严重规则的股票，并排除重点监控中的同规则项；未触发股票的不同规则仍互不影响。
7. 为每项结果生成稳定的 `predictionKey={ts_code}-{ruleKey}-{targetTradeDate}`，再原子写入数据集。

触发距离的未知日必须与预测范围一致：`today` 使用当前窗口内前 N-1 个股票收益，求当前交易日股票涨幅达到阈值所需的涨幅；`next_day` 使用完整 N 个当前股票收益，求下一交易日所需涨幅。指数窗口始终包含当前指数收益。两者均按复合收益反推，不能复用同一组股票窗口。盘中 today 若复用上一交易日的 `next_day` 候选池，仍按展示范围 `today` 计算并将卡片范围返回为“当日”。

健康接口的监控 `itemCount` 按当前日期过滤结束日之前的历史记录，与监控读取接口的有效列表保持一致。

同一股票的 10 日、30 日严重卡分别保留；普通/同向卡仅在严重监管期内保留。读取和盘中刷新必须按当前重点监控快照再次过滤普通/同向卡，防止监管期结束后继续展示。

#### A.10.3 单股详情与 T+N 模拟

单股详情接口返回两类数据：一类是后端正式判定结果，一类是供前端模拟的只读基础输入。前端只能修改未来输入行，不能把模拟结果提交回后端。

```json
{
  "futureTradeDates": ["2026-10-13", "2026-10-14"],
  "simulationBase": {
    "stock": [0.5, -1.2, 2.1],
    "index": [0.2, -0.4, 0.8]
  },
  "simulationThresholds": {
    "3": {"up": 20.0},
    "10": {"up": 100.0},
    "30": {"up": 200.0}
  },
  "calculationInput": {
    "stock": [{"date":"2026-10-09","return":2.1}],
    "index": [{"date":"2026-10-09","return":0.8}],
    "ordinaryDeviation": 20.0,
    "severe10": {"up":100.0},
    "severe30": {"up":200.0},
    "sameDirectionThreshold": 4,
    "ruleVersion": "..."
  }
}
```

前端模拟流程：

1. 以 `simulationBase` 为历史序列，以 `futureTradeDates` 生成未来行。
2. 用户输入某日股票/指数涨幅后，将该行追加到历史序列；3 日在最近 3 个、10/30 日在最近 9/29 个收益率区间内枚举以当前端点结束的有效区间并选择最大上涨偏离。
3. 3 日、10 日和 30 日结果分别与 `simulationThresholds` 的上涨阈值比较；安全空间按三项规则“已触发优先、否则剩余最小”生成。
4. 只更新被编辑行及其后的模拟行，保留用户已填写内容；清空输入时该行及后续依赖结果恢复为不可判定或空值。
5. 该过程不得调用网络、修改 `detail.warnings`、修改 `detail.status` 或改变预测页数据。

后端正式结果仍由 `warnings`、`alerts`、`status` 和 `dataQuality` 提供。前端不得用 `calculationInput` 重算这些字段。

#### A.10.4 重点监控处理

公告任务只由后台执行，页面读取最近一次成功快照。处理顺序为：抓取主源和备源 → 正文语义分类 → 从正文提取异动事实最后交易日 → 生成生效交易日序列 → 同股同类型去重覆盖 → 计算剩余自然日 → 后端去杂 → 原子发布快照。

分类必须使用正文而不是标题猜测：风险提示要求“从严认定”语义；10 日严重异动要求“严重异常波动”及上涨偏离值累计达到 100% 以上，允许公告披露实际连续交易日窗口；30 日严重异动要求 30 个交易日及约 +200%/+300% 阈值语义。监控期均为 10 个有效交易日，3 日普通异动不生成重点监控记录。

同一股票、同一类型、同一公告日的主备源记录合并，主源链接优先；同一股票、同一类型重叠监管期由最新公告覆盖，不延长。正文明确异动最后交易日时，监管从其后首个交易日开始；否则按来源默认生效日计算。监管起止日按交易日序列冻结，页面“剩余 N 天”按上海本地自然日差值展示，结束日当天为 `00`，次日移除。后端统一剔除 5/1 开头标的、ST/*ST 和退市整理期标的，正常 9 开头北交所标的不剔除；前端不得再提供去杂开关。风险提示没有公告入口，严重异动 PDF 只在有效监管期内代理，过期返回 404。

### A.11 API 详细契约（历史补充）

#### A.11.1 单股详情响应

`GET /api/stocks/detail?ts_code=600000.SH` 成功时返回 `code=0`，`data` 至少包含：

```text
ts_code, symbol, name, market, board
currentPrice, change, tradeDate, quoteUpdatedAt
status, statusClass, statusIcon
warnings[4], alerts[], dataQuality
futureTradeDates, simulationBase, calculationInput, simulationThresholds
```

`warnings` 固定四项：`3 日偏离`、`10 日偏离`、`30 日偏离`、`10 日同向`。每项必须带当前值、阈值/次数、展示状态；窗口不足时带不可判定原因。`dataQuality.intraday=true` 只有股票和所属指数盘中行情同时成功时才允许出现。

#### A.11.2 预测卡字段

预测卡必须至少包含：

```text
predictionKey, ts_code, name, symbol, ruleKey
predictionWindow, deviationWindow, deviationLabel, deviationPercent
triggerCondition, triggerValue, triggered, cardTone, alertText
change, quoteUpdatedAt, targetTradeDate, scope
```

`ruleKey` 只能是 `severe_10d` 或 `severe_30d`。不返回 `currentPrice`/`price`；`triggered=true` 时 `cardTone` 必须为 `triggered`，回落后恢复为空字符串但卡片不能删除。`triggerCondition` 和 `triggerValue` 始终保持规则原文，不随触发状态改写。

#### A.11.3 监控响应

`GET /api/monitor?status=current&type=all|risk|severe` 返回 `items`、`updatedAt`、`dataQuality`、`stale`、`sourceHealth`。每项至少包含股票、标题、`riskTone`、`monitorPeriod`、`startDate`、`endDate`、`remainingDays`、`sourceStatus`、`sourceUrl`/`sourceUrls` 和数据质量。风险提示的链接字段必须为空；严重异动过期后不得继续返回链接。

#### A.11.4 状态码与失败语义

| 场景 | HTTP/业务码 | 前端处理 |
| --- | --- | --- |
| 参数缺失或非法 scope | 400 / `40001` | 保留当前页面并提示参数错误 |
| 股票不存在 | 404 / `40401` | 显示股票不存在，不显示正常状态 |
| 当前阶段不允许刷新 | 409 / `40901` | 不发起重试，恢复按钮状态 |
| 上游数据源不可用 | 503 / `50301` | 显示数据不可用，保留已有稳定结果 |
| 数据集尚未准备 | 503 / `50302` | 显示等待数据，不显示空成功 |
| 内部错误 | 500 / `50001` | 显示通用错误并记录 request 日志 |
| 读取接口已有旧数据但新任务失败 | 200 / `code=0`，`dataUnavailable=true` | 保留 `items`，在更新时间处显示失败状态 |

### A.12 前端页面实现约束

#### A.12.1 单股页

进入页面只请求搜索/详情接口一次；刷新由用户主动触发。正式状态、四项预警、监控解释和行情时间直接使用后端字段。详情请求失败时不得用上一次股票的规则结果填充新股票。

模拟表格使用页面本地 state 保存输入值和计算行。输入事件只调用本地 `calculateSimulationRows`，不调用 `getStockDetail`、不刷新行情、不改变页面顶部正式状态。重新选股、刷新或卸载页面时清空模拟输入。

#### A.12.2 预测页

默认加载 `scope=today`，切换 `today/next_day` 只替换已加载数据，不自动刷新行情。手动刷新只调用 `POST /api/predictions/refresh`；前端保留返回列表顺序，不按触发状态过滤或排序。空列表必须结合 `dataUnavailable`、`datasetStatus`、`nextDayAvailable` 判断展示“无候选”还是“数据不可用”。

#### A.12.3 重点监控页

筛选参数只映射到后端 `type`；前端不解析公告标题、不推算起止日期、不决定公告入口。后端已完成去杂，前端只展示接口返回结果，不提供去杂按钮或本地去杂逻辑。`sourceUrl` 为空时隐藏入口，过期或 `stale=true` 时显示快照状态而不是伪造空列表。

### A.13 一致性、缓存与并发

- 规则版本由统一常量维护；规则阈值、窗口或方向口径变更时必须升级 `ruleVersion`，重建 today/next_day 数据集并清理相关盘中态。
- 数据集主键为 `dataset_role + target_trade_date`，写入采用事务/原子替换；同一目标日期不能产生两份可见 ready 数据。
- 盘中行情和刷新结果不写入 Redis、MySQL 或进程缓存；POST 响应结束后不保留盘中状态。
- 后台任务使用数据库任务锁和 lease；实例重启后由 lease 超时恢复，不能依赖进程内锁保证唯一执行。
- 单股详情的股票和指数实时请求必须属于同一刷新批次；一方缺失时返回最近正式结果并标注 fallback。
- API 返回的 `quoteUpdatedAt` 是行情数据时间；`updatedAt` 仅为技术兼容字段，不能作为页面行情时间。

### A.15 发布前检查清单

1. `ruleVersion`、预测数据集和接口契约允许四类上涨规则，但普通/同向卡必须受 10 日或 30 日重点监控资格控制。
2. `stockBasicCoverage.complete=true`，预测排除项有统计，不把数据失败写成空成功。
3. 单股详情能返回模拟基础输入；编辑模拟行不产生网络请求，正式状态不变化。
4. 行情透传接口对 1～99 个代码校验、去重，明确返回 `persisted=false`。
5. 预测刷新响应直接更新页面；后续 GET 仍返回稳定数据集，刷新结果不进入 MySQL、Redis 或进程缓存。
6. 当日和次日预测切换不刷新行情；盘中刷新只更新已有卡片状态。
7. 重点监控主源/备源切换、结束日可见性和严重异动公告入口已验证。
8. 微信开发者工具 Problems 为 0，并完成单股、重点监控、预测和断网验收。

### A.16 变更管理

任何规则、字段或页面行为变更都必须同时更新：PRD、本文档、统一规则实现、API 契约脚本、测试夹具和验收用例。涉及窗口、阈值、方向、预测卡范围或监管期的变更，不允许只修改前端文案；必须升级 `ruleVersion` 并重建受影响数据集。
