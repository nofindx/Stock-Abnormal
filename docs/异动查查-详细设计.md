# 异动查查详细设计

> 版本：V1.3（2026-10-17）
> 对应产品基线：《异动查查小程序 PRD》V3.9
> 定位：面向后端、前端、数据任务、联调、测试和发布的统一开发设计。

## 1. 设计目标与分层

### 1.1 产品范围

系统提供单股计算、重点监控、异动预测三项能力。单股计算和异动预测共用同一套行情规则；重点监控只处理公告事实。系统不提供交易下单、荐股、收益概率、价格目标、历史监控查询或消息推送。

### 1.2 分层原则

```text
数据事实 -> 统一规则 -> 产品过滤 -> 接口适配 -> 页面展示
```

- 数据源层只负责拉取、鉴权、标准化和失败记录。
- 规则层只负责共同交易日、收益率、偏离、普通异动、严重异动和同向次数。
- 产品层负责预测资格、可达距离、同规则排除和公告监管期。
- API 层只负责参数、响应、错误码和字段兼容，不复制计算逻辑。
- 前端只展示后端正式结果；单股 T+N 模拟是唯一允许的本地计算。
- 预测默认只允许 `severe_10d`、`severe_30d`；股票进入 10 日或 30 日严重异动重点监控期且没有独立普通风险提示事实后，按候选条件额外允许 `ordinary_3d`。`same_direction_10d` 只用于单股状态和解释，不生成预测卡片。

## 2. 业务流程

### 2.1 服务启动与基础资料同步

1. 加载规则版本、数据库和数据源配置。
2. 同步交易日历、股票基础资料和股票到所属指数的映射。
3. 同步 `stock_basic(list_status=L)`，更新板块、ST、上市日期、退市整理和价格限制字段。
4. 同步失败不阻塞服务启动，但必须进入 `/health`；基础资料不完整时不得发布 ready 预测集。
5. 启动预测、行情基础数据和公告采集任务；任务锁使用数据库 lease。

### 2.2 统一行情计算

输入为股票日线、所属指数日线、板块规则、行情时间和质量元数据。

1. 按 `trade_date` 取股票和指数交集并升序排列。
2. 不补自然日、不补 0、不混用不同时间点；一方缺失时对应窗口不可判定。
3. 基准指数固定映射：沪市主板 `000001.SH`、深市主板 `399107.SZ`、创业板 `399102.SZ`、科创板 `000688.SH`、北交所 `899050.BJ`。
4. 对 3、10、30 日窗口分别取最近最多 3、10、30 个共同收益区间；仅枚举以最新共同交易日为终点的连续有效子区间，单股同时保留最大上涨偏离和最小下跌偏离。预测只筛选上涨方向。触发距离则在可延伸到目标交易日的上涨区间中反推最小所需涨幅：

```text
stockReturn = Π(1 + stockReturn[i]) - 1
indexReturn = Π(1 + indexReturn[i]) - 1
deviation = stockReturn - indexReturn
```

5. 普通异动服务于单股展示和 10 日同向次数；非监管股票不生成普通预测卡，严重异动监管期且没有独立普通风险提示事实时才可追加普通短窗口卡。同向次数只服务于单股状态和解释。
6. 单股按板块规则判断上涨和下跌阈值及同向次数；预测资格只保留上涨方向。
7. 每项结果必须带实际窗口、收益、偏离、方向、触发状态和质量；数据不足为“不可判定”。

统一规则实现必须被单股详情、全市场预测和盘中刷新共同调用，不得在页面或任务中复制阈值和窗口逻辑。

### 2.3 单股计算与前端模拟

1. 前端搜索股票并请求详情。
2. 后端获取正式计算结果；盘中时股票和所属指数必须在同一批次成功才重算，否则返回稳定结果并标记 fallback。
3. 后端返回行情 `marketStatus/statusReason`、当前有效公告监管 `monitoring`、四项 `warnings`、`alerts`、`nextDayForecast`、`dataQuality` 和模拟输入。监管事实、当日行情与次日候选分别表达；当前监管、当日行情触发或次日有候选时，顶部显示红底风险状态，全部均无时显示浅绿安全状态。
4. 前端直接展示正式结果，不用 `calculationInput` 重算状态。
5. 前端以 `simulationBase`、`futureTradeDates`、`simulationThresholds` 计算 T+N；修改某日后只重算该日及后续行，不发网络请求。

### 2.4 重点监控

1. 后台抓取 18.cn、巨潮资讯和中泰证券业务公告的列表及正文；中泰栏目 ID 为 `3465`。
2. 各公告源独立采集；18.cn 与中泰提供券商公告，巨潮资讯为发行人备源。所有源失败保留上一份成功快照。
3. 分类基于正文：风险提示需要“从严认定”；10 日需要“严重异常波动”及上涨/下跌偏离阈值，或正文明确连续窗口内达到板块同向异常波动次数（主板 4 次、创业板/科创板/北交所 3 次）的认定条件，公告可写 10 个交易日或实际连续交易日窗口；30 日需要 30 个交易日及约 +200%/+300% 语义。
4. 3 日普通异动不生成监控记录；风险提示、10 日和 30 日严重异动按 10 个有效交易日计算监管期。退市整理记录单独显示“退市倒计时”，周期取公告正文确认的进入日和预计最后交易日。
5. 同股同类型重叠记录由最新公告覆盖，同日同类型多来源合并，随后原子发布快照。

### 2.5 盘后预测与阶段切换

1. 15:00 后读取完整活跃股票池、股票和指数正式数据。
2. 校验 ST、上市首日、退市整理、价格限制、停牌尾部和数据完整性。
3. 统一计算后只构造 `severe_10d`、`severe_30d`。
4. 已触发候选保留；未触发候选只有在下一交易日可达距离不超过板块单日上限时保留。
5. `next_day` 排除当前快照已触发任一严重规则的股票，并排除重点监控中的同规则项。
6. 以 `{ts_code}-{ruleKey}-{targetTradeDate}` 生成稳定主键并原子写入。

阶段边界：`09:00` 前保留上一交易日结果；`09:00` 当前目标日的 `next_day` 候选集成为 today，`09:15` 允许主动盘中刷新，`15:00` 进入盘后阶段。盘中刷新只更新已有卡片状态，不新增候选；回落卡片仍保留。盘后归档 today 时沿用此前以目标日前一交易日为基准生成的 `next_day` 候选身份（股票 + 规则），但价格、涨幅、实际偏离窗口、偏离值、触发状态和触发距离必须以每张候选股票及其所属指数的目标日落盘向量重新计算；不得重新扫描全市场并改变候选名单。缺少完整前序候选集、任一候选股票/指数目标日基线时标记数据不可用，禁止用前一日字段回退展示。非候选股票停牌或缺行情不应清空有效候选集，但必须由历史覆盖接口和健康检查明确报告。

### 2.6 失败恢复

| 场景 | 处理 | 对外状态 |
| --- | --- | --- |
| 股票/指数一方缺失 | 使用稳定结果 | `fallback=true` |
| 正式任务失败 | 保留旧数据集 | `dataUnavailable=true`、`datasetStatus=failed` |
| 无历史成功集 | 不发布空成功 | 数据不可用 |
| 公告源全部失败 | 保留旧快照 | `stale=true` |
| 盘中实时请求失败 | 返回稳定结果或错误状态 | 不写入盘中结果 |
| 规则版本变化 | 重建数据集和缓存 | 新旧版本不混用 |

## 3. 接口设计总表

本章集中定义所有对外业务接口、外部数据源接口和内部任务接口；接口字段和错误语义以本章为准。

### 3.1 通用响应与字段

成功：

```json
{"code":0,"data":{},"message":"ok"}
```

失败：

```json
{"code":40001,"data":{"requestId":"..."},"message":"参数错误"}
```

日期为 `YYYY-MM-DD`，内部交易日主键为 `YYYYMMDD`；百分比使用百分数数值，`100.0` 表示 `+100.00%`。`quoteUpdatedAt` 是行情事实时间，`updatedAt` 仅为技术兼容字段。

### 3.2 业务接口清单

| 方法 | 路径 | 用途 | 参数 |
| --- | --- | --- | --- |
| GET | `/api/stocks/search` | 搜索股票 | `q`，1～40 字符 |
| GET | `/api/stocks/detail` | 单股正式结果和模拟输入 | `ts_code` |
| GET | `/api/market/history-coverage` | 只读审计计算数据覆盖 | `offset`、`limit`（可选） |
| GET | `/api/market/calculation-bases` | 直接读取已落盘股票/指数计算基线 | `ts_codes`（逗号分隔，可选）、`offset`、`limit` |
| GET | `/api/market/dataset-status` | 直接读取预测数据集落盘元数据 | 无 |
| GET | `/api/market/jobs` | 直接读取行情计算和预测任务状态 | 无 |
| GET | `/api/monitor` | 当前重点监控 | `status=current`、`type=all\|risk\|delisting\|severe` |
| GET | `/api/predictions` | 当日/次日预测 | `scope=today\|next_day` |
| POST | `/api/predictions/refresh` | 当日盘中刷新 | `{"scope":"today"}` |
| POST | `/api/quotes/realtime` | 盘中行情批量透传 | `{"ts_codes":["000001.SZ", "399107.SZ"]}`，1～99 个 |
| GET | `/health` | 健康检查 | 无 |
| GET | `/health/ui` | 浏览器可读健康检查页面 | 无 |

### 3.3 计算数据覆盖审计

`GET /api/market/history-coverage?offset=0&limit=100` 只读取 `stock_basic`、`stock_calc_base` 和 `index_calc_base`，不请求或保存日线、实时快照；另用 Tushare `suspend_d` 只读核对停牌日期，不持久化停复牌明细。以指数日期并集的最近日期为参照，要求每只活跃股票有 30 个共同收益点（对应 31 个交易日价格）；返回完整/不完整数量、分类计数和分页异常列表。分类包含缺股票向量、缺指数向量、新上市历史不足、指数历史不足、股票/指数基准错位、停牌造成的历史不足、已确认上游行情缺记录及停牌状态源不可用时的未分类缺口。

收益向量缺日期只能证明该日期无股票收益记录，不能单独区分停牌和上游漏数；该接口必须标为待确认，不可自行归因。`offset` 必须不小于 0，`limit` 范围 1～500；数据库不可用或读取失败返回 `50302`，参数错误返回 `40001`。

`GET /api/market/calculation-bases?ts_codes=600123.SH,000001.SZ&limit=100` 直接读取 `stock_basic`、`stock_calc_base` 和所需的 `index_calc_base`。返回股票基础资料、最新收盘基准、3/10/30 日已计算指标、同向次数及完整收益向量，并在顶层返回所属指数向量；这是数据库落盘数据的只读接口，不请求 Tushare 日线、不读取或保存盘中快照。未传 `ts_codes` 时按活跃股票分页，单次最多 100 只，并返回 `containsRawDaily=false`、`containsIntradaySnapshot=false`。

`GET /api/market/dataset-status` 只返回 `prediction_dataset` 的角色、目标日期、基准日期、数据阶段、完整性、条数、排除统计、规则版本和错误状态，不展开预测卡片。预测卡片仍由 `/api/predictions?scope=today|next_day` 读取。

`GET /api/market/jobs` 只返回 `market_calc_job` 和 `prediction_job` 的任务尝试、成功日期、阶段、状态、重试标记和错误信息，用于发布验收；不触发任务、不修改数据库。

### 3.4 股票搜索

`GET /api/stocks/search?q=平安`

```json
{"items":[{"ts_code":"000001.SZ","symbol":"000001","name":"平安银行","market":"SZSE","board":"主板","isSt":false}]}
```

最多返回 5 条；空查询或超长查询返回 `40001`；无匹配返回成功空数组。

### 3.5 单股详情

`GET /api/stocks/detail?ts_code=000001.SZ`

`data` 至少包含：

```text
ts_code, symbol, name, market, board
currentPrice, change, tradeDate, quoteUpdatedAt
marketStatus, marketStatusClass, statusReason, monitoring
monitoringStatus, monitoringStatusDisplay
status, statusDisplay, statusClass, statusIcon, warnings[4], alerts[], dataQuality
futureTradeDates, simulationBase, simulationThresholds, calculationInput
```

`warnings` 固定顺序为 3 日偏离、10 日同向、10 日偏离、30 日偏离，与单股详情四宫格布局一致。偏离项同时返回上涨最大偏离、下跌最小偏离、两侧阈值和触发状态；同向项区分上涨和下跌次数。正式详情只读本地 MySQL 计算基线；数据库不可用、股票或指数基线缺失、任一侧向量与自身基准日期不一致，或双方均有向量但没有共同日期时返回 `50302`，不得转去 Tushare 日线拼另一套正式结果。股票停牌、刚上市或上游缺记录造成两侧基准日期不同但仍有共同日期时，按共同日期对齐并返回已有有效窗口；刚上市首个交易日一侧合法为空时也返回详情，前三项显示暂无有效窗口。`dataQuality.commonDays` 标记覆盖范围；`calculationInput` 是前端模拟基础输入，模拟值变化仅在小程序本地计算，不重复请求后端。

模拟输入示例：

```json
{
  "futureTradeDates":["2026-10-13","2026-10-14"],
  "simulationBase":{"stock":[0.5,-1.2],"index":[0.2,-0.4]},
  "simulationThresholds":{"3":{"up":20.0,"down":-20.0},"10":{"up":100.0,"down":-50.0},"30":{"up":200.0,"down":-70.0}},
  "calculationInput":{"stock":[],"index":[],"ordinaryDeviation":20.0,"severe10":{"up":100.0},"severe30":{"up":200.0},"sameDirectionThreshold":4,"ruleVersion":"..."},
  "dataQuality":{"commonDays":30,"requiredCommonDays":30,"ruleResetDate":""}
}
```

股票不存在返回 `40401`；实时行情不完整仍可返回稳定结果，但必须在 `dataQuality` 标记 fallback。

`simulationThresholds.3` 为兼容正式详情和旧客户端保留的完整规则字段；当前模拟表只消费 `10` 和 `30` 两个字段，3 日规则仅由顶部正式预警卡片展示和判定。后端暂不删除该字段，避免接口版本分叉。

### 3.6 重点监控

`GET /api/monitor?status=current&type=all`

每项至少包含：`monitorKey`、股票代码和名称、标题、`riskTone`、`monitorType`、`eventDirection`、`startDate`、`endDate`、`remainingDays`、`monitorPeriod`、`sourceStatus`、`sourceUrl`/`sourceUrls`、`sourceRelation`、数据质量。`eventDirection` 是依据严重异动公告正文“涨幅/跌幅偏离”提取的本轮事实方向（`up`/`down`/空）；不得用最新单日行情代替。`sourceRelation` 可为 `severe-primary`、`ordinary-independent`、`severe-supporting` 或 `delisting-independent`；佐证来源使用 `supportingFacts`/`supportingSourceUrls` 返回，不得混入主来源列表。所有 `type` 均返回对应分类下的全部有效监管事实，包括页面会去杂隐藏的股票；可附最新落盘股票日收益 `marketChange` 和日期 `marketChangeDate` 供行情参考，但不得作为严重异动方向过滤字段。上涨型严重异动即使最新单日收益为负仍展示；明确为下跌型的严重异动仅在前端隐藏。风险提示不受涨跌影响，也不请求实时源。去杂只在小程序展示层执行。返回 `items`、`updatedAt`、`stale`、`dataQuality`、`sourceHealth`。

普通风险提示链接必须为空；退市整理风险警示使用 `riskTone=delisting-warning` 且显示“退市倒计时”；严重异动监管期结束后链接不可用。全部公告源失败但有旧快照时返回 200 且 `stale=true`。

### 3.7 预测读取

`GET /api/predictions?scope=today|next_day`

顶层字段至少包含：`scope`、`targetTradeDate`、`baseTradeDate`、`phase`、`todaySourceScope`、`realtimeRefreshAllowed`、`datasetQuoteUpdatedAt`、`quoteUpdatedAt`、`dataStage`、`dataQuality`、`dataUnavailable`、`datasetStatus`、`nextDayAvailable`、`exclusionStats`、`items`。

每张卡至少包含：

```text
predictionKey, ts_code, name, symbol, ruleKey,
predictionWindow, deviationWindow, deviationLabel, deviationPercent,
triggerCondition, triggerValue, triggered, cardTone, alertText,
change, quoteUpdatedAt, targetTradeDate, scope
```

`ruleKey` 只能为 `ordinary_3d`、`severe_10d` 或 `severe_30d`；普通卡只有对应股票处于 10 日或 30 日严重异动重点监控期时才允许返回，不返回股票价格字段。同向次数不在预测接口返回。失败但有旧数据时保留 `items` 并标记不可用；真正无候选才返回 ready 空数组。

### 3.8 盘中行情批量透传

`POST /api/quotes/realtime`

请求体：`{"ts_codes":["000001.SZ","399107.SZ"]}`。代码必须为 `6 位数字 + .SH/.SZ/.BJ`，去重后数量为 1～99。后端按批次访问腾讯行情，缺失时依次回退新浪和东方财富，返回 `quotes`、`requestedCount`、`returnedCount`、`quoteUpdatedAt`、`persisted=false`。只透传本次请求结果，不写入 MySQL、Redis、进程缓存或日志正文。单股和预测页面不直接调用第三方行情源；正式结果由后端统一取数和计算。

### 3.9 预测刷新

`POST /api/predictions/refresh`，请求体 `{"scope":"today"}`。只有 intraday 阶段允许实时请求；只更新已有 `predictionKey`，不扫描新增候选。返回完整列表并保持顺序。盘中结果只存在于本次 HTTP 响应，不写入 MySQL、Redis 或进程缓存；刷新后再次 GET 仍读取稳定数据集。阶段不允许刷新返回 `40901` 或 `refreshStatus=not_allowed`；一方行情缺失返回稳定值和 fallback。

### 3.10 健康检查

`GET /health` 必须报告数据源、当前阶段、today/next_day 数据集、行情水位、完整性、卡片数量、排除统计、规则版本、最近失败，以及：

```text
marketCalc.stockBasicCoverage, predictionMigration
```

同时返回实时源来源级请求统计；不再以 Redis 作为盘中结果存储前提。

`/health` 默认返回机器可读 JSON，供云托管探针、告警脚本和 API contract 使用。`/health/ui` 返回浏览器可读的 HTML 摘要，展示总体状态、数据源、行情数据日期与阶段、当日/次日预测数量、股票池完整性、重点监控和待处理事项；浏览器以 `Accept: text/html` 访问 `/health` 时也返回该摘要，不改变程序请求的 JSON 行为。

### 3.11 外部数据源接口

| 来源 | 内容 | 口径 |
| --- | --- | --- |
| Tushare `stock_basic` | 股票池和资格字段 | `list_status=L` |

### 5.3 T+N 模拟算法

1. 使用 `simulationBase` 作为历史收益序列，使用 `futureTradeDates` 生成未来行。
2. 用户修改一行后，将该行追加到历史序列，按统一规则计算 10/30 日偏离：在各自最近最多 10/30 个收益率区间内，只枚举以当前模拟日为终点的连续子区间，分别取最大上涨偏离、最小下跌偏离，并保留两者实际区间和长度。3 日偏离仅在单股顶部正式预警中计算。
3. 模拟表只对 10/30 日比较 `simulationThresholds` 的上涨和下跌阈值；3 日偏离仅属于单股顶部正式预警，不进入模拟表。任一 10/30 日方向/窗口触发，安全空间显示“已触发”，否则显示距最近阈值的空间。
4. 只更新当前行及后续依赖行；输入框清空后保持空白展示，但该空值按 `0%` 参与当前行及后续行计算。
5. 不调用网络，不修改正式状态、预测结果或后端存储。

### A.3 阶段状态机

阶段函数输入当前上海时间、交易日历、基础数据日期和数据集状态，输出：

```json
{
  "phase": "pre_open|dataset_open_pending|intraday|post_close_pending|post_close_confirmed|rest_day",
  "targetTradeDate": "20261012",
  "todaySourceScope": "today|next_day",
  "realtimeRefreshAllowed": false
}
```

固定边界：

```text
09:00:00  next_day 成为 today
09:15:00  允许用户主动实时刷新
15:00:00  进入盘后任务阶段
```

预测接口在下一交易日 `09:00:00` 前返回上一交易日的 today 数据，并允许读取已生成且目标日期匹配的 next_day 数据。到 `09:00:00`，该 next_day 数据集成为 today；`09:00:00` 至盘后新数据集落盘期间，次日接口返回不可用状态，不返回错误日期的数据。盘后初态/正式数据集以 `nextTradeDate` 作为次日目标日；归档为 today 时保留此前 next_day 的候选身份，但必须使用目标日同日收盘向量重算行情和规则字段，不能整张复制前一日卡片。

阶段判断不得使用跨越边界的固定缓存。每次请求必须根据当前上海时间和最近边界重新判定。休息日和下一交易日 09:00 前保留上一交易日 today；收盘已触发卡片不得提前清除。

### A.5 后台任务流程

#### A.5.1 15:00 初态

交易日 15:00 后读取全市场股票池、股票行情和所属指数，写入基础向量并标记 `initial/provisional`，随后从前一交易日已生成的目标日 `next_day` 集取得候选身份，以目标日股票/指数基线重算当日卡片，再按当前收盘基线生成下一交易日 `next_day`。today 源集必须目标日期相同、基准日早于目标日且 `status=ready/datasetQuoteComplete=true`；任一候选股票或其所属指数目标日基线缺失/日期不一致时 today 必须标记不可用且不得回退旧行情。非候选停牌股票不阻止有效候选归档，全市场缺口仍应报告在覆盖审计中。股票和指数完整但候选列表为空时可以发布有效空数据集，不得把计算失败伪装为空结果。

#### A.5.2 正式收盘

正式 Tushare 数据成功后覆盖基础向量，today 保留目标日原有的前序候选身份、并按正式目标日基线重算全部行情和计算字段；next_day 按最新正式收盘基线重算并标记 `formal/confirmed`。失败时保留上一份可用数据集，不发布空成功结果。

#### A.5.3 次日计算

次日必须遍历完整 `stock_basic(list_status=L)`，不是复制当日候选。按 `ts_code + ruleKey` 排除当日同规则已触发、重点监控同规则、数据不足、停牌尾部和不可达候选。`exclusion_stats` 记录排除原因。

`GET /api/predictions?scope=today|next_day`，默认 `today`。返回：

  "baseTradeDate":"20261009",

#### A.6.5 预测刷新

`POST /api/predictions/refresh`，请求体 `{"scope":"today"}`。只有 `scope=today` 且阶段为 `intraday` 时获取实时行情；其他时段只读数据集。只处理已有 `predictionKey`，返回完整列表并保持顺序。盘中结果只随本次响应返回，不写入任何存储；后续 GET 仍读取稳定数据集。返回 `refreshStatus=applied|not_allowed|fallback`。

#### A.6.6 健康检查

`GET /health` 必须报告数据源统计、基础数据日期、当前阶段、两个数据集的目标日期、数据阶段、行情水位、完整性、卡片数量、排除数量、规则版本、最近成功/失败和错误信息，以及 `marketCalc.stockBasicCoverage` 和 `marketCalc.predictionMigration`。预测健康状态必须按公开接口实际使用的数据集计算：盘中 `today` 使用当前 `next_day` 候选集作为实时刷新基线，交易时段的 `next_day` 标记为阶段性不可用，不得仅因持久化更新时间超过 36 小时误报过期。`updatedAt` 仅兼容；不要求盘中 Redis 状态。

#### A.10.1 统一行情规则实现

统一规则的输入是股票日线、所属指数日线、板块规则和数据质量元数据。输入必须先按 `trade_date` 取交集并升序排列；不得补自然日、补 0 或把股票和指数不同时间点的数据拼接在一起。

公告重置按规则窗口隔离：10 日严重异动只重置 3 日、10 日偏离，独立的 30 日累计继续滚动；10 日同向统计始终按最近 10 个共同有效交易日独立计算，不随偏离公告重置。30 日严重异动才重置 3/10/30 日偏离；同向统计仍按其独立的最近 10 个共同有效交易日计算。模拟接口需按窗口返回重置后的基线，以保证前端本地 T+N 重算与后端一致。

基准指数固定映射为沪市主板 `000001.SH`、深市主板 `399107.SZ`、创业板 `399102.SZ`、科创板 `000688.SH`、北交所 `899050.BJ`。单股正式结果和预测按 3/10/30 日规则计算；模拟表只在最近最多 10/30 个有效共同收益区间内，枚举以模拟日为终点的连续子区间，分别选择最大上涨和最小下跌偏离。已结束的历史区间不能作为当前偏离。有效历史不足时，枚举范围上限缩短为实际有效天数。N 个收益区间需要 N+1 个价格点，首点为该区间起始交易日前收盘基准。单股正式结果、预测和模拟使用同一偏离计算口径，模拟展示范围仅保留 10/30 日。

交易所正文中的严重异动公告用于确定规则重置。正文明确本轮异常交易区间截至日时，从截至日之后首个交易日的收益区间开始累计；未明确截至日时，取公告后监管交易日序列的第二个有效交易日。公告前收益不再参与当前 3/10/30 日计算。若同日主监控记录由 18.cn 提供，合并流程必须保留发行人/交易所正文确认的 `ruleResetConfirmed` 和 `ruleResetDate`；未经正文确认的 18.cn 风险提示只作为监管事实，不重置行情累计。重置后未满完整窗口时仍按现有共同收益区间枚举最大上涨偏离，并返回实际窗口；只有没有任何有效共同收益区间时才标记不可判定。

```text
stockReturn = Π(1 + stockReturn[i]) - 1
indexReturn = Π(1 + indexReturn[i]) - 1
deviation   = stockReturn - indexReturn
```

百分比字段在接口中统一使用“百分数数值”，例如 `100.0` 表示 `+100.00%`。每个窗口独立返回 `actualWindow`、`stockReturn`、`indexReturn`、`deviation`、`direction`、`triggered` 和 `dataQuality`。

预测生产候选只判定上涨方向；单股规则状态同时覆盖对应板块的上涨和下跌阈值：

- 普通异动使用 3 个有效交易日，只服务于单股展示和 10 日同向次数统计。
- 10 日严重异动使用最近最多 10 个共同日收益区间，可生成 `severe_10d` 预测卡。
- 30 日严重异动使用最近最多 30 个共同日收益区间，可生成 `severe_30d` 预测卡。
- 10 日同向异动按最近 10 个共同有效交易日、上涨/下跌方向分别统计普通异动；共享至少一个收益区间的同方向重叠窗口只计一次，仅共用边界收盘日的相邻事件分别计数。偏离公告重置和停牌缺口不清空该滚动统计。预测不生成同向次数卡。
- 窗口内最大子区间和公告后重置属于产品计算口径，不代表交易所最终认定；10 日、30 日及同向条件作为独立认定条件展示，重点监控中的正式监管事实必须来自公告。
- 交易所正式规则的“连续 N 个交易日”以首日之前的前收盘价为起点，构成 N 个日收益区间。产品在最近 N 个共同收益区间中选最大子区间，只用于候选预警；单股/预测文案不得宣称其为交易所已认定的异常波动。10 日同向次数单独按最近 10 个共同有效交易日中的 3 日普通异动事件计数，不随偏离公告重置，也不因停牌缺口清零。沪深规则版本和北交所 2026-10-16 实施公告需持续按交易所原文维护规则版本。
- 单股负向偏离达到板块下跌阈值时按规则设置 `triggered=true` 并升级单股状态；预测页不把该负向结果筛选为候选。重点监控仍按公告事实完整采集，不能因预测方向规则删除监管记录。

数据不足时返回 `判定状态=不可判定` 和缺失原因；不能用 `triggered=false` 代替数据不足。统一计算层是单股详情、全市场预测和盘中刷新唯一的规则来源。

#### A.10.2 预测生成顺序

后台对每只股票按以下顺序处理，任何一步失败都记录排除原因并继续处理下一只股票：

1. 从完整 `stock_basic(list_status=L)` 读取股票，并校验 ST、上市首日、退市整理、价格限制和目标交易日资格。
2. 根据股票板块映射所属指数，加载股票/指数共同有效收益率向量。
3. 调用统一计算层，先构造 `severe_10d`、`severe_30d` 候选；读取重点监控快照，股票处于 `severe-10d` 或 `severe-30d` 监管期时，再构造 `ordinary_3d` 候选。
4. 丢弃负向偏离、不可判定、停牌尾部或数据质量不完整的结果。
5. 对已触发项保留卡片；当日按当前交易日待完成涨幅、次日按下一交易日涨幅计算达到上涨阈值所需距离，超过板块单日上限则排除。
6. `next_day` 额外排除当前快照已触发任一严重规则的股票，并排除重点监控中的同规则项；未触发股票的不同规则仍互不影响。
7. 为每项结果生成稳定的 `predictionKey={ts_code}-{ruleKey}-{targetTradeDate}`，再原子写入数据集。

触发距离的未知日必须与预测范围一致：对于 N 日规则，`today` 最多使用 N-1 个已知股票收益，并将目标交易日指数收益纳入指数区间，反推目标日股票涨幅；历史向量更长时也不得多取一个已知股票收益。`next_day` 使用符合该规则回看范围的当前股票/指数收益，反推下一交易日所需涨幅。因当日股票收益未知而指数收益已知，两边的日期区间长度相差一天；切片必须分别构造，不能共用同一组窗口。两者均按复合收益反推。盘中 today 若复用上一交易日的 `next_day` 候选池，仍按展示范围 `today` 计算并将卡片范围返回为“当日”。

健康接口的监控 `itemCount` 是全部当前有效监管事实数（包含小程序展示层会去杂隐藏的股票）；接口不报告前端筛选后的可见条数。

同一股票的 10 日、30 日严重卡分别保留；普通卡仅在严重监管期内保留。同向次数不生成预测卡。读取和盘中刷新必须按当前重点监控快照再次过滤普通卡，防止监管期结束后继续展示。

#### A.10.3 单股详情与 T+N 模拟

单股详情接口返回两类数据：一类是后端正式判定结果，一类是供前端模拟的只读基础输入。前端只能修改未来输入行，不能把模拟结果提交回后端。

```json
{
  "futureTradeDates": ["2026-10-13", "2026-10-14"],
  "simulationBase": {
    "stock": [0.5, -1.2, 2.1],
    "index": [0.2, -0.4, 0.8]
  },
  "simulationThresholds": {
    "3": {"up": 20.0},
    "10": {"up": 100.0},
    "30": {"up": 200.0}
  },
  "calculationInput": {
    "stock": [{"date":"2026-10-09","return":2.1}],
    "index": [{"date":"2026-10-09","return":0.8}],
    "ordinaryDeviation": 20.0,
    "severe10": {"up":100.0},
    "severe30": {"up":200.0},
    "sameDirectionThreshold": 4,
    "ruleVersion": "..."
  }
}
```

示例中的 `simulationThresholds.3` 同样是兼容字段；前端模拟表不得读取或渲染它。

前端模拟流程：

1. 以 `simulationBase` 为历史序列，以 `futureTradeDates` 生成未来行。
2. 用户输入某日股票/指数涨幅后，将该行追加到历史序列；10/30 日分别在最近最多 10/30 个收益率区间内枚举所有以该模拟日为终点的连续子区间并选择最大上涨偏离。
3. 10 日和 30 日结果分别与 `simulationThresholds` 的上涨、下跌阈值比较；任一方向/窗口触发即显示“已触发”，否则安全空间按最近阈值剩余距离生成。模拟表不展示也不计算 3 日偏离。
4. 只更新被编辑行及其后的模拟行，保留用户已填写内容；清空输入时保留空白展示，并按 `0%` 重新计算该行及后续依赖结果。
5. 该过程不得调用网络、修改 `detail.warnings`、修改 `detail.status` 或改变预测页数据。

后端正式结果仍由 `warnings`、`alerts`、`status` 和 `dataQuality` 提供。前端不得用 `calculationInput` 重算这些字段。

#### A.10.4 重点监控处理

严重异动方向字段：公告正文明确“涨幅偏离”时 `eventDirection=up`，明确“跌幅偏离”时 `eventDirection=down`，没有方向证据时为空。小程序下跌方向去杂只读取此公告事实，不读取最新单日 `marketChange`；否则会把上涨严重异动公告之后的单日回落错误隐藏。该方向信息与当前日行情、是否仍处于监管期分开保存。它取代本章节较早版本中“按最新落盘日收益过滤负收益股票”的旧口径。

公告任务只由后台执行，页面读取最近一次成功快照。处理顺序为：抓取主源和备源 → 正文语义分类（严重异动按板块核验上涨/下跌阈值）→ 从正文提取异动事实最后交易日 → 生成生效交易日序列 → 同股同类型去重覆盖 → 计算剩余自然日 → 原子发布完整快照。API 返回完整当前事实；小程序展示时对风险提示、严重异动过滤 5/1、ST/*ST、名称含“退”的股票，退市整理无条件保留，正常 9 开头北交所股票保留。

分类必须使用正文和来源类型而不是标题猜测：18.cn 与巨潮/发行人风险提示要求交易所“从严认定”语义；中泰标题明确为“交易风险提示”时归为风险提示，标题明确为“退市整理期的风险警示”时归为独立的 `delisting-warning`，卡片标签为“退市倒计时”；10/30 日严重异动分类必须按证券板块核对相应偏离阈值，其中 10 日严重异动也可由正文明确的板块同向异常波动次数条件认定（主板 4 次、创业板/科创板/北交所 3 次），不能因为未写 10 日偏离百分比而归成普通风险提示；不能用 10 日阈值兜底分类明确写出的 30 日公告。沪深严重异动公告可披露实际连续交易日窗口；它用于归档公告事实类别，不会改变产品行情候选窗口。严重异动同时保存由公告正文“涨幅/跌幅偏离”提取的 `eventDirection`；前端方向去杂只能使用此字段，不可使用最新单日行情。风险提示和 10/30 日严重异动按 10 个有效交易日计期；退市倒计时从正文提取整理期进入日和预计最后交易日，并保存该日期范围内的交易日序列。正文未提供完整日期时保留兼容的 10 日退市记录。3 日普通异动不生成重点监控记录。风险提示和退市整理风险警示均不触发行情窗口重置。

监管事实的来源关系必须单独建模，不能按“同股同日”直接合并：`severe-10d/severe-30d` 是严重异动主事实；`ordinary` 是独立的交易风险提示；`delisting-warning` 是独立的退市整理风险警示，永远不与前两类合并。只有普通风险提示正文明确复述“严重异常波动”或严重异动窗口/偏离值时，才标记为 `sourceRelation=severe-supporting`，从卡片列表中作为该轮严重异动的佐证来源保留；其链接进入 `supportingSourceUrls`，不混入严重异动的主 `sourceUrls`。同日但正文未明确复述严重异动的普通风险提示仍单独展示；不同日期的普通风险提示也始终单独展示。这样既不漏掉新华传媒等后续独立风险提示，也不会把近岸蛋白中泰对同一轮严重异动的转述误算成第二轮监管事实。

同一股票、同一类型、同一公告日的多来源记录合并；同一股票、同一类型重叠监管期由最新公告覆盖，不延长。正文明确异动最后交易日时，监管从其后首个交易日开始；否则中泰风险提示从公告日、18.cn 风险提示从下一交易日起算。监管起止日按交易日序列冻结，页面“剩余 N 天”按上海本地自然日差值展示，结束日当天为 `00`，次日移除。API 和快照保留全部有效监管事实；前端在风险提示、严重异动中剔除 5/1 开头、ST/*ST、名称含“退”的标的；严重异动方向按正文保存的 `eventDirection` 去杂，不按最新落盘收益过滤，上涨型严重异动即使最新单日为负仍展示，明确下跌型事实才隐藏，方向缺失时保留。风险提示不因当日涨跌隐藏。正常 9 开头北交所标的不剔除。退市整理风险警示在专属筛选和“全部”中都保留且不应用去杂。风险提示与退市整理风险警示不显示公告入口；严重异动 PDF 只在有效监管期内代理，过期返回 404。

### A.11 API 详细契约（历史补充）

#### A.11.1 单股详情响应

`GET /api/stocks/detail?ts_code=600000.SH` 成功时返回 `code=0`，`data` 至少包含：

```text
ts_code, symbol, name, market, board
currentPrice, change, tradeDate, quoteUpdatedAt
status, statusClass, statusIcon
warnings[4], alerts[], dataQuality
futureTradeDates, simulationBase, calculationInput, simulationThresholds
```

`warnings` 固定顺序为四项：`3 日偏离`、`10 日同向`、`10 日偏离`、`30 日偏离`。偏离项返回上涨最大偏离、下跌最小偏离、两侧阈值和触发状态；同向项分别返回上涨、下跌次数。前端当前值只展示实际方向的一侧及对应阈值；当前未触发但 `nextDayForecast.rules` 存在明确方向时，改展示该次日候选方向的偏离值、阈值和剩余空间，不能用另一方向的安全空间配红色风险状态。当前已触发时优先展示已触发方向。每项必须带当前值、阈值/次数、展示状态；窗口不足时带不可判定原因。`dataQuality.intraday=true` 只有股票和所属指数盘中行情同时成功时才允许出现。重点监控返回标准 `ts_code`，前端卡片可直接进入单股详情。

#### A.11.2 预测卡字段

预测卡必须至少包含：

```text
predictionKey, ts_code, name, symbol, ruleKey
predictionWindow, deviationWindow, deviationLabel, deviationPercent
triggerCondition, triggerValue, triggered, cardTone, alertText
change, quoteUpdatedAt, targetTradeDate, scope
```

`ruleKey` 只能是 `severe_10d` 或 `severe_30d`。不返回 `currentPrice`/`price`；`triggered=true` 时 `cardTone` 必须为 `triggered`，回落后恢复为空字符串但卡片不能删除。`triggerCondition` 和 `triggerValue` 始终来自统一公式反推的目标日所需涨幅；触发状态变化不得把它们改写成固定偏离阈值，规则原文保存在 `rule`。

#### A.11.3 监控响应

`GET /api/monitor?status=current&type=all|risk|delisting|severe` 返回 `items`、`updatedAt`、`dataQuality`、`stale`、`sourceHealth`。每项至少包含股票、标题、`riskTone`、`monitorType`、`monitorPeriod`、`startDate`、`endDate`、`remainingDays`、`sourceStatus`、`sourceUrl`/`sourceUrls` 和数据质量。普通风险提示的链接字段必须为空；退市整理风险警示使用独立 `riskTone=delisting-warning`；严重异动过期后不得继续返回链接。

#### A.11.4 状态码与失败语义

| 场景 | HTTP/业务码 | 前端处理 |
| --- | --- | --- |
| 参数缺失或非法 scope | 400 / `40001` | 保留当前页面并提示参数错误 |
| 股票不存在 | 404 / `40401` | 显示股票不存在，不显示正常状态 |
| 当前阶段不允许刷新 | 409 / `40901` | 不发起重试，恢复按钮状态 |
| 上游数据源不可用 | 503 / `50301` | 显示数据不可用，保留已有稳定结果 |
| 数据集尚未准备 | 503 / `50302` | 显示等待数据，不显示空成功 |
| 内部错误 | 500 / `50001` | 显示通用错误并记录 request 日志 |
| 读取接口已有旧数据但新任务失败 | 200 / `code=0`，`dataUnavailable=true` | 保留 `items`，在更新时间处显示失败状态 |

### A.12 前端页面实现约束

#### A.12.1 单股页

进入页面只请求搜索/详情接口一次；单股页不启用系统下拉刷新，预测和重点监控的刷新只由各自页面系统下拉手势触发。正式状态、四项预警、监控解释和行情时间直接使用后端字段。详情请求失败时不得用上一次股票的规则结果填充新股票。

模拟表格使用页面本地 state 保存输入值和计算行。输入事件只调用本地 `calculateSimulationRows`，不调用 `getStockDetail`、不刷新行情、不改变页面顶部正式状态。重新选股、刷新或卸载页面时清空模拟输入。

#### A.12.2 预测页

默认加载 `scope=today`；新用户首次进入页面自动调用一次 `POST /api/predictions/refresh`，只有返回 `refreshStatus=applied` 且 `dataQuality.intraday=true`（或 `dataStage=realtime`）才记录首次完成。非交易时间、阶段不允许刷新、网络失败或正式数据回退均不得消耗首次机会；同一设备完成一次成功盘中刷新后后续进入不重复自动刷新。切换 `today/next_day` 只替换已加载数据，不自动刷新行情。用户下拉刷新继续调用 `POST /api/predictions/refresh`；前端保留返回列表顺序，不按触发状态过滤或排序。空列表必须结合 `dataUnavailable`、`datasetStatus`、`nextDayAvailable` 判断展示“无候选”还是“数据不可用”。

#### A.12.3 重点监控页

筛选参数只映射到后端 `type`；前端不解析公告标题、不推算起止日期、不决定公告入口。前端只按 `riskTone` 和股票代码/名称执行已定义的展示去杂，不修改或删除后端事实；不提供去杂按钮。退市整理在“全部”和专属筛选始终保留。`sourceUrl` 为空时隐藏入口，过期或 `stale=true` 时显示快照状态而不是伪造空列表。

### A.13 一致性、缓存与并发

- 规则版本由统一常量维护；规则阈值、窗口或方向口径变更时必须升级 `ruleVersion`，重建 today/next_day 数据集并清理相关盘中态。
- 数据集主键为 `dataset_role + target_trade_date`，写入采用事务/原子替换；同一目标日期不能产生两份可见 ready 数据。
- 盘中行情和刷新结果不写入 Redis、MySQL 或进程缓存；POST 响应结束后不保留盘中状态。
- 后台任务使用数据库任务锁和 lease；实例重启后由 lease 超时恢复，不能依赖进程内锁保证唯一执行。
- 单股详情的股票和指数实时请求必须属于同一刷新批次；一方缺失时返回最近正式结果并标注 fallback。
- API 返回的 `quoteUpdatedAt` 是行情数据时间；`updatedAt` 仅为技术兼容字段，不能作为页面行情时间。

### A.15 发布前检查清单

1. `ruleVersion`、预测数据集和接口契约只允许 `ordinary_3d`、`severe_10d`、`severe_30d` 三类预测卡；普通卡必须受 10 日或 30 日重点监控资格控制，且已有独立普通风险提示事实时不得重复生成，同向次数不进入预测接口。重点监控接口另有独立 `delisting-warning` 监管标签。
2. `stockBasicCoverage.complete=true`，预测排除项有统计，不把数据失败写成空成功。
3. 单股详情能返回模拟基础输入；编辑模拟行不产生网络请求，正式状态不变化。
4. 行情透传接口对 1～99 个代码校验、去重，明确返回 `persisted=false`。
5. 预测刷新响应直接更新页面；后续 GET 仍返回稳定数据集，刷新结果不进入 MySQL、Redis 或进程缓存。
6. 当日和次日预测切换不刷新行情；盘中刷新只更新已有卡片状态。
7. 重点监控主源/备源切换、结束日可见性和严重异动公告入口已验证。
8. 微信开发者工具 Problems 为 0，并完成单股、重点监控、预测和断网验收。

### A.16 变更管理

任何规则、字段或页面行为变更都必须同时更新：PRD、本文档、统一规则实现、API 契约脚本、测试夹具和验收用例。涉及窗口、阈值、方向、预测卡范围或监管期的变更，不允许只修改前端文案；必须升级 `ruleVersion` 并重建受影响数据集。
